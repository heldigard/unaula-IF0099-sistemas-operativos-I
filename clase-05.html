Introducción a Procesos

¿Qué es un proceso?
  • Un programa en ejecución
  • Tiene su propio espacio de memoria
  • Identificado por un PID (Process ID)
  • Contiene: código, datos, stack, heap y PCB

Diferencia entre programa y proceso:

Programa

  • Archivo en disco
  • Código ejecutable
  • Pasivo (estático)
  • Ejemplo: /bin/bash

Proceso

  • Programa en ejecución
  • En memoria RAM
  • Activo (dinámico)
  • Ejemplo: bash con PID 1234

Ciclo de Vida de un Proceso

Un proceso pasa por varios estados desde su creación hasta su terminación 
    ┌─────────────┐
    │   NUEVO     │  ← Proceso creado
    └──────┬──────┘
           │
           ▼
    ┌─────────────┐
    │   LISTO     │  ← Esperando CPU
    └──────┬──────┘
           │
           ▼
    ┌─────────────┐
    │ EJECUTANDO  │  ← Usando CPU
    └──────┬──────┘
           │
           ├──► ┌─────────────┐
           │    │ ESPERANDO   │  ← Esperando I/O
           │    └──────┬──────┘
           │           │
           └───────────┘
           │
           ▼
    ┌─────────────┐
    │ TERMINADO   │  ← Proceso finalizado
    └─────────────┘

PCB (Process Control Block)

Bloque de Control de Proceso

El PCB es la "huella digital" de un proceso
  • Estructura de datos que contiene toda la información del proceso
  • Almacenado en el kernel
  • Cada proceso tiene su propio PCB

Contenido del PCB:

Campo Descripción Ejemplo
PID Process Identifier (único) 1234
Estado Estado actual del proceso Running, Sleeping
PC Program Counter (siguiente instrucción) 0x7f8a4b2c
Registros Estado de los registros del CPU RAX=0x100, RBX=0x200
Memoria Límites de memoria del proceso Base=0x4000, Límite=0x2000
Archivos Archivos abiertos por el proceso stdin, stdout, /tmp/log

Estados de un Proceso en Linux

Estado Símbolo ps Descripción
Running R Ejecutándose o en cola de ejecución
Sleeping S Esperando evento interrumpible
Disk sleep D Esperando E/S de disco (no interrumpible)
Stopped T Detenido por señal (SIGSTOP, SIGTSTP)
Zombie Z Terminado pero no limpiado por padre
⚠️ Procesos Zombie:
  • Hijo terminó pero padre no hizo wait()
  • Ocupan entrada en tabla de procesos
  • Se eliminan cuando el padre termina

PID y PPID

Cada proceso tiene identificadores únicos

PID (Process ID)

  • Identificador único del proceso
  • Número entero positivo
  • Asignado por el kernel
  • Se reutiliza después de terminar

PPID (Parent PID)

  • PID del proceso padre
  • Cada proceso tiene un padre (excepto init)
  • init/systemd es PID 1
  • Crea jerarquía de procesos

Ver PID y PPID:

$ ps -ef | grep bash
root      1234  1000  0 10:00 ?        00:00:01 /bin/bash
          ↑      ↑
         PID    PPID

  • F9 - Matar proceso

  • F8 - Aumentar nice
  • / - Buscar proceso

kill y Señales

kill envía señales a procesos para controlar su comportamiento

Señales más comunes:

Señal Número Acción
SIGTERM 15 Terminación elegante (permite limpieza)
SIGKILL 9 Terminación inmediata (no se puede ignorar)
SIGHUP 1 Colgar (recargar configuración)
SIGINT 2 Interrupción (Ctrl+C)
SIGSTOP 19 Pausar proceso (no se puede ignorar)
SIGCONT 18 Continuar proceso pausado

Ejemplos de uso:

# Terminar proceso (SIGTERM por defecto)
kill 1234

# Forzar terminación
kill -9 1234

# Recargar configuración
kill -HUP $(pidof nginx)

# Pausar proceso
kill -STOP 1234

# Continuar proceso pausado
kill -CONT 1234
⚠️ Precaución con SIGKILL (-9):
  • No permite al proceso limpiar recursos
  • Puede dejar archivos temporales
  • Puede causar corrupción de datos
  • Usar SIGTERM (15) primero

Listar todas las señales:

$ kill -l
1) SIGHUP       2) SIGINT       3) SIGQUIT      4) SIGILL
5) SIGTRAP      6) SIGABRT      7) SIGBUS       8) SIGFPE
9) SIGKILL     10) SIGUSR1     11) SIGSEGV     12) SIGUSR2
13) SIGPIPE     14) SIGALRM     15) SIGTERM     ...

Prioridades y nice

Las prioridades de proceso determinan cuánto tiempo de CPU reciben

Valores nice:

  • Rango: -20 (más alta prioridad) a 19 (más baja)
  • Valor por defecto: 0
  • Solo root puede usar valores negativos
  • Valores altos = "ser nice" = ceder CPU a otros
Prioridad del Kernel
    ↑
 -20 │████████████████████ Alto privilegio (solo root)
     │
   0 │████████▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ Bajo privilegio
     │
  19 │                                        ▓▓▓▓▓▓▓
    └────────────────────────────────────────────→
    Mayor valor nice = Menor prioridad

Comandos de prioridad:

# Iniciar proceso con nice determinado
nice -n 10 comando        # Prioridad baja
nice -n -5 comando        # Prioridad alta (requiere root)

# Cambiar nice de proceso en ejecución
renice -n 5 -p 1234       # Cambiar a nice 5
renice +5 -p 1234        # Aumentar nice en 5

Ver prioridad y nice:

$ ps -eo pid,ni,pri,comm
  PID  NI  PRI COMMAND
    1   0   20 systemd
 1234  10   30 firefox
 5678  -5   15 jackd

systemd y systemctl

systemd es el sistema de inicialización y gestión de servicios en Linux moderno

Gestión de servicios con systemctl:

Comando Descripción
systemctl start servicio Iniciar servicio
systemctl stop servicio Detener servicio
systemctl restart servicio Reiniciar servicio
systemctl reload servicio Recargar configuración
systemctl status servicio Ver estado del servicio
systemctl enable servicio Habilitar al inicio
systemctl disable servicio Deshabilitar al inicio
systemctl is-enabled servicio Ver si está habilitado

Ejemplos prácticos:

# Ver estado de un servicio
systemctl status nginx

# Iniciar servicio
sudo systemctl start nginx

# Habilitar al inicio
sudo systemctl enable nginx

# Ver todos los servicios
systemctl list-units --type=service

# Ver servicios fallidos
systemctl --failed

# Ver logs de un servicio
journalctl -u nginx -f

Práctica Guiada

Actividad 1: Explorar procesos

Tiempo: 10 minutos

  1. Abre una terminal
  2. Ejecuta ps aux | less para ver todos los procesos
  3. Identifica el proceso con mayor uso de CPU
  4. Identifica el proceso con mayor uso de memoria
  5. Busca procesos zombie: ps aux | grep Z

Actividad 2: Monitoreo en tiempo real

Tiempo: 10 minutos

  1. Ejecuta top
  2. Observa los procesos que más CPU consumen
  3. Presiona M para ordenar por memoria
  4. Presiona P para volver a ordenar por CPU
  5. Abre otra terminal y ejecuta htop (si está instalado)

Actividad 3: Gestionar procesos

Tiempo: 15 minutos

  1. Inicia un proceso en segundo plano: sleep 300 &
  2. Obtén su PID: ps aux | grep sleep
  3. Cámbialo a estado stopped: kill -STOP [PID]
  4. Verifica que está en estado T: ps -p [PID] -o pid,stat,cmd
  5. Continúa el proceso: kill -CONT [PID]
  6. Termina el proceso: kill [PID]

Actividad 4: Gestión de servicios

Tiempo: 10 minutos

  1. Verifica si SSH está corriendo: systemctl status ssh
  2. Lista todos los servicios activos: systemctl list-units --type=service --state=running
  3. Verifica si un servicio está habilitado: systemctl is-enabled cron
  4. Reinicia un servicio (si tienes permisos): sudo systemctl restart cron

Entregable de la Clase

Script: monitoreo_procesos.sh

Descripción: Script en Bash que muestra los 5 procesos que más consumen CPU y memoria

Requisitos:

  • Mostrar top 5 procesos por CPU
  • Mostrar top 5 procesos por memoria
  • Mostrar fecha y hora del reporte
  • Mostrar carga promedio del sistema
  • Guardar reporte en archivo con timestamp

Estructura sugerida:

#!/bin/bash
# monitoreo_procesos.sh
# Script de monitoreo de procesos

# Fecha y hora
fecha=$(date +"%Y-%m-%d %H:%M:%S")
archivo="reporte_$(date +%Y%m%d_%H%M%S).txt"

echo "=== REPORTE DE PROCESOS ===" > "$archivo"
echo "Fecha: $fecha" >> "$archivo"
echo "" >> "$archivo"

# Carga promedio
echo "=== CARGA PROMEDIO ===" >> "$archivo"
uptime >> "$archivo"
echo "" >> "$archivo"

# Top 5 CPU
echo "=== TOP 5 CPU ===" >> "$archivo"
ps aux --sort=-%cpu | head -6 >> "$archivo"
echo "" >> "$archivo"

# Top 5 Memoria
echo "=== TOP 5 MEMORIA ===" >> "$archivo"
ps aux --sort=-%mem | head -6 >> "$archivo"

echo "Reporte guardado en: $archivo"
cat "$archivo"

Instrucciones de entrega:

  1. Guardar el script como monitoreo_procesos.sh
  2. Dar permisos de ejecución: chmod +x monitoreo_procesos.sh
  3. Ejecutar el script: ./monitoreo_procesos.sh
  4. Capturar la salida del script
  5. Entregar: script + captura de ejecución
