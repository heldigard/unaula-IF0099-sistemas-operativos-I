1. Introducción a la Gestión de Memoria

¿Por qué gestionar la memoria?

La memoria RAM es un recurso limitado y compartido. El SO debe asignarla eficientemente entre todos los procesos.

Conceptos Fundamentales

ConceptoDescripción
Dirección lógicaDirección que ve el programa (virtual)
Dirección físicaDirección real en hardware RAM
MMUMemory Management Unit - traduce direcciones
SwapMemoria virtual en disco

2. Jerarquía de Memoria

La memoria se organiza en niveles según velocidad y costo:

┌─────────────────────────────────────┐
│  Registros CPU     │  Más rápida    │
│  (nS)              │  Más costosa   │
├─────────────────────────────────────┤
│  Cache L1/L2/L3    │  Muy rápida    │
│  (MB)              │                │
├─────────────────────────────────────┤
│  RAM (Principal)   │  Rápida        │
│  (GB)              │  Volátil       │
├─────────────────────────────────────┤
│  SSD/HDD           │  Lenta         │
│  (TB)              │  Persistente   │
└─────────────────────────────────────┘
         ↑ Velocidad / Costo ↑
Principio de localidad: Los programas tienden a acceder a las mismas áreas de memoria repetidamente. El SO aprovecha esto para optimizar.

3. Asignación Contigua

El proceso ocupa un bloque continuo de memoria:

Ventajas:

  • Simple de implementar
  • Mapeo dirección lógica→física es directo (solo sumar base)

Desventajas:

  • Fragmentación externa
  • Difícil encontrar bloques grandes
  • Procesos limitados por tamaño de bloque disponible

Esquema Base-Límite:

Dirección Física = Dirección Lógica + Base
Verificación: 0 ≤ Dirección Lógica < Límite

Ejemplo:
  Base = 1400
  Límite = 400
  Dirección lógica 100 → Física 1500 ✓
  Dirección lógica 500 → Error (fuera de límite) ✗

4. Particiones

Particiones Fijas (Estáticas)

CaracterísticaDescripción
TamañoDivisión de memoria en bloques de tamaño fijo
VentajaSimple, rápido asignar
DesventajaFragmentación interna (espacio desperdiciado dentro de partición)

Particiones Dinámicas (Variables)

CaracterísticaDescripción
TamañoCada proceso obtiene exactamente lo que necesita
VentajaSin fragmentación interna
DesventajaFragmentación externa (huecos entre procesos)
Estrategias de ubicación:
  • First Fit: Primer hueco suficiente (más rápido)
  • Best Fit: Hueco más pequeño suficiente (menos desperdicio)
  • Worst Fit: Hueco más grande (deja espacio usable)

5. Fragmentación

Fragmentación Interna

Espacio desperdiciado DENTRO de la partición asignada. Ocurre en particiones fijas cuando el proceso es menor que la partición.

Fragmentación Externa

Espacio desperdiciado ENTRE particiones. Hay memoria libre total suficiente pero no contigua.

Solución: Compactación

Antes de compactar:
[P1][ libre ][P2][ libre ][P3][ libre grande pero fragmentado ]

Después de compactar:
[P1][P2][P3][ libre contiguo grande ]
Swap: Como alternativa a compactación, los procesos inactivos se mueven a disco liberando RAM.

6. Práctica en Linux

Comandos para monitorear memoria:

# Ver uso de memoria total
free -h

# Ver procesos ordenados por uso de memoria
ps aux --sort=-%mem | head -10

# Información detallada de memoria
vmstat -s

# Ver uso de memoria de un proceso específico
pmap [PID]

# Ver swap disponible y usado
swapon -s

# Ver estadísticas de memoria en tiempo real
vmstat 1 5
