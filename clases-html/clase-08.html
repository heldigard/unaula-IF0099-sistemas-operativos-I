Introducción al IPC

IPC (Inter-Process Communication): Mecanismos que permiten a los procesos intercambiar datos y sincronizarse

¿Por qué necesitamos IPC?

  • Los procesos tienen espacios de memoria aislados
  • Necesitan coordinarse para tareas complejas
  • Compartir datos entre aplicaciones
  • Sincronizar acciones concurrentes

Mecanismos IPC principales:

Mecanismo Descripción Uso típico
Pipes Comunicación unidireccional (stream) Productor-Consumidor
Señales Notificaciones de eventos Control de procesos
Memoria Compartida Segmento de memoria accesible por múltiples procesos Alto rendimiento
Sockets Comunicación de red y local Cliente-Servidor

Pipes (Tuberías)

Un pipe es un canal de comunicación unidireccional entre dos procesos

Características de los Pipes:

  • Unidireccional: Los datos fluyen en una sola dirección
  • Stream: Flujo de bytes (no mensajes estructurados)
  • FIFO: First In, First Out (el primero que entra, sale primero)
  • Buffer: Capacidad limitada (típicamente 64KB en Linux)

Esquema de un Pipe:

┌──────────┐      write       ┌──────────┐
│Productor │ ──────────────────> │Consumidor│
│ (escritor)│    (pipe)          │ (lector) │
└──────────┘                     └──────────┘

     │                                 │
     ├──> pipe[1] (escritura)          │
     │                                 │
     │                                 ├──> pipe[0] (lectura)
     │                                 │
   stdout                              stdin

Tipos de Pipes:

Pipe Anónimo

  • Solo entre procesos relacionados (padre-hijo)
  • No tiene nombre en el sistema de archivos
  • Desaparece cuando los procesos terminan
  • Uso: shell (|) y fork()

Pipe Nombrado (FIFO)

  • Entre cualquier proceso
  • Tiene nombre en el sistema de archivos
  • Persiste hasta ser eliminado
  • Uso: comunicación general entre procesos

Pipes Anónimos

Los pipes anónimos son creados por el shell y solo existen mientras los procesos estén activos

Uso en Bash (Shell)

El operador pipe (|):

# Ejemplo 1: Listar archivos largos
ls -l | grep ".txt"

# Ejemplo 2: Contar procesos
ps aux | grep chrome | wc -l

# Ejemplo 3: Monitorear logs
tail -f /var/log/syslog | grep "ERROR"

Cómo funciona:

  • El shell crea un pipe anónimo
  • Redirige stdout del comando 1 al pipe
  • Redirige stdin del comando 2 desde el pipe
  • Ambos comandos se ejecutan en paralelo

Ejemplo detallado:

Comando: ls -l | grep ".txt"

┌─────────────────────────────────────────────────┐
│ Shell crea pipe anónimo                        │
│                                                 │
│  ls -l          pipe           grep ".txt"      │
│  [hijo1]    ───────>    [hijo2]                │
│  stdout                   stdin                 │
│                                                 │
│  1. fork() → crea proceso hijo (ls -l)        │
│  2. fork() → crea proceso hijo (grep)         │
│  3. pipe() → crea canal de comunicación        │
└─────────────────────────────────────────────────┘

Ejemplo práctico - Análisis de procesos:

# Encontrar los 5 procesos que más CPU consumen
ps aux | sort -rk 3 | head -6

# Explicación:
# ps aux      - Lista todos los procesos
# sort -rk 3  - Ordena por columna 3 (CPU) descendente
# head -6      - Muestra las primeras 6 líneas (encabezado + 5)

Pipes Nombrados (FIFO)

Los pipes nombrados (FIFO) tienen entrada en el sistema de archivos y permiten comunicación entre procesos no relacionados

Crear y usar un FIFO:

Comandos básicos:

# 1. Crear el FIFO
mkfifo /tmp/mi_pipe

# 2. Verificar que se creó
ls -l /tmp/mi_pipe
# prw-r--r-- 1 user user 0 feb 10 10:00 /tmp/mi_pipe
# (la 'p' indica pipe)

# 3. Escribir en el FIFO (bloquea hasta que alguien lea)
echo "Hola mundo" > /tmp/mi_pipe

# 4. Leer del FIFO (otra terminal)
cat /tmp/mi_pipe

# 5. Eliminar el FIFO
rm /tmp/mi_pipe

Script Productor (escritor):

#!/bin/bash
# productor.sh
FIFO="/tmp/mi_pipe"

# Crear el FIFO si no existe
[ -p "$FIFO" ] || mkfifo "$FIFO"

echo "Productor: Escribiendo en $FIFO"
for i in {1..10}; do
    echo "Mensaje $i"
    sleep 1
done > "$FIFO"

echo "Productor: Terminé de escribir"

Script Consumidor (lector):

#!/bin/bash
# consumidor.sh
FIFO="/tmp/mi_pipe"

echo "Consumidor: Leyendo de $FIFO"
while read linea; do
    echo "Consumidor: Recibí - $linea"
done < "$FIFO"

echo "Consumidor: No hay más datos"

Ejecución:

# Terminal 1 - Iniciar el consumidor primero
./consumidor.sh

# Terminal 2 - Ejecutar el productor
./productor.sh
⚠️ Comportamiento de bloqueo:
  • Si el FIFO está vacío, el lector se bloquea
  • Si el FIFO está lleno, el escritor se bloquea
  • Al menos un lector debe estar presente antes de escribir

Señales

Las señales son notificaciones enviadas a un proceso para informar eventos

Señales más comunes en Linux:

Señal Número Acción por defecto Uso
SIGINT 2 Terminar Ctrl+C (interrupción)
SIGTERM 15 Terminar Solicitud de terminación
SIGKILL 9 Terminar (forzado) Matar proceso inmediatamente
SIGSTOP 19 Detener Pausar proceso (Ctrl+Z)
SIGCONT 18 Continuar Reanudar proceso detenido
SIGHUP 1 Terminar Terminal cerrado
SIGUSR1 10 Terminar Definido por usuario
SIGUSR2 12 Terminar Definido por usuario

Enviar señales:

# Enviar SIGTERM (terminación elegante)
kill -15 1234
kill 1234        # 15 por defecto

# Enviar SIGKILL (terminación forzada)
kill -9 1234

# Enviar SIGSTOP (pausar)
kill -STOP 1234

# Enviar SIGCONT (continuar)
kill -CONT 1234

# Enviar SIGUSR1 a un proceso
kill -USR1 1234

Memoria Compartida

La memoria compartida es un segmento de memoria accesible por múltiples procesos

Características:

  • Más rápido: Sin copia de datos entre procesos
  • Sincronización: Requiere mecanismos adicionales (semáforos)
  • Persistencia: Existe mientras alguien la tenga mapeada
  • Tamaño: Definido al crearlo

Esquema de Memoria Compartida:

┌─────────────────────────────────────────────────┐
│          MEMORIA COMPARTIDA                      │
│  ┌────────────────────────────────────────┐    │
│  │  Datos compartidos                    │    │
│  │  - variables                          │    │
│  │  - estructuras                        │    │
│  │  - buffers                            │    │
│  └────────────────────────────────────────┘    │
└─────────────────────────────────────────────────┘
       ▲                     ▲
       │                     │
    Proceso A             Proceso B
   (lee/escribe)         (lee/escribe)

SIN COPIA DE DATOS (acceso directo)

Uso típico:

  • Bases de datos de alto rendimiento
  • Caché compartido entre procesos
  • Comunicación de baja latencia
⚠️ Requiere sincronización:
  • Usar semáforos o mutex para evitar race conditions
  • Coordinar lectura/escritura
  • Prevenir deadlocks

Sockets

Los sockets son puntos finales de comunicación bidireccional

Tipos de Sockets:

Unix Domain Sockets

  • Comunicación local (misma máquina)
  • Archivos en el sistema de archivos
  • Más rápido que TCP/IP
  • Uso: X Window, syslog
/var/run/docker.sock
/var/run/mysql/mysql.sock

Network Sockets (TCP/IP)

  • Comunicación entre máquinas
  • Dirección IP + puerto
  • Cliente-Servidor
  • Uso: Servicios web, bases de datos
192.168.1.100:3306
localhost:8080

Arquitectura Cliente-Servidor:

┌────────────┐                    ┌────────────┐
│  Cliente   │                    │ Servidor   │
├────────────┤                    ├────────────┤
│            │  connect()         │            │
│   socket() │ ──────────────────> │  socket()  │
│            │                    │  bind()    │
│   send()   │ ──────────────────> │  listen()  │
│            │                    │  accept()  │
│   recv()   │ <────────────────── │            │
│            │                    │            │
└────────────┘                    └────────────┘

 Puerto: 8080
 IP: 127.0.0.1

Ejemplo simple con netcat (nc):

# Servidor - Escucha en puerto 8080
nc -l 8080

# Cliente - Se conecta al servidor
nc localhost 8080

# En el cliente, escribe mensajes, aparecen en el servidor

Práctica Guiada

Actividad 1: Pipes anónimos en Bash

Tiempo: 10 minutos

  1. Abre una terminal
  2. Lista los archivos .txt en tu directorio home: find ~ -name "*.txt" 2>/dev/null | head -10
  3. Cuenta cuántos archivos .txt existen: find ~ -name "*.txt" 2>/dev/null | wc -l
  4. Combina comandos con pipes: ps aux | grep bash | wc -l
  5. Crea tu propio pipe: echo "Hola" | cat

Actividad 2: Crear un Pipe Nombrado

Tiempo: 10 minutos

  1. Crea un FIFO: mkfifo /tmp/mi_fifo
  2. Verifica que se creó: ls -l /tmp/mi_fifo
  3. En otra terminal, inicia un lector: cat /tmp/mi_fifo
  4. En la terminal original, escribe: echo "Hola desde el pipe" > /tmp/mi_fifo
  5. Observa que el mensaje aparece en la terminal del lector
  6. Elimina el FIFO: rm /tmp/mi_fifo

Actividad 3: Enviar señales

Tiempo: 10 minutos

  1. Inicia un proceso en segundo plano: sleep 300 &
  2. Obtén el PID: ps aux | grep sleep
  3. Envía SIGSTOP: kill -STOP [PID]
  4. Verifica que está detenido: ps -p [PID] -o pid,stat
  5. Envía SIGCONT: kill -CONT [PID]
  6. Termina el proceso: kill [PID]

Entregable de la Clase

Scripts Productor-Consumidor con Pipes

Descripción: Implementar un sistema Productor-Consumidor usando bash scripts y un pipe nombrado

Requisitos:

  • productor.sh: Genera números y los escribe en el FIFO
  • consumidor.sh: Lee números del FIFO y calcula su suma
  • Usar pipe nombrado (FIFO)
  • Mostrar capturas de la ejecución

Estructura sugerida:

productor.sh:

#!/bin/bash
# productor.sh

FIFO="/tmp/numeros_pipe"

# Crear FIFO
[ -p "$FIFO" ] || mkfifo "$FIFO"

echo "Productor: Generando números..."
for i in {1..20}; do
    echo "$i"
    sleep 0.5
done > "$FIFO"

echo "Productor: Terminé"

consumidor.sh:

#!/bin/bash
# consumidor.sh

FIFO="/tmp/numeros_pipe"

echo "Consumidor: Esperando números..."
suma=0
cantidad=0

while read numero; do
    echo "Consumidor: Recibí $numero"
    suma=$((suma + numero))
    cantidad=$((cantidad + 1))
done < "$FIFO"

echo "Consumidor: Terminé"
echo "Total recibidos: $cantidad"
echo "Suma total: $suma"

Instrucciones de ejecución:

  1. Guardar ambos scripts con permisos de ejecución: chmod +x productor.sh consumidor.sh
  2. En una terminal, ejecutar: ./consumidor.sh
  3. En otra terminal, ejecutar: ./productor.sh
  4. Capturar la salida de ambas terminales
  5. Verificar que la suma es correcta (1+2+...+20 = 210)

Entregable:

  • Código fuente de ambos scripts
  • Capturas de pantalla de la ejecución
  • Breve explicación del funcionamiento
