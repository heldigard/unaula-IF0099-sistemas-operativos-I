Objetivos de Aprendizaje

Resultado de Aprendizaje: Administra la memoria, los procesos de entrada y salida, la comunicación entre procesos y la sincronización de los mismos.

Al finalizar esta clase, serás capaz de:

  1. Comprender la jerarquía de memoria y sus niveles
  2. Explicar la asignación contigua de memoria
  3. Diferenciar entre particiones fijas y dinámicas
  4. Identificar y solucionar problemas de fragmentación
  5. Monitorear el uso de memoria en Linux

Glosario de Memoria

  • MMU (Memory Management Unit): Dispositivo de hardware que traduce direcciones virtuales a físicas.
  • Swap: Área en el disco duro que se usa como extensión de la memoria RAM.
  • Fragmentación: Desperdicio de memoria RAM que no puede ser utilizada.
  • Localidad de Referencia: Tendencia de los programas a acceder a direcciones de memoria cercanas en el tiempo y espacio.

1. Introducción a la Gestión de Memoria

¿Por qué gestionar la memoria?

La memoria RAM es un recurso limitado y compartido. El SO debe asignarla eficientemente entre todos los procesos.

Conceptos Fundamentales

ConceptoDescripción
Dirección lógicaDirección que ve el programa (virtual)
Dirección físicaDirección real en hardware RAM
MMUMemory Management Unit - traduce direcciones
SwapMemoria virtual en disco

2. Jerarquía de Memoria

La memoria se organiza en niveles según velocidad y costo:

┌─────────────────────────────────────┐
│  Registros CPU     │  Más rápida    │
│  (nS)              │  Más costosa   │
├─────────────────────────────────────┤
│  Cache L1/L2/L3    │  Muy rápida    │
│  (MB)              │                │
├─────────────────────────────────────┤
│  RAM (Principal)   │  Rápida        │
│  (GB)              │  Volátil       │
├─────────────────────────────────────┤
│  SSD/HDD           │  Lenta         │
│  (TB)              │  Persistente   │
└─────────────────────────────────────┘
         ↑ Velocidad / Costo ↑
Principio de localidad: Los programas tienden a acceder a las mismas áreas de memoria repetidamente. El SO aprovecha esto para optimizar.

3. Asignación Contigua

El proceso ocupa un bloque continuo de memoria:

Ventajas:

  • Simple de implementar
  • Mapeo dirección lógica→física es directo (solo sumar base)

Desventajas:

  • Fragmentación externa
  • Difícil encontrar bloques grandes
  • Procesos limitados por tamaño de bloque disponible

Esquema Base-Límite:

Dirección Física = Dirección Lógica + Base
Verificación: 0 ≤ Dirección Lógica < Límite

Ejemplo:
  Base = 1400
  Límite = 400
  Dirección lógica 100 → Física 1500 ✓
  Dirección lógica 500 → Error (fuera de límite) ✗

4. Particiones

Particiones Fijas (Estáticas)

CaracterísticaDescripción
TamañoDivisión de memoria en bloques de tamaño fijo
VentajaSimple, rápido asignar
DesventajaFragmentación interna (espacio desperdiciado dentro de partición)

Particiones Dinámicas (Variables)

CaracterísticaDescripción
TamañoCada proceso obtiene exactamente lo que necesita
VentajaSin fragmentación interna
DesventajaFragmentación externa (huecos entre procesos)
Estrategias de ubicación:
  • First Fit: Primer hueco suficiente (más rápido)
  • Best Fit: Hueco más pequeño suficiente (menos desperdicio)
  • Worst Fit: Hueco más grande (deja espacio usable)

5. Fragmentación

Fragmentación Interna

Espacio desperdiciado DENTRO de la partición asignada. Ocurre en particiones fijas cuando el proceso es menor que la partición.

Fragmentación Externa

Espacio desperdiciado ENTRE particiones. Hay memoria libre total suficiente pero no contigua.

Solución: Compactación

Antes de compactar:
[P1][ libre ][P2][ libre ][P3][ libre grande pero fragmentado ]

Después de compactar:
[P1][P2][P3][ libre contiguo grande ]
Swap: Como alternativa a compactación, los procesos inactivos se mueven a disco liberando RAM.

6. Práctica en Linux

📋 Laboratorio Complementario

Para practicar el monitoreo de memoria y recursos en un entorno real, consulta el Laboratorio 4: Memoria y Monitoreo.

Comandos para monitorear memoria:

# Ver uso de memoria total
free -h

# Ver procesos ordenados por uso de memoria
ps aux --sort=-%mem | head -10

# Información detallada de memoria
vmstat -s

# Ver uso de memoria de un proceso específico
pmap [PID]

# Ver swap disponible y usado
swapon -s

# Ver estadísticas de memoria en tiempo real
vmstat 1 5

Ejercicios Prácticos Guiados:

Ejercicio 1: Análisis de Uso de Memoria

Tiempo: 15 minutos

  1. Verificar memoria total disponible con free -h
  2. Identificar los 5 procesos que más memoria usan: ps aux --sort=-%mem | head -6
  3. Calcular porcentaje de uso de memoria: free | grep Mem | awk '{print ($3/$2)*100}'
  4. Verificar si hay uso de swap: swapon -s o free -h | grep Swap
  5. Documentar en tabla comparativa con todas las métricas

Ejercicio 2: Exploración de /proc/meminfo

Tiempo: 15 minutos

  1. Ver información detallada de memoria: cat /proc/meminfo
  2. Buscar MemTotal, MemFree, MemAvailable, Buffers, Cached
  3. Calcular: MemTotal - MemFree = ¿Cuánta memoria está "usada"?
  4. Comparar con el valor de MemAvailable
  5. Pregunta: ¿Por qué MemAvailable es diferente de MemFree?
Pista: Linux usa memoria "libre" para caches. MemAvailable incluye memoria que puede liberarse de los caches.

Ejercicio 3: Análisis de Procesos y Memoria

Tiempo: 15 minutos

  1. Elegir un proceso (ej: bash): ps aux | grep bash
  2. Obtener su PID y ejecutar: pmap [PID]
  3. Identificar las diferentes regiones de memoria (heap, stack, librerías)
  4. Ver el uso de memoria virtual vs física (RSS)
  5. Calcular: ¿Qué porcentaje de la memoria virtual está realmente en RAM?

Ejercicio 4: Fragmentación Interna (Particiones Fijas)

Tiempo: 15 minutos

¿Qué es fragmentación interna?
Es el espacio DESPERDICIADO DENTRO de una partición cuando el proceso es más pequeño que el espacio asignado.

Situación práctica: Imagina que tienes tres cajas (particiones) de 200KB cada una. Llegan tres paquetes (procesos): uno de 150KB, otro de 180KB y otro de 50KB. Cada paquete va en una caja.

Pregunta: ¿Cuánto espacio sobra (se desperdicia) en cada caja?

Calcula paso a paso:

  1. Caja 1 tiene 200KB, paquete ocupa 150KB → Espacio libre dentro de la caja: 200 - 150 = _____ KB
  2. Caja 2 tiene 200KB, paquete ocupa 180KB → Espacio libre dentro de la caja: 200 - 180 = _____ KB
  3. Caja 3 tiene 200KB, paquete ocupa 50KB → Espacio libre dentro de la caja: 200 - 50 = _____ KB

Total desperdiciado: Suma los tres espacios libres = _____ KB

Reflexión: Aunque hay espacio libre dentro de las cajas, NO se puede usar para otros paquetes porque cada caja está asignada a un solo paquete. ¡Ese espacio se pierde!

Ejercicio 5: Fragmentación Externa (Particiones Dinámicas)

Tiempo: 15 minutos

¿Qué es fragmentación externa?
Es cuando hay suficiente memoria libre en TOTAL, pero está dividida en pedazos pequeños y separados (no contiguos), por lo que no sirve para procesos grandes.

Situación práctica: Imagina una estantería donde hay libros ocupando espacio. Entre los libros hay huecos:

[Libro A: ocupa 300KB] [Hueco: 200KB libre] [Libro C: ocupa 400KB] [Hueco: 100KB libre]

Llega un nuevo libro (Proceso D) que necesita 250KB de espacio.

Analicemos juntos:

  1. ¿Cuánto espacio libre hay en TOTAL? Suma los huecos: 200 + 100 = _____ KB
  2. ¿Hay 250KB libres en total? _____ (Sí/No)
  3. ¿El hueco de 200KB es suficiente para el libro de 250KB? _____ (Sí/No)
  4. ¿El hueco de 100KB es suficiente para el libro de 250KB? _____ (Sí/No)
  5. ¿Puede entrar el libro de 250KB? _____ (Sí/No)
Conclusión: Aunque hay 300KB libres en total (más que los 250KB necesarios), el libro NO cabe porque los huecos están separados. Esto es fragmentación externa: tenemos memoria suficiente, pero no en un solo bloque continuo.

Ejercicio 6: Cálculo Base-Límite (Traducción de Direcciones)

Tiempo: 10 minutos

¿Qué es Base-Límite?
Es un mecanismo de protección de memoria. Cada proceso tiene una dirección "Base" (dónde empieza en memoria física) y un "Límite" (cuánto puede crecer).

Analogía: Imagina que alquilas un apartamento en un edificio:

  • Base = 2000 → Tu apartamento empieza en el piso 2000
  • Límite = 1000 → Tu apartamento tiene 1000 unidades de espacio (del 0 al 999)

Dentro de tu apartamento (dirección lógica), tú ves posiciones del 0 al 999.
En el edificio real (dirección física), tu apartamento ocupa desde el 2000 hasta el 2999.

Fórmula mágica: Dirección Física = Dirección Lógica + Base

Regla de seguridad: Si tu dirección lógica es ≥ 1000, ¡te saliste de tu apartamento! → ERROR

Completa la tabla:

Dirección Lógica
(dentro del apto)		 ¿Está dentro del límite?
(¿es < 1000?)		 Cálculo Dirección Física
(en el edificio)
0 Sí ✓ 2000 + 0 2000
500 _____ 2000 + 500 _____
999 _____ 2000 + 999 _____
1000 No ✗ - ERROR
(fuera de límite)
1500 _____ - _____
¿Por qué es importante? Esto protege que un proceso no acceda a la memoria de otro proceso. Si intentas acceder a una dirección fuera de tu límite, el SO te detiene.

Ejercicio 7: Estrategias de Ubicación (First Fit, Best Fit, Worst Fit)

Tiempo: 10 minutos

¿Cuándo se usan estas estrategias?
Cuando hay varios "huecos" de memoria libre y llega un nuevo proceso, ¿cuál hueco elegimos? Cada estrategia tiene una filosofía diferente.

Situación: Necesitas guardar un proceso de 250KB. Los huecos disponibles en memoria son:

Hueco 1: 100KB (muy pequeño, no sirve)
Hueco 2: 500KB (sí sirve)
Hueco 3: 200KB (muy pequeño, no sirve)  
Hueco 4: 300KB (sí sirve)

Solo los huecos de 500KB y 300KB pueden albergar el proceso de 250KB.

Analicemos cada estrategia:

Estrategia ¿Qué busca? ¿Qué hueco usa? Espacio que sobra
(desperdicio)
First Fit
(Primero que sirva)		 El PRIMER hueco que sea suficiente (más rápido) _____ KB _____ KB
Best Fit
(Mejor ajuste)		 El hueco MÁS PEQUEÑO que sea suficiente (menos desperdicio) _____ KB _____ KB
Worst Fit
(Peor ajuste)		 El hueco MÁS GRANDE (deja el mayor remanente) _____ KB _____ KB

Preguntas de reflexión:

  1. ¿Cuál estrategia desperdicia menos espacio en este caso? _____
  2. ¿Cuál es más rápida de calcular (no necesita revisar todos los huecos)? _____
  3. ¿Cuál deja el mayor hueco libre después de asignar? _____
Consejo: En la práctica, First Fit es más rápido y funciona bien. Best Fit minimiza el desperdicio pero puede dejar muchos huecos pequeños inútiles.
