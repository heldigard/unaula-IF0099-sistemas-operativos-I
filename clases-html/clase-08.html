1. La Pirámide de Almacenamiento

La memoria no es uniforme. El SO debe equilibrar velocidad y costo moviendo datos entre niveles.

[ Registros CPU ] ◄── 1 ciclo (nS) ↓ [ Memoria Caché ] ◄── L1, L2, L3 (MBs) ↓ [ Memoria RAM ] ◄── Principal (Volátil) ↓ [ Disco SSD/NVMe ] ◄── TBs (Persistente)

Principio de Localidad

Temporal: Si accedes a un dato, es muy probable que lo necesites de nuevo pronto.

Espacial: Si accedes a un dato, es probable que necesites los que están almacenados físicamente cerca.

2. Direcciones Lógicas vs Físicas

Para un proceso, la memoria es un espacio infinito que empieza en la dirección 0. Para el hardware, es un conjunto de celdas físicas dispersas.

  • Dirección Lógica (Virtual): Generada por la CPU para el proceso.
  • Dirección Física: La ubicación real en los chips de RAM.
  • MMU (Memory Management Unit): El hardware que hace la traducción en tiempo real.

Base y Límite

En el modelo de asignación simple, el SO guarda el registro Base (dónde empieza el proceso en RAM) y el Límite (cuánto mide). Si el proceso intenta leer fuera de esa frontera, el SO lanza un Segmentation Fault.

3. Estrategias de Asignación Contigua

¿Cómo decide el SO dónde poner un nuevo proceso en la RAM?

EstrategiaDescripción ProfesionalImpacto
First FitUsa el primer hueco que sea suficientemente grande.El más rápido de calcular.
Best FitBusca el hueco que más se ajuste al tamaño exacto.Minimiza desperdicio, pero es lento.
Worst FitUsa el hueco más grande disponible.Deja huecos grandes útiles para el futuro.

4. Fragmentación: El Desperdicio de RAM

Fragmentación Interna

Ocurre en Particiones Fijas. El proceso no llena todo el bloque asignado. El espacio sobrante se pierde.

Fragmentación Externa

Ocurre en Particiones Dinámicas. Hay mucha RAM libre total, pero está dividida en pedazos tan pequeños que nada cabe.

Compactación (Defrag de RAM)

El SO mueve los procesos para unir los huecos. Es costoso en CPU pero necesario en sistemas sin paginación.

5. Comandos de Auditoría de Memoria

Diagnóstico Linux (Bash)

# Uso humano de la RAM
free -h

# Mapa detallado de un proceso
pmap -x [PID]

# Ver uso de caché del kernel
slabtop -sc

# Reporte preciso (USS/PSS)
sudo smem -tk

Diagnóstico Windows (PowerShell)

# Ver hardware físico de RAM
Get-CimInstance Win32_PhysicalMemory

# Ver uso de memoria por proceso
Get-Process | Sort-Object WorkingSet64 -Desc | 
Select-Object Name, WorkingSet64 -First 10

# Monitor de fallos de página
Get-Counter "\Memory\Page Faults/sec"

6. Laboratorio de Memoria Híbrido

Tarea 1: El Archivo de Configuración /proc/meminfo (Linux)

  1. Explore el archivo: cat /proc/meminfo.
  2. Identifique: MemFree (RAM vacía) vs MemAvailable (RAM realmente usable).
  3. ¿Cuánta RAM está dedicada a "Dirty pages" (datos esperando ser guardados al disco)?

Tarea 2: Monitor de Recursos (Windows)

  1. Abra resmon.exe → Pestaña Memoria.
  2. Identifique la memoria en estado Standby. ¿Es memoria libre o usada? (Tip: Es caché de archivos).
  3. Observe qué pasa con la "Memoria Modificada" cuando copia un archivo de 2GB.

Tarea 3: Mapa de Proceso

En Linux, ejecute pmap -x [PID] de su servidor SSH. Identifique las secciones [stack] y [heap]. ¿Cuál es más grande?

Casos Reales: Memoria en Producción

Caso 1: OutOfMemory en Servidor de Base de Datos

Escenario: Tu servidor PostgreSQL comenzó a fallar con errores "out of memory: cannot allocate memory". Al revisar con free -h ves que solo quedan 200MB disponibles de 16GB.

Diagnóstico:

  1. ¿Qué parámetros de PostgreSQL controlan la memoria por conexión?
  2. Si tienes 100 conexiones y work_mem = 256MB, ¿cuánta memoria solo para work_mem se necesita?
  3. ¿Qué ajustes harías para evitar el OOM?

Solución: Reducir max_connections y usar un pooler de conexiones como pgBouncer.

Caso 2: Servidor Linux Sin Swap y Alta Presión

Escenario: Un servidor en producción sin espacio swap muestra "Out of Memory" cuando la RAM llega al 100%. No hay forma de recuperar memoria porque no hay swap.

Diagnóstico:

  1. ¿Por qué es importante tener swap incluso cuando hay RAM disponible?
  2. ¿Qué indica un valor alto de "si" (swap in) y "so" (swap out) en vmstat 1?
  3. ¿Cómo determinas el tamaño adecuado de swap en un servidor moderno?

Comando clave: vmstat 1, swapon -s

Caso 3: Cache del Sistema consume toda la RAM

Escenario: Un servidor muestra que la aplicación solo tiene 2GB disponibles de 16GB. El resto está en "cached". Pero cuando la app intenta allocate más memoria, el sistema no responde.

Diagnóstico:

  1. ¿La memoria "cached" está realmente usada o disponible?
  2. ¿Qué diferencia hay entre "cache" y "buffer" en Linux?
  3. ¿Cómo liberas la memoria cache sin reiniciar?

Comando clave: echo 3 > /proc/sys/vm/drop_caches (solo en emergencias)
