🚀 FASE 1: Fundamentos y Arquitectura (E1)
15% 25 Feb RA1

📋 Descripción

En esta fase establecerás la base técnica del proyecto UCS. Debes demostrar que comprendes los fundamentos de sistemas operativos y que puedes configurar un entorno de virtualización profesional donde las máquinas virtuales se vean entre sí.

🎯 Objetivo: Montar tu "oficina de trabajo" para todo el semestre. Al finalizar, tendrás dos VMs (Linux y Windows) comunicándose en red.

🛠️ Qué debes hacer (Paso a paso)

1 Instalar VirtualBox y descargar ISOs

  • Descarga VirtualBox 7.x de https://www.virtualbox.org/
  • Descarga Ubuntu Server 22.04 LTS (versión SERVER, no Desktop)
  • Descarga Windows 10/11 Pro (o versión de evaluación)

2 Crear las Máquinas Virtuales

VM 1: UCS-Linux (Ubuntu Server)

Nombre: UCS-Linux Tipo: Linux → Ubuntu (64-bit) RAM: 4GB (mínimo 2GB) CPU: 2 núcleos Disco: 20GB (dinámico) Red: Adaptador Puente (Bridge)

VM 2: UCS-Windows (Windows Pro)

Nombre: UCS-Windows Tipo: Microsoft Windows → Windows 10/11 (64-bit) RAM: 6GB (mínimo 4GB) CPU: 2 núcleos Disco: 40GB (dinámico) Red: Adaptador Puente (Bridge)

3 Configurar Red en Modo Bridge

En VirtualBox: VM → Configuración → Red → Adaptador 1 → Conectado a: Adaptador Puente

Esto permite que las VMs obtengan IPs de tu red local como computadores reales.

4 Verificar Conectividad

En Linux:

# Ver tu IP ip addr show # Hacer ping a Windows ping 192.168.1.XXX # (IP de tu VM Windows)

En Windows:

# Ver tu IP ipconfig # Hacer ping a Linux ping 192.168.1.XXX # (IP de tu VM Linux)

5 Recolectar Información del Sistema

En Linux:

uname -a # Información del kernel lscpu # Información de CPU free -h # Memoria df -h # Disco

En Windows:

systeminfo # Información completa del sistema

6 Crear Diagrama de Red

Dibuja un esquema visual que incluya:

  • Tu computador (Host)
  • Router/Red local
  • VM Linux con su IP y recursos
  • VM Windows con su IP y recursos
  • Flechas mostrando la comunicación entre VMs

Herramientas: draw.io, PowerPoint, o incluso papel y lápiz (luego fotografía)

⚙️ FASE 2: Procesos y Monitoreo (E2)
15% 11 Mar RA2

📋 Descripción

Implementarás visibilidad operativa sobre tu sistema UCS. Como ingeniero, no debes entrar a la VM para saber que algo falló; el sistema debe avisarte automáticamente.

🎯 Objetivo: Crear scripts de monitoreo que detecten problemas y envíen alertas. Automatizar la supervisión de procesos y servicios.

🛠️ Qué debes hacer (Paso a paso)

1 Crear Script de Monitoreo en Linux (monitor.sh)

Este script debe ejecutarse cada N segundos y alertar si el CPU supera el 80%.

#!/bin/bash # monitor.sh - Script de monitoreo UCS UMBRAL_CPU=80 INTERVALO=5 while true; do # Obtener uso de CPU USO_CPU=$(top -bn1 | grep "Cpu(s)" | awk '{print $2}' | cut -d'%' -f1) echo "$(date) - Uso de CPU: ${USO_CPU}%" # Verificar si supera umbral if (( $(echo "$USO_CPU > $UMBRAL_CPU" | bc -l) )); then echo "⚠️ ALERTA: Uso de CPU alto: ${USO_CPU}%" # Aquí puedes agregar envío de correo o notificación fi sleep $INTERVALO done

Comandos adicionales a incluir:

# Ver procesos que más consumen ps aux --sort=-%cpu | head -n 5 # Ver uso de memoria free -h # Ver espacio en disco df -h

2 Crear Script de Servicios en Windows (services.ps1)

Este script vigila el servicio "Cola de Impresión" (Spooler) y lo reinicia automáticamente si se detiene.

# services.ps1 - Monitoreo de servicios Windows $SERVICIO = "Spooler" $INTERVALO = 10 while ($true) { $estado = Get-Service -Name $SERVICIO Write-Host "$(Get-Date) - Estado del servicio $SERVICIO`: $($estado.Status)" if ($estado.Status -eq "Stopped") { Write-Host "⚠️ ALERTA: Servicio detenido. Reiniciando..." -ForegroundColor Red Start-Service -Name $SERVICIO Write-Host "✅ Servicio reiniciado correctamente" -ForegroundColor Green } Start-Sleep -Seconds $INTERVALO }

3 Configurar Ejecución Automática

En Linux (systemd):

# Crear archivo de servicio sudo nano /etc/systemd/system/ucs-monitor.service # Contenido: [Unit] Description=UCS Monitor Service After=network.target [Service] Type=simple ExecStart=/ruta/a/monitor.sh Restart=always User=tu-usuario [Install] WantedBy=multi-user.target # Activar servicio sudo systemctl enable ucs-monitor sudo systemctl start ucs-monitor

En Windows (Tarea Programada):

# Abrir Task Scheduler (taskschd.msc) # Crear nueva tarea: # - General: Ejecutar con privilegios más altos # - Desencadenadores: Al inicio # - Acción: Iniciar PowerShell.exe -File "C:\ruta\services.ps1"

4 Probar los Scripts

Prueba en Linux:

# Ejecutar script manualmente chmod +x monitor.sh ./monitor.sh # En otra terminal, generar carga de CPU: stress --cpu 4 --timeout 30 # Verificar que el script detecta el alto uso de CPU

Prueba en Windows:

# Ejecutar script .\services.ps1 # Detener manualmente el servicio Spooler: Stop-Service Spooler # Verificar que el script lo reinicia automáticamente

🔍 Ejemplos de Escenarios que Resolverás

📊 Escenario 1: Memory Pressure (Fuga de Memoria)

Situación: Un proceso tiene un "Memory Leak" (fuga de memoria) y está consumiendo toda la RAM.

Tu tarea:

# 1. Identificar qué proceso consume más memoria ps aux --sort=-%mem | head -n 5 # 2. Ver detalles del mapeo de memoria del proceso pmap -x PID # 3. Monitorear uso de swap vmstat 1 10 # 4. Documentar hallazgos y solución

💾 Escenario 2: I/O Bottleneck (Cuello de Botella de Disco)

Situación: El servidor web está lento. Los usuarios reportan tiempos de respuesta altos.

Tu tarea:

# 1. Ver estadísticas de I/O por disco iostat -x 1 10 # Observar columnas: # - %util: Porcentaje de utilización (cerca de 100% = problema) # - await: Tiempo promedio de espera (alto = lento) # 2. Ver procesos que más leen/escriben iotop # 3. Analizar y proponer solución

🔗 Escenario 3: Forense de Archivos (Inodos Huérfanos)

Situación: El sistema reporta "disco lleno" pero al revisar no hay archivos grandes.

Tu tarea:

# 1. Ver uso de inodos (no solo espacio) df -i # 2. Buscar archivos con inodos huérfanos lsof +L1 # 3. Ver archivos borrados pero con procesos abiertos lsof | grep deleted # 4. Encontrar y reparar links simbólicos rotos find / -xtype l 2>/dev/null

🔒 FASE 4: Seguridad y Hardening (E4)
15% 22 Abr RA4

📋 Descripción

Transformarás el sistema UCS de "funcional" a "seguro y a prueba de ataques". Aplicarás técnicas de hardening en ambos sistemas operativos y documentarás las vulnerabilidades mitigadas.

🛠️ Qué debes hacer (Paso a paso)

1 Hardening en Linux

a) Configurar Firewall (UFW):

# Ver estado actual sudo ufw status verbose # Política por defecto: denegar todo entrada, permitir salida sudo ufw default deny incoming sudo ufw default allow outgoing # Permitir solo SSH (puerto 22) desde tu red sudo ufw allow from 192.168.1.0/24 to any port 22 # Si tienes Apache, permitir HTTP/HTTPS sudo ufw allow 80/tcp sudo ufw allow 443/tcp # Activar firewall sudo ufw enable # Verificar reglas sudo ufw status numbered

b) Implementar ACLs (Access Control Lists):

# Crear directorio para datos UCS sudo mkdir -p /var/www/ucs # Establecer propietario www-data sudo chown www-data:www-data /var/www/ucs # Permisos base: solo propietario y grupo sudo chmod 750 /var/www/ucs # ACL granular: usuario específico tiene acceso de lectura sudo setfacl -m u:tu-usuario:r /var/www/ucs # Verificar ACLs getfacl /var/www/ucs

c) Desactivar servicios innecesarios:

# Ver servicios activos sudo systemctl list-units --type=service --state=running # Desactivar servicios que no necesitas sudo systemctl disable [servicio] sudo systemctl stop [servicio] # Ejemplos comunes a desactivar en servidor: # - cups (impresión) # - bluetooth # - avahi-daemon

2 Hardening en Windows

a) Configurar Políticas de Seguridad Local:

# Abrir editor de políticas secpol.msc # Configurar: # - Políticas de contraseñas: # * Longitud mínima: 8 caracteres # * Complejidad: Habilitada # * Vigencia máxima: 90 días # # - Políticas de bloqueo de cuenta: # * Umbral de bloqueo: 5 intentos fallidos # * Duración: 30 minutos

b) Configurar Windows Firewall:

# Abrir firewall wf.msc # Crear reglas de entrada: # 1. Bloquear todo por defecto # 2. Permitir solo: # - Puerto 3389 (RDP) - si lo necesitas # - Puerto 80/443 (IIS) - si está activo # - ICMP (ping) - opcional

c) Auditar eventos de seguridad:

# Abrir Visor de Eventos eventvwr.msc # Navegar a: # Windows Logs → Security # Ver intentos de inicio de sesión: # Event ID 4624 - Inicio exitoso # Event ID 4625 - Inicio fallido # Configurar auditoría adicional en: # secpol.msc → Configuración avanzada de auditoría

3 Crear Matriz de Riesgos

Documenta mínimo 8 vulnerabilidades identificadas y cómo las mitigaste.

# Vulnerabilidad Riesgo Mitigación Aplicada Evidencia
1 Puertos abiertos innecesarios Alto Firewall UFW configurado ufw status
2 Permisos de archivos débiles Medio ACLs implementados getfacl
3 Servicios innecesarios activos Medio Servicios desactivados systemctl
... ... ... ... ...

🌐 FASE 5: Integración de Servicios (E5)
15% 06 May RA5

📋 Descripción

Puesta en marcha definitiva. Los nodos Linux y Windows deben colaborar para servir la aplicación web UCS. Integrarás servidores web, almacenamiento redundante y monitoreo end-to-end.

🛠️ Qué debes hacer (Paso a paso)

1 Desplegar Servidor Web Apache (Linux)

a) Instalar y configurar Apache:

# Instalar Apache sudo apt update sudo apt install apache2 -y # Crear Virtual Host para UCS sudo nano /etc/apache2/sites-available/ucs.conf # Contenido: <VirtualHost *:80> ServerName ucs.local DocumentRoot /var/www/ucs <Directory /var/www/ucs> AllowOverride All Require all granted </Directory> ErrorLog ${APACHE_LOG_DIR}/ucs_error.log CustomLog ${APACHE_LOG_DIR}/ucs_access.log combined </VirtualHost> # Activar sitio sudo a2ensite ucs.conf sudo a2dissite 000-default.conf sudo systemctl reload apache2

b) Configurar HTTPS (SSL auto-firmado):

# Generar certificado SSL sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \ -keyout /etc/ssl/private/ucs.key \ -out /etc/ssl/certs/ucs.crt # Configurar VirtualHost SSL sudo nano /etc/apache2/sites-available/ucs-ssl.conf # Contenido: <VirtualHost *:443> ServerName ucs.local DocumentRoot /var/www/ucs SSLEngine on SSLCertificateFile /etc/ssl/certs/ucs.crt SSLCertificateKeyFile /etc/ssl/private/ucs.key <Directory /var/www/ucs> AllowOverride All Require all granted </Directory> </VirtualHost> # Activar módulos SSL y sitio sudo a2enmod ssl sudo a2ensite ucs-ssl.conf sudo systemctl reload apache2

2 Desplegar Servidor IIS (Windows)

a) Instalar IIS:

# PowerShell como Administrador Install-WindowsFeature -name Web-Server -IncludeManagementTools # Verificar instalación Get-WindowsFeature Web-Server

b) Configurar Application Pool y Sitio:

# Crear Application Pool dedicado Import-Module WebAdministration New-Item -Path IIS:\AppPools\UCS-Pool Set-ItemProperty -Path IIS:\AppPools\UCS-Pool -Name "managedRuntimeVersion" -Value "v4.0" # Crear directorio del sitio New-Item -ItemType Directory -Path "C:\inetpub\ucs" # Crear sitio web New-Website -Name "UCS-Windows" -Port 8080 -PhysicalPath "C:\inetpub\ucs" -ApplicationPool "UCS-Pool" # Verificar sitio creado Get-Website

3 Configurar Almacenamiento Avanzado

a) RAID 1 (Mirroring) en Linux:

# Instalar mdadm sudo apt install mdadm -y # Crear RAID 1 con dos discos sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc # Formatear sudo mkfs.ext4 /dev/md0 # Montar sudo mkdir /mnt/raid1 sudo mount /dev/md0 /mnt/raid1 # Configurar fstab para montaje automático echo '/dev/md0 /mnt/raid1 ext4 defaults 0 0' | sudo tee -a /etc/fstab # Verificar estado del RAID cat /proc/mdstat sudo mdadm --detail /dev/md0

b) Storage Spaces en Windows:

# PowerShell como Administrador # Ver discos disponibles Get-PhysicalDisk | Where-Object {$_.CanPool -eq $true} # Crear Storage Pool $disks = Get-PhysicalDisk | Where-Object {$_.CanPool -eq $true} New-StoragePool -FriendlyName "UCS-Pool" -StorageSubsystemFriendlyName "Windows Storage*" -PhysicalDisks $disks # Crear Virtual Disk con mirroring New-VirtualDisk -StoragePoolFriendlyName "UCS-Pool" -FriendlyName "UCS-Disk" -ResiliencySettingName Mirror -Size 20GB # Inicializar y formatear Get-VirtualDisk -FriendlyName "UCS-Disk" | Get-Disk | Initialize-Disk Get-VirtualDisk -FriendlyName "UCS-Disk" | Get-Partition | Format-Volume -FileSystem NTFS -NewFileSystemLabel "UCS-Data"

4 Configurar Interoperabilidad (Samba)

Permitir que Windows acceda a carpetas compartidas de Linux:

# Instalar Samba sudo apt install samba -y # Crear carpeta compartida sudo mkdir -p /srv/samba/ucs-data sudo chown nobody:nogroup /srv/samba/ucs-data sudo chmod 777 /srv/samba/ucs-data # Configurar smb.conf sudo nano /etc/samba/smb.conf # Agregar al final: [ucs-data] comment = UCS Shared Data path = /srv/samba/ucs-data browsable = yes guest ok = yes read only = no create mask = 0755 # Reiniciar Samba sudo systemctl restart smbd sudo systemctl restart nmbd # Verificar estado sudo systemctl status smbd

5 Crear Dashboard de Integración

Crear un script que verifique que todo está funcionando:

#!/bin/bash # dashboard-check.sh echo "===================================" echo "Dashboard de Salud UCS" echo "$(date)" echo "===================================" # Verificar Apache echo -e "\n🌐 Servidor Web Apache:" if systemctl is-active --quiet apache2; then echo "✅ Apache está corriendo" curl -s -o /dev/null -w "%{http_code}" http://localhost else echo "❌ Apache está detenido" fi # Verificar RAID echo -e "\n💾 Estado RAID:" cat /proc/mdstat | grep "md0" # Verificar Samba echo -e "\n📁 Servicio Samba:" if systemctl is-active --quiet smbd; then echo "✅ Samba está corriendo" else echo "❌ Samba está detenido" fi # Verificar monitoreo echo -e "\n⚙️ Script de monitoreo:" if pgrep -f "monitor.sh" > /dev/null; then echo "✅ Monitor está activo" else echo "❌ Monitor no está corriendo" fi echo -e "\n==================================="
