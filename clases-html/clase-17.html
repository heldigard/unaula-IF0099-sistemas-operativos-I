Teoría: HTTP y Servidores Web

¿Qué es un Servidor Web?

Un servidor web es software que procesa solicitudes HTTP de clientes (navegadores) y entrega contenido (HTML, CSS, imágenes, etc.).

Protocolo HTTP

HTTP (HyperText Transfer Protocol)

  • Protocolo de capa de aplicación
  • Cliente-servidor (request-response)
  • Puerto 80 (HTTP) / 443 (HTTPS)
  • Sin estado (stateless)

Métodos comunes:

  • GET - Obtener recurso
  • POST - Enviar datos
  • PUT - Actualizar recurso
  • DELETE - Eliminar recurso

HTTP vs HTTPS

Características principales:

  • Open Source (Apache License)
  • Multiplataforma (Linux, Windows, macOS)
  • Modular y extensible
  • ~40% de los servidores web (2024)
  • Virtual Hosting (múltiples sitios en 1 servidor)

Virtual Hosts

Virtual Hosting permite alojar múltiples sitios web en un solo servidor usando:

  • IP-based: Diferentes direcciones IP
  • Name-based: Diferentes nombres de dominio (mismo IP) ← Más común
Ejemplo: Un servidor con IP 192.168.1.10 puede servir:
  • www.sitio1.com → /var/www/sitio1
  • www.sitio2.com → /var/www/sitio2
  • www.sitio3.com → /var/www/sitio3

Instalación de Apache2

Requisitos previos:
  • VM con Ubuntu Server 22.04/24.04
  • Usuario con privilegios sudo
  • Conexión a Internet

Paso 1: Actualizar el sistema

sudo apt update
sudo apt upgrade -y

Paso 2: Instalar Apache2

# Instalar Apache
sudo apt install apache2 -y

# Verificar versión
apache2 -v

Paso 3: Verificar el servicio

# Verificar estado
sudo systemctl status apache2

# Habilitar inicio automático
sudo systemctl enable apache2

# Verificar que está escuchando
sudo ss -tlnp | grep :80

Paso 4: Probar desde el navegador

Abre el navegador y accede a:

  • http://localhost (desde la VM)
  • http://IP_DE_TU_VM (desde el host)

Deberías ver la página "Apache2 Ubuntu Default Page"

Ubicación de archivos importantes:
  • /var/www/html - Document root por defecto
  • /etc/apache2/ - Configuración
  • /etc/apache2/apache2.conf - Configuración principal
  • /etc/apache2/sites-available/ - Virtual hosts disponibles
  • /etc/apache2/sites-enabled/ - Virtual hosts activos
  • /var/log/apache2/ - Logs (access.log, error.log)

Virtual Hosts

Vamos a configurar dos sitios web en el mismo servidor:

  • site1.local → Sitio de prueba 1
  • site2.local → Sitio de prueba 2

Paso 1: Crear directorios para cada sitio

# Crear directorios
sudo mkdir -p /var/www/site1.local
sudo mkdir -p /var/www/site2.local

# Crear páginas de prueba
echo "<h1>Bienvenido a Site 1</h1>" | sudo tee /var/www/site1.local/index.html
echo "<h1>Bienvenido a Site 2</h1>" | sudo tee /var/www/site2.local/index.html

# Establecer permisos
sudo chown -R www-data:www-data /var/www/site1.local
sudo chown -R www-data:www-data /var/www/site2.local
sudo chmod -R 755 /var/www/site1.local
sudo chmod -R 755 /var/www/site2.local

Paso 2: Crear archivos de Virtual Host

Para site1.local:

sudo nano /etc/apache2/sites-available/site1.local.conf

Contenido:

<VirtualHost *:80>
    ServerName site1.local
    ServerAlias www.site1.local
    DocumentRoot /var/www/site1.local

    ErrorLog ${APACHE_LOG_DIR}/site1.local_error.log
    CustomLog ${APACHE_LOG_DIR}/site1.local_access.log combined
</VirtualHost>

Para site2.local:

sudo nano /etc/apache2/sites-available/site2.local.conf

Contenido:

<VirtualHost *:80>
    ServerName site2.local
    ServerAlias www.site2.local
    DocumentRoot /var/www/site2.local

    ErrorLog ${APACHE_LOG_DIR}/site2.local_error.log
    CustomLog ${APACHE_LOG_DIR}/site2.local_access.log combined
</VirtualHost>

Paso 3: Habilitar los Virtual Hosts

# Habilitar sitios
sudo a2ensite site1.local.conf
sudo a2ensite site2.local.conf

# Deshabilitar sitio por defecto (opcional)
sudo a2dissite 000-default.conf

# Verificar configuración
sudo apache2ctl configtest

# Recargar Apache
sudo systemctl reload apache2

Paso 4: Configurar resolución de nombres

En Windows (host): Editar C:\Windows\System32\drivers\etc\hosts

192.168.1.10  site1.local
192.168.1.10  site2.local

En Linux (VM): Editar /etc/hosts

127.0.0.1  site1.local
127.0.0.1  site2.local

Configurar HTTPS con Certificado Self-Signed

Nota: Los certificados self-signed generarán advertencias en el navegador. Son útiles solo para desarrollo/testing.

Paso 1: Habilitar módulo SSL

sudo a2enmod ssl
sudo systemctl restart apache2

Paso 2: Generar certificado self-signed

sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout /etc/ssl/private/apache-selfsigned.key \
    -out /etc/ssl/certs/apache-selfsigned.crt

Se te pedirá información:

  • Country: CO
  • State: Antioquia
  • Locality: Medellin
  • Organization: UNAULA
  • Common Name: site1.local

Paso 3: Configurar Virtual Host HTTPS

Editar /etc/apache2/sites-available/site1.local.conf:

<VirtualHost *:80>
    ServerName site1.local
    Redirect permanent / https://site1.local/
</VirtualHost>

<VirtualHost *:443>
    ServerName site1.local
    DocumentRoot /var/www/site1.local

    SSLEngine on
    SSLCertificateFile /etc/ssl/certs/apache-selfsigned.crt
    SSLCertificateKeyFile /etc/ssl/private/apache-selfsigned.key

    ErrorLog ${APACHE_LOG_DIR}/site1.local_error.log
    CustomLog ${APACHE_LOG_DIR}/site1.local_access.log combined
</VirtualHost>

Paso 4: Recargar y probar

# Verificar configuración
sudo apache2ctl configtest

# Recargar Apache
sudo systemctl reload apache2

# Probar HTTPS
curl -k https://site1.local

Actividad: Configuración Completa de Apache

Objetivo

Configurar un servidor Apache con múltiples sitios web y HTTPS.

Requisitos

  1. Instalar Apache2 en Ubuntu Server
  2. Verificar que el servicio esté funcionando

  4. Configurar contenido diferente para cada sitio
  5. Configurar HTTPS con certificado self-signed para sitio1.local
