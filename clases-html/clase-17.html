1. ¿Qué es Apache HTTP Server?

Es el servidor web de código abierto más veterano y flexible del mercado. Su diseño se basa en un núcleo ligero que se extiende mediante **Módulos** cargables. A diferencia de IIS, Apache se configura mediante archivos de texto.

Filosofía de Configuración

En Linux Ubuntu, la configuración se divide para facilitar el mantenimiento:

  • /etc/apache2/apache2.conf: Archivo maestro.
  • sites-available/: Sitios web que "podrían" existir.
  • sites-enabled/: Sitios web que el servidor está sirviendo actualmente (links simbólicos).

2. Virtual Hosting: Múltiples dominios, un IP

Permite a una empresa alojar miles de dominios en un solo servidor físico.

# Estructura de un Virtual Host en /etc/apache2/sites-available/ucs.conf
<VirtualHost *:80>
    ServerName ucs.local
    DocumentRoot /var/www/ucs/html
    ErrorLog ${APACHE_LOG_DIR}/ucs_error.log
</VirtualHost>

3. Módulos y MPMs (Multi-Processing Modules)

Define cómo Apache usa la CPU y la RAM para atender miles de peticiones:

  • Event: (Estándar moderno) Usa hilos optimizados para conexiones persistentes.
  • Prefork: Usa un proceso por cada usuario. Muy estable pero consume mucha RAM.
  • Worker: Híbrido entre procesos e hilos.

4. Seguridad y SSL (HTTPS)

Usamos **TLS/SSL** para cifrar la comunicación. El puerto estándar es el 443.

  • Certificado (.crt): Documento público que identifica al servidor.
  • Llave Privada (.key): Código secreto que el servidor usa para descifrar datos. Debe protegerse con permisos 600.

5. Comandos de Gestión y Auditoría

Mantenimiento (Bash)

# Habilitar un sitio nuevo
sudo a2ensite ucs.conf

# Deshabilitar el sitio default
sudo a2dissite 000-default.conf

# Habilitar módulo de seguridad SSL
sudo a2enmod ssl

# Validar errores de sintaxis
sudo apache2ctl configtest

Diagnóstico en Vivo

# Ver sitios cargados en RAM
sudo apache2ctl -S

# Ver hilos de Apache en tiempo real
top -H -p $(pgrep apache2 | head -1)

# Ver ataques o errores en vivo
sudo tail -f /var/log/apache2/error.log

# Ver visitas en tiempo real
sudo tail -f /var/log/apache2/access.log

6. Actividad Práctica Final: Despliegue UCS (Insumo E5)

Laboratorio: El Portal de Servicios Linux

Objetivo: Poner en producción el sitio web corporativo seguro.

Pasos a realizar:

  1. Instale Apache: sudo apt install apache2 -y.
  2. Certificado Forense: Genere una llave privada y un certificado de 2048 bits: 
    sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout /etc/ssl/private/ucs.key -out /etc/ssl/certs/ucs.crt
  3. Virtual Host: Cree /etc/apache2/sites-available/ucs-ssl.conf y configure el puerto 443 apuntando a sus nuevos archivos de certificado.
  4. Seguridad de Archivos: Asegure que la carpeta /var/www/ucs pertenezca al usuario www-data y tenga permisos 750.

Tarea de Cierre: Use curl -k https://localhost para verificar que el servidor responde correctamente (el -k ignora que el certificado es auto-firmado).

Entregable: Una captura del comando apache2ctl -S mostrando su sitio HTTPS configurado para la Evaluación E5.

Casos Reales: Apache en Producción

Caso 1: Apache No Inicia tras Cambio de Config

Escenario: Después de modificar el archivo de configuración, Apache no quiere iniciar. Muestra "Syntax error".

Diagnóstico:

# Validar sintaxis sin iniciar
sudo apache2ctl configtest

# Ver error específico
sudo apachectl -t

# Si hay error en VirtualHost, revisar /var/log/apache2/error.log

Caso 2: Servidor Lento con Muchas Conexiones

Escenario: El servidor responde lento cuando hay más de 100 usuarios simultáneos.

Diagnóstico:

# Ver consumo de memoria por proceso Apache
ps aux | grep apache2 | awk '{sum+=$6} END {print sum/1024 " MB"}'

# Ver número de conexiones establecidas
netstat -tun | grep :80 | wc -l

# Cambiar MPM de Prefork a Event para mejor rendimiento
sudo a2dismod mpm_prefork
sudo a2enmod mpm_event

Caso 3: Error 403 Forbidden en Archivo Existente

Escenario: Los usuarios ven "403 Forbidden" al acceder a archivos que definitely existen.

Causa: Permisos incorrectos en la carpeta o archivo .htaccess restrictivo.

Solución:

# Verificar permisos (debe ser al menos 755 en carpetas, 644 en archivos)
ls -la /var/www/ucs/

# Verificar que Apache tiene permiso de ejecución en toda la ruta
namei -l /var/www/ucs/index.html

# Si usa .htaccess, verificar que AllowOverride está configurado
