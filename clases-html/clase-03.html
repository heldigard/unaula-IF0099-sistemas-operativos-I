Cambio de Contexto

¿Qué es el Cambio de Contexto?

El cambio de contexto (context switch) es el proceso mediante el cual el sistema operativo transfiere el control de la CPU de un proceso a otro. Este es un mecanismo fundamental que permite la multiprogramación y el funcionamiento eficiente de los sistemas operativos modernos.

Analogía: Imagina un professor con múltiples estudiantes preguntando. El professor atiende a un estudiante (proceso en ejecución), anota dónde se quedó (guarda estado), y atiende al siguiente (cambio de contexto). Cuando vuelve al primer estudiante, continúa desde donde lo dejó.
¿Por qué esto importa?
Sin cambio de contexto, tu computadora solo podría hacer UNA cosa a la vez. No podrías tener el navegador abierto mientras escuchas música y descargas un archivo. El cambio de contexto hace que todo parezca suceder "al mismo tiempo".

Componentes del Cambio de Contexto

  • Salvado del estado: Guardar registros, contador de programa, puntero de pila
  • Actualización del PCB: Guardar información del proceso que cede la CPU
  • Selección del nuevo proceso: El scheduler elige el siguiente proceso
  • Carga del estado: Restaurar registros y contador del nuevo proceso
  • Actualización de estructuras: Modificar tablas de memoria y descriptores
Tiempo de Cambio de Contexto: El cambio de contexto no es "gratis". El sistema operativo debe invertir tiempo de CPU en realizar este intercambio. Este tiempo depende de la arquitectura del hardware y de la eficiencia del kernel.

Costos del Cambio de Contexto

Componente Descripción Impacto
Salvado de registros Almacenar estado actual de CPU Alto
Actualización de tablas Cambiar punteros de memoria virtual Medio
Invalidación de caché Limpiar caché de CPU Alto
Cambio de privilegio kernel → usuario Bajo

PCB (Process Control Block)

El PCB es la estructura de datos principal que representa un proceso en el sistema operativo. Contiene toda la información necesaria para gestionar un proceso.

Campos del PCB

Identificación

  • PID: Identificador único del proceso
  • PPID: PID del proceso padre
  • Usuario propietario

Estado de CPU

  • Contador de programa
  • Registros generales
  • Puntero de pila
  • Flags de estado

Gestión de Memoria

  • Tabla de páginas
  • Límites de segmentos
  • Tabla de descriptores

Información de E/S

  • Lista de archivos abiertos
  • Dispositivos asignados
  • Estado de E/S

Estados del Proceso

Un proceso puede estar en diferentes estados durante su ciclo de vida. El modelo más común es el de 5 estados.

Estados del Modelo de 5 Estados

Estado Descripción Causa
NUEVO Proceso siendo creado fork(), CreateProcess()
LISTO Esperando asignación de CPU Listo para ejecutar
EJECUTANDO Instrucciones ejecutándose Tiene la CPU asignada
BLOQUEADO Esperando evento/E-S read(), wait()
TERMINADO Proceso finalizado exit(), return
Estado de "Suspensión": En sistemas modernos, existe un estado adicional de "suspendido" donde el proceso puede ser movido a memoria swap para liberar RAM.

Algoritmos de Planificación de CPU

El scheduler (planificador) decide qué proceso de la cola de "listos" debe ejecutarse next. Existen diferentes algoritmos con distintas propiedades.

Comparativa de Algoritmos

Algoritmo Tipo Ventaja Desventaja
FCFS (First Come, First Served) No expulsivo Simple, justo Efecto convoy
SJF (Shortest Job First) No expulsivo Tiempo de espera mínimo Inanición de procesos largos
SRTF (Shortest Remaining Time) Expulsivo Respuesta rápida Inanición
RR (Round Robin) Expulsivo 、公平, responsivo Overhead de cambios
Por Prioridad Expulsivo/No Importancia Inanición

FCFS - First Come, First Served

El proceso que llega primero se ejecuta primero. Es el algoritmo más simple.

Proceso | Tiempo de ráfaga | Tiempo de espera
--------|------------------|-----------------
  P1    |       24        |        0
  P2    |        3        |       24
  P3    |        3        |       27

Tiempo de espera promedio: (0 + 24 + 27) / 3 = 17 ms

SJF - Shortest Job First

Selecciona el proceso con menor tiempo de ráfaga de CPU.

Proceso | Tiempo de ráfaga | Tiempo de espera
--------|------------------|-----------------
  P1    |        6        |        3
  P2    |        8        |        9
  P3    |        7        |        0
  P4    |        3        |        7

Tiempo de espera promedio: (3 + 9 + 0 + 7) / 4 = 4.75 ms
(Mínimo posible)

RR - Round Robin

Cada proceso obtiene un quantum de tiempo fijo. Si no termina, vuelve a la cola.

Quantum = 4 ms

Proceso | Tiempo de ráfaga | Tiempo de espera
--------|------------------|-----------------
  P1    |       10        |        0
  P2    |        5        |        4
  P3    |        8        |        7

Secuencia: P1(4) → P2(4) → P3(4) → P1(4) → P2(1) → P3(4) → P1(2)
Ejemplo Interactivo: Ejecuta el siguiente comando para ver los procesos en estado "listos" y sus prioridades en Linux: 
ps -eo pid,ppid,stat,pri,ni,cmd --sort=pri

Práctica Guiada: Jugando con Procesos (30 min)

Objetivo: Ver los conceptos teóricos en acción. No te preocupes si no entiendes todo de inmediato, la idea es familiarizarte con los comandos.
Consejo antes de empezar: Abre DOS terminales. En una ejecutarás comandos y en la otra observarás los resultados. Esto hará todo más fácil de entender.

Ejercicio 1: Ver procesos corriendo (5 min)

Vamos a ver qué procesos están ejecutándose en tu sistema ahora mismo:

# Ver los procesos principales (solo los 10 que más CPU usan)
ps aux --sort=-%cpu | head -10

# Ver procesos de tu usuario
ps aux | grep $USER | head -10
¿Qué ves? Cada línea es un proceso. Busca:
- PID: El número de identificación (como una cédula)
- %CPU: Cuánto procesador está usando
- COMMAND: Qué programa es

Ejercicio 2: Crear y observar un proceso (5 min)

Vamos a crear un proceso simple y ver cómo cambia de estado:

Paso 1: Crear un proceso "dormilón"

# Ejecutar sleep (duerme por 300 segundos = 5 minutos)
sleep 300 &

# Verás algo como: [1] 1234
# [1] = número del trabajo
# 1234 = PID del proceso

# Guarda ese número (tu PID será diferente)

Paso 2: Verificar que existe

# Buscar tu proceso sleep
ps aux | grep sleep

# Deberías ver algo como:
# usuario  1234  0.0  0.0   7200   800 pts/0    S    10:00   0:00 sleep 300
# 
# La "S" significa que está "Sleeping" (dormido, esperando)

Paso 3: Detener el proceso (como pausar un video)

# Detener el proceso (usa tu número de PID)
kill -STOP 1234

# Verificar que está detenido
ps aux | grep sleep

# Ahora debería mostrar "T" (Stopped) en lugar de "S"
# usuario  1234  0.0  0.0   7200   800 pts/0    T    10:00   0:00 sleep 300

Paso 4: Reanudar el proceso (como darle play)

# Reanudar el proceso
kill -CONT 1234

# Verificar que volvió a "S" (sleeping)
ps aux | grep sleep

Paso 5: Terminar el proceso

# Matar el proceso
kill 1234

# Verificar que desapareció
ps aux | grep sleep
# Solo debería mostrar el propio comando "grep"
¿Lo lograste? Si el proceso no aparece o los comandos no funcionan, no te preocupes. Pregunta al profesor o intenta de nuevo.

Ejercicio 3: Observar el administrador de tareas (5 min)

# Ejecutar top (el administrador de tareas de Linux)
top

# Verás una pantalla que se actualiza cada pocos segundos
# Muestra qué procesos están usando más CPU y memoria

# Dentro de top, prueba estas teclas:
# 'q' - Salir de top
# 'M' - Ordenar por uso de memoria
# 'P' - Ordenar por uso de CPU (vuelve al orden normal)

# Observa cómo los números cambian - eso es el cambio de contexto en acción

Ejercicio 4: Ver árbol de procesos (5 min)

Los procesos tienen "familias". Vamos a ver la jerarquía:

# Ver árbol de procesos (versión simple)
pstree | head -20

# Esto muestra qué procesos iniciaron otros procesos
# Por ejemplo: systemd (el abuelo) → sshd (el padre) → bash (el hijo)

# Ver tu shell actual y su familia
echo "Mi PID es: $$"
pstree -p | grep $$

# Busca tu PID en la salida y mira quién está "arriba" de ti
Analogía familiar: Igual que tú tienes padres, abuelos y bisabuelos, los procesos también tienen una familia. El proceso más antiguo suele ser init o systemd (PID 1).

Ejercicio 5: Limpieza (2 min)

Si creaste procesos que siguen corriendo, vamos a limpiar:

# Matar todos los procesos sleep que puedas tener
killall sleep 2>/dev/null

# Verificar que no quedaron procesos zombies
ps aux | grep Z
# No debería mostrar nada (o solo el grep mismo)

Ejercicio de Refuerzo: Explorando Procesos

Objetivo: Observar procesos en tu sistema y entender su jerarquía.

Actividades sugeridas:

  1. Crear diferentes procesos:
    • Abre una terminal y ejecuta: yes > /dev/null & (consume CPU)
    • En otra terminal ejecuta: sleep 300 & (está en espera)
    • Observa ambos con: ps -eo pid,ppid,stat,cmd | grep -E "yes|sleep"
  2. Descubre la jerarquía:
    • Ejecuta pstree -p y busca tu shell actual
    • ¿Qué proceso inició tu shell? (hint: revisa la columna PPID)
    • ¿Y quién inició ese proceso?
  3. Observa el administrador de tareas:
    • Ejecuta top y observa qué procesos usan más CPU
    • Presiona q para salir
    • ¿Reconoces algún proceso?
Consejo: No te preocupes si no entiendes todo de inmediato. La idea es familiarizarte con los comandos. Puedes detener los procesos de prueba con kill [PID] cuando termines.

Resumen de la Clase

Cambio de Contexto

Proceso de transferir el control de CPU entre procesos. Incluye salvado/carga de estado y actualización de estructuras del kernel.

PCB

Estructura de datos que contiene toda la información de un proceso: identificación, estado de CPU, memoria y E/S.

Estados del Proceso

Nuevo → Listo → Ejecutando → Bloqueado → Terminado. Las transiciones ocurren por eventos del sistema.

Algoritmos de Planificación

FCFS, SJF, SRTF, Round Robin, Prioridades. Cada uno tiene trade-offs entre throughput, latencia y fairness.

Comandos Aprendidos Hoy

  • ps -eo pid,ppid,stat,pri,cmd - Ver PCB de procesos
  • pstree -p - Jerarquía de procesos
  • top - Monitor en tiempo real
  • kill -STOP/-CONT - Controlar estados
  • renice - Cambiar prioridad
