Objetivos de Aprendizaje

Al finalizar esta clase, serás capaz de:

  1. Explicar la diferencia entre memoria física y virtual
  2. Describir cómo funciona la paginación (paging)
  3. Entender el proceso de swapping
  4. Reconocer el fenómeno de thrashing y cómo evitarlo
  5. Monitorear el uso de memoria y swap
  6. Comparar la gestión de memoria entre Linux y Windows

Conceptos Clave de Sesión

  • Page Fault (Fallo de Página): Error generado cuando un proceso intenta acceder a una página que no está cargada en la RAM física.
  • Thrashing (Hiperpaginación): Situación donde el sistema pasa más tiempo moviendo páginas entre disco y RAM que ejecutando programas.
  • LRU (Least Recently Used): Algoritmo que reemplaza la página que no ha sido usada por el tiempo más largo.
  • OOM Killer (Out of Memory): Mecanismo del Kernel de Linux que termina procesos para liberar memoria cuando esta es críticamente baja.

1. Introducción a la Memoria Virtual

Pregunta fundamental: ¿Cómo ejecutar programas que requieren más memoria de la disponible físicamente?

El Problema de la Memoria Limitada

La memoria física (RAM) es un recurso limitado y costoso:

  • Los programas modernos requieren cada vez más memoria
  • Múltiples programas ejecutándose simultáneamente
  • La RAM física es finita y costosa
  • Sin memoria virtual, estaríamos limitados por la RAM instalada

La Solución: Memoria Virtual

Memoria Virtual es una técnica que crea una ilusión de memoria ilimitada:

  • Abstracción: Cada proceso cree que tiene toda la memoria para sí
  • Espacio de direcciones virtual: Independiente de la memoria física
  • Uso de disco: Parte del disco se usa como extensión de la RAM
  • Gestión automática: El SO mueve datos entre RAM y disco transparentemente

2. Memoria Física vs Virtual

Aspecto Memoria Física Memoria Virtual
También llamada RAM, memoria real Memoria lógica, espacio de direcciones
Ubicación Hardware (chips de RAM) Abstracción del SO (RAM + disco)
Tamaño Físico (ej: 8GB, 16GB) Lógico (ej: 2TB por proceso en x86-64)
Velocidad Muy rápida (nanosegundos) Variable (RAM rápida, disco lento)
Costo Alto por GB Bajo (usa espacio en disco)
Visibilidad Hardware, gestionada por MMU Visible para procesos

3. Paginación (Paging)

Paging es el mecanismo fundamental de la memoria virtual. Divide la memoria en unidades fijas llamadas páginas.

Conceptos Clave

Concepto Descripción Tamaño Típico
Página Virtual Unidad de memoria virtual 4 KB (también 2 MB, 1 GB para huge pages)
Marco de Página Unidad de memoria física 4 KB (igual que la página)
Tabla de Páginas Mapeo virtual → físico 1 entrada por página
MMU Memory Management Unit (hardware) Traduce direcciones en tiempo real

Proceso de Traducción de Direcciones

       │                              │
       ▼                              ▼
+----------------+           +------------------+
│ Tabla de       │           │  Desplazamiento  │
│ Páginas        │           │  se mantiene     │
│ (en RAM/TLB)   │           │  igual           │
└────────┬───────┘           └──────────────────┘
         │
         ▼
+------------------+
│  Número de       │
│  Marco de Página │
└────────┬─────────┘
         │
         ▼
┌─────────────────────────────────────────┐

├───────────────────┬─────────────────────┤

         └────────┬───────────┘

           Datos en RAM

Page Fault

Un page fault ocurre cuando el proceso accede a una página que no está en RAM:

  1. El proceso accede a una dirección virtual
  2. La MMU busca la página en la tabla de páginas
  3. La página está marcada como "no presente" (en disco)
  4. Se genera una excepción de page fault
  5. El SO maneja el fault:
    • Encuentra un marco de página libre en RAM
    • Si no hay libre, selecciona una víctima para expulsar
    • Carga la página desde disco a RAM
    • Actualiza la tabla de páginas
    • Reinicia la instrucción que falló
Costo de un page fault: Un page fault típico toma ~10-100 µs si la página está en RAM, pero ~10-20 ms si requiere acceso a disco. ¡Eso es 100-1000 veces más lento!

4. Swapping

Swapping es el proceso de mover páginas completas entre RAM y disco.

¿Cuándo Ocurre Swapping?

  • Memoria insuficiente: Cuando la RAM está casi llena
  • Page fault: Cuando se accede a una página en disco
  • Algoritmo de reemplazo: Cuando el SO necesita liberar marcos

Algoritmos de Reemplazo de Páginas

Algoritmo Descripción Uso Real
FIFO First In, First Out - Reemplaza la página más antigua Raramente usado (muy simple)
Óptimo Reemplaza la página que se usará más tarde Teórico, imposible de implementar
LRU Least Recently Used - Reemplaza la menos usada recientemente Común, aproximado en hardware
Clock Approximación de LRU con bit de referencia Muy usado en Linux

Swap Space en Linux

En Linux, el swap puede ser de dos tipos:

Partición de Swap

  • Partición dedicada en disco
  • Más eficiente
  • Se crea durante instalación
  • Tipo 82 en fdisk

Archivo de Swap

  • Archivo normal en filesystem
  • Fácil de agregar/redimensionar
  • Ligero overhead de filesystem
  • Usa dd y mkswap

Crear y Activar Swap en Linux

# Crear archivo de swap de 2GB
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Verificar
free -h
swapon --show

# Hacer permanente (agregar a /etc/fstab)
'/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

Swapping en Windows

Windows usa pagefile.sys para el swap:

  • Ubicación: C:\pagefile.sys (oculto)
  • Gestión: Panel de control → Sistema → Configuración avanzada
  • Administración automática por defecto
  • Se puede desactivar (no recomendado)

5. Thrashing

Thrashing es un estado degenerativo donde el SO gasta más tiempo paginando que ejecutando procesos.

Causas del Thrashing

  • Sobrecarga de memoria: Demasiados procesos para la RAM disponible
  • Falta de localidad: Los procesos no exhiben buena localidad de referencia
  • Ciclo vicioso: Page faults → Swap → Más page faults

Ciclo de Thrashing

+---------------------------------------------------------------+
|  CPU UTILIZACIÓN ↓                                              |
|    │                                                            |
|    ▼                                                            |
|  Procesos esperan page fault                                   |
|    │                                                            |
|    ▼                                                            |
|  Cola de procesos ready aumenta                                |
|    │                                                            |
|    ▼                                                            |
|  SO carga más procesos para mantener CPU ocupada                |
|    │                                                            |
|    ▼                                                            |
|  Menos marcos por proceso                                       |
|    │                                                            |
|    ▼                                                            |
|  Más page faults                                                |
|    │                                                            |
|    └─────────────────────────────────────┐                      |
|                                          ▼                      |
|                              (CICLO SE REPITE)                  |
+---------------------------------------------------------------+

Detectar Thrashing

Señales de thrashing:
  • Uso de CPU bajo pero alto uso de disco
  • Tasa de page faults muy alta
  • Responsividad del sistema muy pobre
  • Swap casi al máximo

Soluciones al Thrashing

Solución Descripción
Reducir multiprogramación Ejecutar menos procesos simultáneamente
Aumentar RAM Solución hardware más directa
Algoritmo de working set Mantener en RAM las páginas en uso reciente
Priority paging Dar prioridad a páginas del kernel

6. Monitoreo de Memoria

Monitoreo en Linux

Comando: free

# Mostrar uso de memoria en formato humano
free -h

# Salida ejemplo:
#               total        used        free      shared  buff/cache   available
# Mem:           7.7G        2.1G        3.2G        150M        2.4G        5.2G
# Swap:          2.0G          0B        2.0G

# Mostrar con actualización continua
free -h -s 2

# Ver en bytes (no human-readable)
free -b

Comando: vmstat

# Estadísticas de memoria virtual
vmstat 2 5

# Salida ejemplo:
# procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
#  r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
#  1  0      0 3200000 200000 2400000    0    0     5    10   50   30  5  2 92  1  0
#  0  1      0 3100000 210000 2500000    0    0   100     0  600 1200 10  5 85  0  0

# Campos clave:
# si - Swap in (KB/s desde disco)
# so - Swap out (KB/s a disco)
# wa - CPU time waiting for I/O

Comando: top / htop

# Ver uso de memoria por proceso
top

# Presiona 'M' para ordenar por uso de memoria
# Presiona 'P' para ordenar por CPU

# htop es más visual
htop

/proc/meminfo

# Información detallada de memoria
cat /proc/meminfo

# Campos útiles:
# MemTotal, MemFree, MemAvailable
# SwapTotal, SwapFree
# Dirty (páginas modificadas en RAM)
# Cached (páginas cached)

Monitoreo en Windows

Administrador de Tareas

  • Ver memoria por proceso
  • Ver uso total de RAM
  • Ver commit charge (uso de página)

Monitor de Rendimiento (perfmon)

# Contadores clave:
Memory\Available MBytes
Memory\Pages/sec
Memory\Page Faults/sec
Memory\Pool Paged Bytes
Paging File\% Usage

PowerShell

# Ver uso de memoria
Get-Process | Sort-Object WorkingSet -Descending | Select-Object -First 10

# Ver estadísticas de memoria
Get-WmiObject Win32_OperatingSystem | Select-Object TotalVisibleMemorySize, FreePhysicalMemory

# Ver pagefile
Get-WmiObject Win32_PageFileUsage

7. Comparación: Gestión de Memoria Linux vs Windows

Aspecto Linux Windows
Tamaño de página 4 KB (también huge pages de 2 MB, 1 GB) 4 KB (x86/x64), también large pages
Espacio de swap Partición o archivo, múltiples swap pagefile.sys, uno o más por volumen
Configuración /proc/sys, swapon, sysctl Registro, Panel de control
Caché de archivos Páginas cache (free + buff/cache) System Cache, Standby List
Overcommit Sí, configurable (/proc/sys/vm/overcommit_memory) No tan explícito, pero permite commit mayor que RAM
Herramientas free, vmstat, top, /proc Task Manager, perfmon, PowerShell
OOM Killer Sí, mata procesos si no hay memoria Similar, pero menos agresivo

Políticas de Caché

Linux

  • Usa RAM libre para caché
  • Buff/cache: archivos cacheados
  • Recupera fácilmente si un proceso necesita memoria
  • vm.swappiness controla agresividad de swap (0-100)

Windows

  • SuperFetch, ReadyBoost
  • Standby List: páginas no usadas recientemente
  • Modified List: páginas modificadas para escribir
  • Prioriza caché de aplicaciones sobre archivos

Ejercicio 2: Script de Alerta de Memoria

Objetivo: Crear un script que alerte cuando el uso de memoria supere un umbral

#!/bin/bash
# memory_alert.sh - Alerta cuando el uso de memoria es alto

UMBRAL=80  # Porcentaje
EMAIL="usuario@example.com"

while true; do
    # Obtener porcentaje de memoria usada
    MEM_USADA=$(free | grep Mem | awk '{printf("%.0f"), $3/$2 * 100.0}')
    MEM_TOTAL=$(free -h | grep Mem | awk '{print $2}')
    MEM_USADA_GB=$(free -h | grep Mem | awk '{print $3}')

    echo "[$(date)] Memoria usada: $MEM_USADA% ($MEM_USADA_GB de $MEM_TOTAL)"

    if [ $MEM_USADA -gt $UMBRAL ]; then
        echo "¡ALERTA! Uso de memoria alto: $MEM_USADA%"
        echo "Memoria usada: $MEM_USADA_GB de $MEM_TOTAL" |
            mail -s "Alerta de memoria: $MEM_USADA%" $EMAIL
    fi

    sleep 300  # Verificar cada 5 minutos
done

Uso del script:

# Dar permisos
chmod +x memory_alert.sh

# Ejecutar en background
nohup ./memory_alert.sh &
