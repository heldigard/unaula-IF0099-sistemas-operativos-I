1. El Proceso en el Ecosistema Windows

En Windows, un proceso es un **Objeto Ejecutivo** complejo gestionado por el Object Manager del Kernel NT. A diferencia de Linux, donde un proceso es "ligero" por diseño, en Windows tiene metadatos masivos desde su nacimiento.

1.1 Estructuras Críticas

  • EPROCESS: El bloque de control en el espacio de kernel (Ring 0). Contiene el PID, hilos asociados y el Access Token.
  • KPROCESS: Bloque de control utilizado por el microkernel para el scheduling de hilos.
  • PEB (Process Environment Block): Estructura en espacio de usuario que contiene la lista de DLLs cargadas y variables de entorno.

Windows Job Objects

Es un objeto que permite agrupar procesos para gestionarlos como una sola unidad. Permite poner límites de RAM o CPU a todo un grupo de procesos (ej: todos los hilos de un navegador).

2. Niveles de Inspección Profesional

Dependiendo de la gravedad del problema, un ingeniero utiliza diferentes herramientas:

Nivel 1: Administrador de Tareas

Uso rápido. Permite ver el PID, usuario y consumo básico. En la pestaña Detalles se pueden cambiar afinidades de CPU.

Nivel 2: Resource Monitor (resmon)

Muestra el impacto en tiempo real sobre el Disco (I/O) y la Red (puertos abiertos por cada app).

Nivel 3: Sysinternals Process Explorer

Es la herramienta estándar de oro para administradores. Sus capacidades únicas incluyen:

  • Handle Search: ¿Qué proceso tiene bloqueado mi archivo config.xml?
  • DLL View: Ver todas las librerías dinámicas que una aplicación está usando en memoria.
  • VirusTotal Integration: Envía el hash del proceso a la nube para verificar si es malware.

3. Automatización con PowerShell

La administración moderna de servidores Windows Server se realiza mediante PowerShell, que trata a los procesos como objetos .NET manipulables.

# 1. Ver procesos que consumen más de 1GB de RAM
Get-Process | Where-Object {$_.WorkingSet -gt 1GB}

# 2. Identificar procesos que no responden (Hung)
Get-Process | Where-Object {$_.Responding -eq $false}

# 3. Terminar todos los procesos de "Notepad" de forma forzada
Stop-Process -Name "notepad" -Force

# 4. Ver hilos de un proceso específico
(Get-Process chrome)[0].Threads | Select-Object Id, StartAddress, ThreadState

Analyze Wait Chain

En el Administrador de Tareas → Detalles → Clic derecho → Analyze Wait Chain. Te dice exactamente qué proceso está bloqueando a otro (Deadlock).

Laboratorio: Diagnóstico y Recuperación

Objetivo: Automatizar el control de un servicio corporativo en Windows.

Pasos a realizar:

  1. Abra PowerShell ISE o VS Code como Administrador.
  2. Scripting: Cree fix_service.ps1. El script debe:
    • Obtener el estado del servicio W32Time (Windows Time).

Entregable: Captura del script fix_service.ps1 funcionando y una captura de Process Explorer mostrando los hilos de su navegador web.

Casos Reales: Procesos Windows en Producción

Caso 1: Servidor con 100% CPU por svchost.exe

Escenario: Un Windows Server 2019 tiene la CPU al 100%. Al abrir el Administrador de Tareas, ves múltiples procesos svchost.exe consumiendo recursos.

Diagnóstico:

  1. Ejecuta Get-Process | Sort-Object CPU -Descending | Select-Object -First 10
  2. Identifica el PID exacto del proceso problemático
  3. Usa tasklist /SVC /FI "PID eq [NUMERO]" para ver qué servicio está dentro del svchost
  4. Reinicia solo ese servicio, no todo el servidor

Caso 2: Aplicación que No Responde y No se Puede Terminar

Escenario: Una aplicación (.exe) se quedó colgada y al intentar cerrarla con el Administrador de Tareas o Stop-Process, simplemente no termina.

Solución:

  1. Usa Get-Process -Name "nombreapp" -ErrorAction SilentlyContinue para obtener el PID
  2. Ejecuta taskkill /PID [NUMERO] /F /T con el flag /T para matar el árbol de procesos
  3. Si persiste, el proceso está en estado "D" (espera de disco) - reinicia el servidor

Caso 3: Conflicto de Puertos (Puerto 8080 en Uso)

Escenario: Intentas levantar un servicio web en el puerto 8080 pero dice que ya está en uso. Necesitas identificar qué proceso lo ocupa.

Solución:

# Encontrar qué proceso usa el puerto 8080
netstat -ano | findstr :8080

# Ver el proceso específico
Get-Process -Id [PID_ENCONTRADO]

# Si es un proceso legítimo, reconfigura tu servicio a otro puerto
# Si es un proceso_colgado, termínalo
Stop-Process -Id [PID] -Force

Ejercicio: Monitor de Procesos en Tiempo Real

Crea un script monitor_procesos.ps1 que:

  1. Monitoree cada 10 segundos los procesos que consumen más de 500MB de RAM
  2. Genere un archivo CSV con: Fecha, Hora, NombreProceso, PID, MemoriaMB
  3. Si un proceso supera 2GB, envíe un mensaje de alerta a consola
  4. Use Register-ScheduledTask para que el script se ejecute automáticamente cada hora

Actividad opcional: Script completo + 3 capturas del CSV generado.
