Objetivos de Aprendizaje

Resultado de Aprendizaje: Administra la memoria, los procesos de entrada y salida, el sistema de archivos, los mecanismos de protección y seguridad y las interfaces que ofrece el sistema operativo al usuario.

Al finalizar esta clase, serás capaz de:

  1. Comprender la estructura física de los discos duros
  2. Explicar el concepto de particiones y esquemas de particionado
  3. Diferenciar entre sistemas de archivos básicos
  4. Analizar el subsistema de E/S del SO
  5. Gestionar discos y particiones en Linux

Glosario de Almacenamiento

  • HDD / SSD: Hard Disk Drive (mecánico) / Solid State Drive (electrónico).
  • MBR / GPT: Esquemas de tabla de particiones (antiguo y moderno respectivamente).
  • E/S o I/O: Entrada y Salida de datos entre el sistema y el hardware.
  • DMA (Direct Memory Access): Acceso Directo a Memoria, permite al hardware transferir datos a la RAM sin usar el CPU.

1. Hardware de Discos

Estructura de un Disco Duro (HDD)

Componentes principales:
┌────────────────────────────────────────────┐
│  Platos: Discos magnéticos que giran       │
│  Velocidad típica: 5400-7200 RPM           │
├────────────────────────────────────────────┤
│  Cabezales: Lectura/escritura              │
│  Flotan sobre capa de aire (nanómetros)    │
├────────────────────────────────────────────┤
│  Brazo actuador: Posiciona cabezales       │
├────────────────────────────────────────────┤
│  Controladora: Gestiona operaciones        │
└────────────────────────────────────────────┘

Geometría lógica:
- Cilindros: Conjunto de pistas en mismo radio
- Cabezas: Una por superficie (2 por plato)
- Sectores: División angular (512 bytes o 4KB)
- Pista: Círculo concéntrico en una superficie

Tiempos de Acceso

Tipo de tiempoDescripciónValor típico
Seek timeMover cabezal al cilindro3-10 ms
LatencyGirar hasta el sector2-6 ms (media rotación)
TransferLeer datos100-200 MB/s
TotalSuma de anteriores8-15 ms
SSD (Solid State Drive):
  • Sin partes móviles (memoria flash)
  • Tiempo de acceso: ~0.1 ms (100x más rápido)
  • Velocidad: 500-7000 MB/s (NVMe)
  • Vida útil limitada por ciclos de escritura

2. Particiones

Las particiones dividen un disco en secciones independientes:

Esquemas de Particionado

EsquemaDescripciónLímites
MBRMaster Boot Record4 particiones primarias, 2TB máx
GPTGUID Partition Table128 particiones, 9.4 ZB máx

Tipos de Particiones MBR

MBR (512 bytes):
- 446 bytes: Boot loader (código de arranque)
- 64 bytes: Tabla de particiones (4 × 16 bytes)
- 2 bytes: Firma (0xAA55)

Tipos de partición:
├─ Partición Primaria (hasta 4)
│   └─ Contiene sistema de archivos directamente
├─ Partición Extendida (solo 1)
│   └─ Contiene particiones lógicas
└─ Particiones Lógicas
    └─ Dentro de extendida, ilimitadas en teoría

Ejemplo de layout:
┌─────────┬─────────┬────────────────────────────┐
│Primaria │Primaria │ Partición Extendida         │
│  /boot  │  swap   │ ┌────────┬────────┐        │
│  500MB  │  2GB    │ │Lógica 1│Lógica 2│ ...    │
│         │         │ │  /     │ /home  │        │
│         │         │ │  20GB  │  50GB  │        │
└─────────┴─────────┴─┴────────┴────────┴────────┘

Tipos de Sistemas de Archivos Linux

IDs comunes en MBR:
  • 0x83 - Linux native (ext2/3/4)
  • 0x82 - Linux swap
  • 0x8e - Linux LVM
  • 0x07 - NTFS/HPFS
  • 0x0b/0x0c - FAT32

3. Sistemas de Archivos Básicos

EXT4 (Extended File System 4)

CaracterísticaDescripción
Tamaño máximo archivo16 TB
Tamaño máximo volumen1 EB (exabyte)
Tamaño de bloque1KB - 64KB
CaracterísticasJournaling, extents, defragmentación online

Estructura Básica de un Sistema de Archivos

Layout típico de un FS:
┌───────────────┬───────────────┬─────────────────┬──────────────┐
│  Boot Block   │  Superblock   │  Metadata       │  Data Blocks │
│  (reservado)  │               │  (inodos, etc)  │              │
└───────────────┴───────────────┴─────────────────┴──────────────┘

Superblock contiene:
- Tamaño del sistema de archivos
- Número de bloques libres
- Tamaño de bloque
- Fecha de último montaje
- Estado (limpio/sucio)

4. Gestión de Entrada/Salida (E/S)

Subsistema de E/S del SO

El SO gestiona el acceso a dispositivos mediante:

  • Device Drivers: Controladores específicos de hardware
  • Buffering: Almacenamiento temporal de datos
  • Caching: Mantener copias en memoria para acceso rápido
  • Spooling: Cola de trabajos para dispositivos compartidos

Métodos de E/S

MétodoDescripciónEficiencia
ProgramadaCPU espera activaBaja
Por interrupciónDispositivo notifica a CPUMedia
DMATransferencia directa memoria-dispositivoAlta

DMA (Direct Memory Access)

Sin DMA:
CPU ──lee byte──> Dispositivo
CPU ──escribe──> Memoria
(repite para cada byte)

Con DMA:
CPU ──configura──> Controlador DMA
DMA ──transfiere──> Memoria ↔ Dispositivo
DMA ──interrumpe──> CPU (transferencia completa)

Beneficio: CPU libre durante transferencia
Scheduling de disco: El SO reordena peticiones de E/S para minimizar movimiento del cabezal:
  • FIFO: Orden de llegada
  • SSTF: Shortest Seek Time First
  • SCAN/Elevator: Va de extremo a extremo

5. Práctica en Linux

📋 Laboratorio Complementario

Para practicar la gestión de discos, particiones y sistemas de archivos, consulta el Laboratorio 5: Sistemas de Archivos Avanzados.

Comandos para gestión de discos:

# Listar discos y particiones
lsblk
fdisk -l

# Ver uso de disco
df -h

# Ver información detallada de particiones
sudo fdisk -l /dev/sda

# Crear particiones (interactivo)
sudo fdisk /dev/sdb

# Versión moderna con GPT
sudo gdisk /dev/sdb

# Formatear una partición
sudo mkfs.ext4 /dev/sdb1

# Ver información de filesystem
sudo dumpe2fs /dev/sda1 | head -20

# Ver estadísticas de E/S
iostat -x 1 5

# Ver procesos usando E/S
iotop

Ejercicios Prácticos de Almacenamiento:

Ejercicio 1: Benchmarking de Disco (Fase 3 Prep)

Objetivo: Medir la velocidad real de E/S en tu VM

  1. Instalar herramientas: sudo apt update && sudo apt install sysstat iotop -y
  2. Prueba de escritura (crear archivo de 1GB): dd if=/dev/zero of=/tmp/testfile bs=1G count=1 oflag=dsync
  3. Observa la velocidad reportada en MB/s. ¿Es HDD o SSD virtual?
  4. Prueba de lectura: dd if=/tmp/testfile of=/dev/null bs=1G count=1
  5. Compara ambas velocidades.

Ejercicio 2: Monitoreo en Tiempo Real

Objetivo: Detectar cuellos de botella de E/S

  1. Abre dos terminales.
  2. En T1 ejecuta: iostat -xz 1 (Fíjate en la columna %util)
  3. En T2 ejecuta una carga: find / -name "test*" 2>/dev/null
  4. Observa cómo sube el %util en T1. ¿Qué disco está trabajando?
  5. Ejecuta sudo iotop -o para ver qué proceso exacto está leyendo/escribiendo.

Ejercicio 3: Análisis de Sectores y Tamaño

Objetivo: Entender la geometría lógica

  1. Ejecuta sudo fdisk -l
  2. Busca la línea "Units: sectors of 1 * 512 = 512 bytes"
  3. Identifica el sector de inicio y fin de tu partición principal.
  4. Calcula: (Sector Fin - Sector Inicio) * 512 / 1024 / 1024 / 1024. ¿Coincide con los GB reportados?
