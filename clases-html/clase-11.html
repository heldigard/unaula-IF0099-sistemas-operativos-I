1. Introducción al Almacenamiento en Linux

Pregunta fundamental: ¿Cómo gestiona Linux el almacenamiento físico para proporcionar flexibilidad y escalabilidad?

El Desafío del Almacenamiento Tradicional

En el almacenamiento tradicional, las particiones son estáticas:

  • Una vez creadas, es difícil redimensionarlas
  • El espacio no utilizado en una partición no puede usarse en otra
  • Limitado a 4 particiones primarias (MBR)
  • Difícil agregar nuevo almacenamiento sin interrumpir el servicio

La Solución: LVM

LVM (Logical Volume Manager) abstrae el almacenamiento físico para proporcionar:

  • Flexibilidad: Redimensionar volúmenes en tiempo de ejecución
  • Agilidad: Agregar nuevos discos sin detener el sistema
  • Snapshots: Crear instantáneas de volúmenes para backups
  • Striping: Distribuir datos across múltiples discos para mejor rendimiento

2. MBR vs GPT

MBR (Master Boot Record)

El esquema de particionado tradicional:

Característica MBR
Tamaño máximo disco 2 TB
Máximo de particiones 4 primarias o 3 primarias + 1 extendida (con lógicas)
Ubicación Primer sector del disco (512 bytes)
Compatibilidad Universal (BIOS y UEFI con CSM)
Bootloader Almacena código de arranque 
+-------------------+
|  MBR (512 bytes)  |
| - Código de arranque (446 bytes) |
| - Tabla de particiones (64 bytes) |
| - Firma (2 bytes) |
+-------------------+
|  Partición 1      |
+-------------------+
|  Partición 2      |
+-------------------+
|  ...              |
+-------------------+

GPT (GUID Partition Table)

El esquema moderno de particionado:

Característica GPT
Tamaño máximo disco 18 EB (prácticamente ilimitado)
Máximo de particiones 128 (por defecto, expandible)
Ubicación Múltiples copias en el disco (redundancia)
Compatibilidad UEFI (requiere), BIOS con bootloader híbrido
Backup Copia de seguridad al final del disco

MBR

  • Discos ≤ 2TB
  • Máximo 4 particiones primarias
  • Compatible con BIOS
  • Universalmente soportado

GPT

  • Discos > 2TB
  • Hasta 128 particiones
  • Requiere UEFI
  • Tabla con redundancia
Recomendación actual: Usar GPT con UEFI para sistemas nuevos. MBR solo para compatibilidad con hardware antiguo o sistemas que requieran BIOS.

3. Sistema de Archivos ext4

ext4 (Fourth Extended Filesystem) es el sistema de archivos por defecto en la mayoría de distribuciones Linux.

Características Principales

Característica Descripción
Tamaño máximo archivo 16 TB
Tamaño máximo volumen 1 EB
Máximo de archivos ~4 mil millones (límite de 32-bit)
Journaling Sí, previene corrupción por fallos
Extents Asignación más eficiente de bloques
Delayed allocation Mejora rendimiento y fragmentación
Fast fsck Verificación de disco más rápida

Estructura de ext4

+-------------------+
|  Superbloque      |  Información del sistema de archivos
+-------------------+
|  Descriptores de Grupo |  Describen grupos de bloques
+-------------------+
|  Tabla de Inodos |  Metadatos de archivos
+-------------------+
|  Mapa de Bits     |  Bloques libres/inodos libres
+-------------------+
|  Bloques de Datos |  Contenido real de archivos
+-------------------+

Journaling

ext4 usa un journal (diario) para registrar transacciones antes de aplicarlas:

  1. Se escribe la transacción en el journal
  2. Se aplica la transacción al sistema de archivos
  3. Se marca la transacción como completada
Ventaja del journaling: Si ocurre un fallo de energía o crash, el sistema puede recuperar el estado consistente usando el journal.

4. Logical Volume Manager (LVM)

Arquitectura de LVM

LVM usa tres capas de abstracción:

+---------------------------------------------------------------+
|  Volúmenes Lógicos (LV)                                        |
|  /dev/vg00/root    /dev/vg00/home    /dev/vg01/data           |
+---------------------------------------------------------------+
|  Grupo de Volúmenes (VG)                                       |
|  vg00 (combina sda1, sdb1)         vg01 (combina sdc1)        |
+---------------------------------------------------------------+
|  Volúmenes Físicos (PV)                                        |
|  /dev/sda1         /dev/sdb1         /dev/sdc1                |
+---------------------------------------------------------------+
|  Discos Físicos                                                |
|  /dev/sda          /dev/sdb          /dev/sdc                 |
+---------------------------------------------------------------+

Componentes LVM

Componente Descripción Comandos
PV (Physical Volume) Partición o disco físico usado por LVM pvcreate, pvdisplay, pvs
VG (Volume Group) Pool de almacenamiento que combina PVs vgcreate, vgdisplay, vgs
LV (Logical Volume) Volumen lógico que se puede formatear y montar lvcreate, lvdisplay, lvs

Flujo de Trabajo Completo LVM

1. Crear Volúmenes Físicos (PV)

# Particionar disco nuevo (opcional - puedes usar el disco directamente)
fdisk /dev/sdb
# o
parted /dev/sdb

# Crear partición tipo LVM (código 8e para fdisk)
# Luego crear el volumen físico
pvcreate /dev/sdb1

# Ver información del PV
pvdisplay /dev/sdb1
pvs

2. Crear Grupo de Volúmenes (VG)

# Crear VG usando el PV
vgcreate vg_datos /dev/sdb1

# Agregar más PVs al VG (opcional)
vgextend vg_datos /dev/sdc1

# Ver información del VG
vgdisplay vg_datos
vgs

3. Crear Volúmenes Lógicos (LV)

# Crear LV de 10GB
lvcreate -L 10G -n lv_documentos vg_datos

# Crear LV usando todo el espacio disponible
lvcreate -l 100%FREE -n lv_backup vg_datos

# Ver información del LV
lvdisplay /dev/vg_datos/lv_documentos
lvs

4. Formatear y Montar

# Formatear con ext4
mkfs.ext4 /dev/vg_datos/lv_documentos

# Crear punto de montaje
mkdir /datos/documentos

# Montar temporalmente
mount /dev/vg_datos/lv_documentos /datos/documentos

# Verificar
df -h /datos/documentos

Redimensionamiento en VIVO

Ventaja clave de LVM: Puedes redimensionar volúmenes sin reiniciar el servicio.

Expandir un LV

# 1. Extender el LV (agregar 5GB)
lvextend -L +5G /dev/vg_datos/lv_documentos

# 2. Redimensionar el sistema de archivos
resize2fs /dev/vg_datos/lv_documentos

# En un solo paso:
lvextend -L +5G -r /dev/vg_datos/lv_documentos

Reducir un LV

Precaución: Reducir es más peligroso. Primero reduce el sistema de archivos, luego el LV. 
# 1. Desmontar
umount /datos/documentos

# 2. Verificar sistema de archivos
e2fsck -f /dev/vg_datos/lv_documentos

# 3. Reducir sistema de archivos a 8GB
resize2fs /dev/vg_datos/lv_documentos 8G

# 4. Reducir LV a 8GB
lvreduce -L 8G /dev/vg_datos/lv_documentos

# 5. Remontar
mount /dev/vg_datos/lv_documentos /datos/documentos

Snapshots de LVM

Los snapshots permiten capturar el estado de un LV en un momento dado:

# Crear snapshot de 2GB
lvcreate -L 2G -s -n lv_snap /dev/vg_datos/lv_documentos

# Montar el snapshot
mount /dev/vg_datos/lv_snap /mnt/snapshot

# Eliminar snapshot cuando ya no se necesite
lvremove /dev/vg_datos/lv_snap

5. RAID Básico

RAID (Redundant Array of Independent Disks) combina múltiples discos para mejorar rendimiento, redundancia o ambos.

Niveles RAID Comunes

Nivel Mínimo Discos Descripción Ventajas Desventajas
RAID 0 2 Striping (distribuye datos) Máximo rendimiento Sin redundancia
RAID 1 2 Mirroring (espejo) Redundancia completa 50% de capacidad
RAID 5 3 Striping + paridad distribuida Rendimiento + redundancia Escritura lenta en rebuild
RAID 10 4 RAID 1 + RAID 0 Rendimiento + redundancia 50% de capacidad

Comparación Visual

RAID 0 (Striping)

Dato 1 → Disco 1, Bloque 1
Dato 1 → Disco 2, Bloque 1
Dato 2 → Disco 1, Bloque 2
Dato 2 → Disco 2, Bloque 2

Capacidad: 100% (sumada)
Rendimiento: 2x en lectura/escritura
Redundancia: Ninguna

RAID 1 (Mirroring)

Dato 1 → Disco 1, Bloque 1
Dato 1 → Disco 2, Bloque 1 (copia)
Dato 2 → Disco 1, Bloque 2
Dato 2 → Disco 2, Bloque 2 (copia)

Capacidad: 50% (un disco)
Rendimiento: 2x lectura, 1x escritura
Redundancia: Completa
Importante: RAID NO es backup. Protege contra fallo de disco, no contra borrado accidental, corrupción de datos o desastres.

6. Archivo /etc/fstab

fstab (file system table) define cómo y dónde se montan los sistemas de archivos automáticamente durante el arranque.

Formato de /etc/fstab

# <file system> <mount point>   <type>  <options>       <dump>  <pass>
UUID=xxxx-xxxx    /               ext4    errors=remount-ro 0       1
UUID=yyyy-yyyy    /home           ext4    defaults          0       2
/dev/sdb1         /data           ext4    defaults          0       2
/swapfile         none            swap    sw                0       0

Campos Explicados

Campo Descripción Ejemplo
file system Dispositivo a montar /dev/sda1, UUID=xxx, /dev/vg00/root
mount point Directorio donde se monta /, /home, /data
type Tipo de sistema de archivos ext4, xfs, btrfs, swap
options Opciones de montaje defaults, ro, noauto
dump Backup con dump (0=no) 0, 1
pass Orden de fsck (0=omitir) 0, 1 (root), 2 (otros)

Opciones Comunes

Opción Descripción
defaults rw, suid, dev, exec, auto, nouser, async
ro Solo lectura (read-only)
rw Lectura-escritura (default)
auto Montar automáticamente en arranque
noauto No montar automáticamente
user Permitir montar por usuario normal
nosuid Ignorar bits SUID/SGID
nofail No fallar arranque si error

Cómo Obtener el UUID

# Método 1: blkid
sudo blkid /dev/sda1

# Método 2: lsblk
lsblk -f

# Método 3: udevadm
udevadm info --query=all --name=/dev/sda1 | grep UUID

Ejemplo Completo: Agregar LVM a fstab

# 1. Crear punto de montaje
sudo mkdir -p /datos/documentos

# 2. Obtener UUID (o usar ruta /dev/vg_datos/lv_documentos)
sudo blkid /dev/vg_datos/lv_documentos

# 3. Editar fstab
sudo nano /etc/fstab

# Agregar línea:
UUID=xxxx-xxxx  /datos/documentos  ext4  defaults  0  2

# 4. Verificar sintaxis
sudo mount -a

# 5. Verificar que está montado
df -h /datos/documentos
Siempre verificar con mount -a: Antes de reiniciar, ejecuta mount -a para detectar errores en fstab sin dejar el sistema inarrancable.

7. Actividad Práctica

Ejercicio 1: Agregar Disco a Máquina Virtual

Objetivo: Agregar un nuevo disco a tu VM y configurarlo con LVM

Paso 1: Agregar disco en VirtualBox/VMware

  • Apagar la VM
  • En configuración de VM, agregar nuevo disco duro (10GB)
  • Iniciar la VM

Paso 2: Verificar que el disco es visible

# Listar discos
lsblk

# Ver información detallada
sudo fdisk -l

Paso 3: Particionar con fdisk

# Iniciar fdisk en el nuevo disco (ej: /dev/sdb)
sudo fdisk /dev/sdb

# Comandos en fdisk:
# n - nueva partición
# p - primaria
# 1 - número de partición
# ENTER - usar primer sector por defecto
# ENTER - usar último sector por defecto (todo el disco)
# t - cambiar tipo
# 8e - tipo Linux LVM
# p - imprimir tabla
# w - escribir y salir

Paso 4: Crear volumen físico LVM

# Crear PV
sudo pvcreate /dev/sdb1

# Verificar
sudo pvdisplay

Paso 5: Crear grupo de volúmenes

# Crear VG
sudo vgcreate vg_practica /dev/sdb1

# Verificar
sudo vgdisplay vg_practica

Paso 6: Crear volumen lógico

# Crear LV de 5GB
sudo lvcreate -L 5G -n lv_datos vg_practica

# Verificar
sudo lvdisplay

Paso 7: Formatear y montar

# Formatear
sudo mkfs.ext4 /dev/vg_practica/lv_datos

# Crear punto de montaje
sudo mkdir /datos

# Montar temporalmente
sudo mount /dev/vg_practica/lv_datos /datos

# Verificar
df -h /datos

Paso 8: Montaje permanente en fstab

# Obtener UUID
sudo blkid /dev/vg_practica/lv_datos

# Editar fstab
sudo nano /etc/fstab

# Agregar línea:
UUID=tu-uuid-aqui  /datos  ext4  defaults  0  2

# Guardar y verificar
sudo mount -a
df -h /datos

# Crear archivo de prueba
echo "Prueba LVM" | sudo tee /datos/prueba.txt
cat /datos/prueba.txt

Ejercicio 2: Script de Automatización

Objetivo: Crear un script que automatice el proceso de configuración de LVM

#!/bin/bash
# script_lvm.sh - Automatiza configuración de LVM

set -e  # Detener si hay error

DISCO=$1
VG_NAME="vg_datos"
LV_NAME="lv_datos"
MOUNT_POINT="/datos"

# Verificar argumentos
if [ -z "$DISCO" ]; then
    echo "Uso: $0 <disco> (ej: /dev/sdb)"
    exit 1
fi

echo "Configurando LVM en $DISCO..."

# Crear partición LVM (automático con parted)
echo "Creando partición LVM..."
sudo parted -s $DISCO mklabel gpt
sudo parted -s $DISCO mkpart primary 0% 100%
sudo parted -s $DISCO set 1 lvm on

PARTICION="${DISCO}1"

# Crear volumen físico
echo "Creando volumen físico..."
sudo pvcreate $PARTICION

# Crear grupo de volúmenes
echo "Creando grupo de volúmenes..."
sudo vgcreate $VG_NAME $PARTICION

# Crear volumen lógico (todo el espacio)
echo "Creando volumen lógico..."
sudo lvcreate -l 100%FREE -n $LV_NAME $VG_NAME

# Formatear
echo "Formateando con ext4..."
sudo mkfs.ext4 /dev/${VG_NAME}/${LV_NAME}

# Crear punto de montaje
echo "Creando punto de montaje..."
sudo mkdir -p $MOUNT_POINT

# Montar
echo "Montando volumen..."
sudo mount /dev/${VG_NAME}/${LV_NAME} $MOUNT_POINT

# Agregar a fstab
UUID=$(sudo blkid -s UUID -o value /dev/${VG_NAME}/${LV_NAME})
if ! grep -q "$UUID" /etc/fstab; then
    echo "Agregando a fstab..."
    echo "UUID=$UUID $MOUNT_POINT ext4 defaults 0 2" | sudo tee -a /etc/fstab
fi

echo "¡Configuración completada!"
echo "Volumen montado en: $MOUNT_POINT"
df -h $MOUNT_POINT

Uso del script:

# Dar permisos
chmod +x script_lvm.sh

# Ejecutar (con el nuevo disco como argumento)
sudo ./script_lvm.sh /dev/sdb

Tiempo estimado: 60 minutos
