1. Componentes del Sistema Operativo

1.1 Kernel - El Núcleo del Sistema

El Kernel es el componente central del Sistema Operativo. Es el software que tiene control total sobre todo lo que sucede en el sistema.

¿Por qué se llama "Kernel"?

La palabra viene del alemán "Kern" que significa "núcleo" o "semilla". Así como una semilla contiene toda la información para que una planta crezca, el Kernel contiene todo lo necesario para que el sistema funcione.

Funciones del Kernel

  • Gestión de procesos: Crear, schedule y terminar procesos
  • Gestión de memoria: Asignar y liberar RAM
  • Gestión de E/S: Controlar dispositivos
  • Gestión de archivos: Organizar y acceder a datos
  • Seguridad: Proteger recursos y procesos

1.2 Shell - La Interfaz de Comandos

La Shell es un programa que permite interactuar con el Kernel. Es un intérprete de comandos que traduce lo que escribes en llamadas al sistema.

Sistema Shell Características
Linux bash, zsh, fish Scripting, pipes, redirección
Windows PowerShell, cmd Objetos, .NET integrado
macOS zsh (default), bash Unix-like, herramientas BSD

Analogía de la Shell

Usuario → Shell (traductor) → Kernel (ejecuta) → Hardware Sin Shell: Usuario ❌ No puede hablar con Kernel Con Shell: Usuario "abre archivo.txt" Shell traduce → open("archivo.txt") Kernel abre archivo → Hardware lee disco

1.3 System Calls - Llamadas al Sistema

Las System Calls son la puerta de entrada al Kernel. Son funciones que permiten a los programas solicitar servicios que requieren privilegios especiales.

Categorías de System Calls

Categoría Linux Windows Propósito
Control de procesos fork(), exec(), exit() CreateProcess, ExitProcess Crear/terminar procesos
Manipulación archivos open(), read(), write() CreateFile, ReadFile Operaciones I/O
Gestión memoria mmap(), brk() VirtualAlloc Asignar memoria
Comunicaciones socket(), bind(), listen() WSAStartup, socket Comunicación en red

1.4 Modo Usuario vs Modo Kernel

Los procesadores modernos tienen al menos dos modos de operación:

🔓 Modo Usuario

Donde corren las aplicaciones:

  • Acceso limitado a hardware
  • No puede ejecutar instrucciones privilegiadas
  • Acceso restringido a memoria
  • Navegadores, editores, juegos

🔒 Modo Kernel

Donde corre el Sistema Operativo:

  • Acceso completo al hardware
  • Puede ejecutar cualquier instrucción
  • Acceso a toda la memoria
  • Kernel, drivers de dispositivo

Transición entre Modos

┌─────────────────────────────────────────────────────┐ │ MODO USUARIO │ │ (Navegador, Word, Spotify, etc.) │ │ │ │ Usuario ejecuta: open("archivo.txt") │ │ ↓ │ │ ───────────────────────────────────── │ │ │ System Call (TRAP) │ │ ▼ │ │ ───────────────────────────────────── │ │ │ │ MODO KERNEL │ │ (Kernel verifica permisos y ejecuta) │ │ │ │ │ ▼ │ │ ───────────────────────────────────── │ │ │ Retorno al modo usuario │ │ ▼ │ │ Usuario continúa ejecución │ └─────────────────────────────────────────────────────┘

¿Por qué dos modos?

Si todos los programas corrieran en modo kernel, cualquier programa podría:

  • Leer tu contraseña de la memoria
  • Formatear tu disco duro
  • Interceptar tus pulsaciones de teclado
  • Causar que todo el sistema crashee

La separación de modos protege al sistema y a los usuarios.

1.5 Arquitectura en Capas

Un Sistema Operativo está organizado en capas jerárquicas:

Capa Descripción Ejemplos
Aplicaciones Programas de usuario Navegadores, editores, juegos
Librerías Funciones reutilizables libc, .NET Framework
Shell Intérprete de comandos bash, PowerShell
Kernel Núcleo del sistema Gestión procesos, memoria, E/S
Hardware Componentes físicos CPU, RAM, disco, red
