1. Componentes del Sistema Operativo

1.1 Kernel - El Núcleo del Sistema

El Kernel es el componente central del Sistema Operativo. Es el software que tiene control total sobre todo lo que sucede en el sistema.

¿Por qué se llama "Kernel"?

La palabra viene del alemán "Kern" que significa "núcleo" o "semilla". Así como una semilla contiene toda la información para que una planta crezca, el Kernel contiene todo lo necesario para que el sistema funcione.

Funciones del Kernel

  • Gestión de procesos: Crear, schedule y terminar procesos
  • Gestión de memoria: Asignar y liberar RAM
  • Gestión de E/S: Controlar dispositivos
  • Gestión de archivos: Organizar y acceder a datos
  • Seguridad: Proteger recursos y procesos

1.2 Shell - La Interfaz de Comandos

La Shell es un programa que permite interactuar con el Kernel. Es un intérprete de comandos que traduce lo que escribes en llamadas al sistema.

Sistema Shell Características
Linux bash, zsh, fish Scripting, pipes, redirección
Windows PowerShell, cmd Objetos, .NET integrado
macOS zsh (default), bash Unix-like, herramientas BSD

Analogía de la Shell

Usuario → Shell (traductor) → Kernel (ejecuta) → Hardware Sin Shell: Usuario ❌ No puede hablar con Kernel Con Shell: Usuario "abre archivo.txt" Shell traduce → open("archivo.txt") Kernel abre archivo → Hardware lee disco

1.3 System Calls - Llamadas al Sistema

Las System Calls son la puerta de entrada al Kernel. Son funciones que permiten a los programas solicitar servicios que requieren privilegios especiales.

Categorías de System Calls

Categoría Linux Windows Propósito
Control de procesos fork(), exec(), exit() CreateProcess, ExitProcess Crear/terminar procesos
Manipulación archivos open(), read(), write() CreateFile, ReadFile Operaciones I/O
Gestión memoria mmap(), brk() VirtualAlloc Asignar memoria
Comunicaciones socket(), bind(), listen() WSAStartup, socket Comunicación en red

1.4 Modo Usuario vs Modo Kernel

Los procesadores modernos tienen al menos dos modos de operación:

🔓 Modo Usuario

Donde corren las aplicaciones:

  • Acceso limitado a hardware
  • No puede ejecutar instrucciones privilegiadas
  • Acceso restringido a memoria
  • Navegadores, editores, juegos

🔒 Modo Kernel

Donde corre el Sistema Operativo:

  • Acceso completo al hardware
  • Puede ejecutar cualquier instrucción
  • Acceso a toda la memoria
  • Kernel, drivers de dispositivo

Transición entre Modos

┌─────────────────────────────────────────────────────┐ │ MODO USUARIO │ │ (Navegador, Word, Spotify, etc.) │ │ │ │ Usuario ejecuta: open("archivo.txt") │ │ ↓ │ │ ───────────────────────────────────── │ │ │ System Call (TRAP) │ │ ▼ │ │ ───────────────────────────────────── │ │ │ │ MODO KERNEL │ │ (Kernel verifica permisos y ejecuta) │ │ │ │ │ ▼ │ │ ───────────────────────────────────── │ │ │ Retorno al modo usuario │ │ ▼ │ │ Usuario continúa ejecución │ └─────────────────────────────────────────────────────┘

¿Por qué dos modos?

Si todos los programas corrieran en modo kernel, cualquier programa podría:

  • Leer tu contraseña de la memoria
  • Formatear tu disco duro
  • Interceptar tus pulsaciones de teclado
  • Causar que todo el sistema crashee

La separación de modos protege al sistema y a los usuarios.

1.5 Arquitectura en Capas

Un Sistema Operativo está organizado en capas jerárquicas:

Capa Descripción Ejemplos
Aplicaciones Programas de usuario Navegadores, editores, juegos
Librerías Funciones reutilizables libc, .NET Framework
Shell Intérprete de comandos bash, PowerShell
Kernel Núcleo del sistema Gestión procesos, memoria, E/S
Hardware Componentes físicos CPU, RAM, disco, red

1.6 Comandos Prácticos para Explorar el SO

En Linux (Ubuntu Server)

Terminal - Explorando el Sistema
# Ver información del kernel
uname -a

# Ver módulos del kernel cargados
lsmod

# Ver system calls disponibles
man syscalls

# Ver procesos en ejecución
ps aux

# Ver espacio de usuario vs kernel
strace ls 2>&1 | head -20

En Windows Server

PowerShell - Explorando el Sistema
# Ver información del sistema
Get-ComputerInfo | Select-Object OsName, WindowsVersion

# Ver procesos
Get-Process | Select-Object -First 10

# Ver servicios
Get-Service | Where-Object {$_.Status -eq "Running"} | Select-Object -First 10

💡 Tip

Estos comandos te permiten ver la estructura interna del SO en acción. Úsalos para completar tu entregable.

1.7 Laboratorio Práctico: Explorando el Sistema Operativo (20 min)

Objetivo: Ver en acción los componentes del SO que acabamos de aprender. No te preocupes si no entiendes todo de inmediato.
Antes de empezar: Solo necesitas una terminal Linux. Puedes usar tu VM, Webminal, o JSLinux. Todos los comandos son seguros de ejecutar.

Ejercicio 1: Conociendo al Kernel (5 min)

Vamos a ver qué kernel está corriendo tu sistema:

Terminal - Información del Kernel
# Ver información del kernel
uname -a

# Ver solo la versión
uname -r

# Ver el tipo de sistema
uname -m

# ¿Qué ves?
# Linux = El kernel
# 5.x.x = La versión
# x86_64 = Arquitectura de 64 bits
¿Qué significa esto?
Estos comandos preguntan al kernel "¿quién eres?" y "¿qué versión eres?". Es como revisar la placa de un carro para saber el modelo y año.

Ejercicio 2: Ver las System Calls en acción (5 min)

Vamos a espiar qué le pide un programa al kernel cuando corre:

Terminal - Rastreando System Calls
# Ejecutar strace (espía de system calls) con ls
# El comando "-c" cuenta cuántas veces se llamó cada función
strace -c ls /tmp

# Observa la tabla que aparece al final
# Las columnas son: 
# - % time = tiempo gastado en esa llamada
# - seconds = segundos totales
# - usecs/call = microsegundos por llamada
# - calls = número de veces que se llamó
# - syscall = nombre de la función
Analogía: Imagina que ls es un cliente en un restaurante y el kernel es la cocina. strace es como tener un micrófono que graba cada vez que el cliente pide algo al mesero. "Por favor, abra la puerta del refrigerador" (open), "Muéstrame el menú" (read), "Cierre la puerta" (close).

Ejercicio 3: Ver los módulos del kernel (5 min)

Linux carga "módulos" (drivers) según necesita. Vamos a verlos:

Terminal - Explorando Módulos
# Ver módulos cargados (solo los primeros 10 para no saturar)
lsmod | head -10

# Contar cuántos módulos hay en total
lsmod | wc -l

# Ver módulos relacionados con red (conexión internet)
lsmod | grep net | head -5

# Ver módulos de almacenamiento (discos duros)
lsmod | grep -E "scsi|sata|nvme" | head -5
¿Qué son estos módulos?
Son como "apps" que el kernel instala para hablar con el hardware. Por ejemplo, un módulo para tu tarjeta de red, otro para tu disco duro, otro para el sonido, etc. Linux tiene muchos módulos porque puede correr en muchos tipos diferentes de computadoras.

Ejercicio 4: Comparar comandos Linux vs Windows (5 min)

Si tienes acceso a una computadora Windows (tu máquina host, una tablet, o pregunta a un compañero), prueba esto:

Comparativa Sencilla
# === EN LINUX ===
uname -a              # Info del sistema
ls                    # Listar archivos
pwd                   # Ver directorio actual
cat /etc/os-release   # Ver distro Linux

# === EN WINDOWS (PowerShell) ===
systeminfo            # Info del sistema
dir                   # Listar archivos
cd                    # Ver directorio actual
Get-ComputerInfo | Select OsName  # Ver versión Windows
Observación: Aunque los comandos son diferentes, hacen lo mismo. Los dos sistemas tienen un kernel, shell, y system calls. La diferencia es cómo están organizados internamente y cómo los comandos se escriben.

Puedes usar tu máquina virtual de Ubuntu Server o cualquier terminal Linux disponible.

    • Si tienes acceso a Windows, compara 3 aspectos con Linux:
