Introducción a la Gestión de Procesos

En la Clase 03: Cambio de Contexto y Concurrencia vimos la teoría detrás de los procesos (PCB, estados, scheduling). Hoy pondremos esos conceptos en práctica usando la terminal de Linux.

Conceptos Clave para Recordar:

PID (Process ID)

Identificador único numérico asignado por el kernel a cada proceso en ejecución.

PPID (Parent PID)

PID del proceso que dio origen al proceso actual, creando una estructura de árbol.

Comando ps - Listar Procesos

ps muestra un snapshot de los procesos actuales

Linux maneja dos estándares históricos para los parámetros de los comandos:

  • BSD (Berkeley Software Distribution): Parámetros sin guión (ej. aux).
  • POSIX/UNIX: Parámetros con guión (ej. -ef).

Opciones más usadas:

ps aux (estilo BSD)

$ ps aux
USER   PID  %CPU %MEM  VSZ   RSS   TTY   STAT START  TIME COMMAND
root     1   0.0  0.1  168000 12000 ?     Ss   10:00  0:01 /sbin/init
user   1234  1.5  2.3  456000 234000 ?     Sl   10:05  5:23 /usr/bin/firefox
Columna Significado
USER Usuario dueño
PID Process ID
%CPU Uso de CPU
%MEM Uso de memoria
VSZ Memoria virtual (KB)
RSS Memoria física (KB)
STAT Estado

ps -ef (estilo POSIX)

$ ps -ef
UID    PID  PPID  C STIME TTY   TIME     CMD
root     1     0  0 10:00 ?     00:00:01 /sbin/init
user  1234  1000  1 10:05 ?     00:05:23 /usr/bin/firefox
Columna Significado
UID ID del usuario
PPID Parent PID
C %CPU (versión antigua)
STIME Hora de inicio
TIME Tiempo CPU acumulado

Filtrar procesos:

# Ver procesos de un usuario
ps -u username

# Ver proceso por PID
ps -p 1234

# Ver proceso por nombre
ps -C firefox

# Ver árbol de procesos
ps -ef --forest

kill y Señales

kill envía señales a procesos para controlar su comportamiento

Señales más comunes:

Señal Número Acción
SIGTERM 15 Terminación elegante (permite limpieza)
SIGKILL 9 Terminación inmediata (no se puede ignorar)
SIGHUP 1 Colgar (recargar configuración)
SIGINT 2 Interrupción (Ctrl+C)
SIGSTOP 19 Pausar proceso (no se puede ignorar)
SIGCONT 18 Continuar proceso pausado

Ejemplos de uso:

# Terminar proceso (SIGTERM por defecto)
kill 1234

# Forzar terminación
kill -9 1234

# Recargar configuración
kill -HUP $(pidof nginx)

# Pausar proceso
kill -STOP 1234

# Continuar proceso pausado
kill -CONT 1234
⚠️ Precaución con SIGKILL (-9):
  • No permite al proceso limpiar recursos
  • Puede dejar archivos temporales
  • Puede causar corrupción de datos
  • Usar SIGTERM (15) primero

Listar todas las señales:

$ kill -l
1) SIGHUP       2) SIGINT       3) SIGQUIT      4) SIGILL
5) SIGTRAP      6) SIGABRT      7) SIGBUS       8) SIGFPE
9) SIGKILL     10) SIGUSR1     11) SIGSEGV     12) SIGUSR2
13) SIGPIPE     14) SIGALRM     15) SIGTERM     ...

Prioridades y nice

Las prioridades de proceso determinan cuánto tiempo de CPU reciben

Valores nice:

  • Rango: -20 (más alta prioridad) a 19 (más baja)
  • Valor por defecto: 0
  • Solo root puede usar valores negativos
  • Valores altos = "ser nice" = ceder CPU a otros
Prioridad del Kernel
    ↑
 -20 │████████████████████ Alto privilegio (solo root)
     │
   0 │████████▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ Bajo privilegio
     │
  19 │                                        ▓▓▓▓▓▓▓
    └────────────────────────────────────────────→
    Mayor valor nice = Menor prioridad

Comandos de prioridad:

# Iniciar proceso con nice determinado
nice -n 10 comando        # Prioridad baja
nice -n -5 comando        # Prioridad alta (requiere root)

# Cambiar nice de proceso en ejecución
renice -n 5 -p 1234       # Cambiar a nice 5
renice +5 -p 1234        # Aumentar nice en 5

Ver prioridad y nice:

$ ps -eo pid,ni,pri,comm
  PID  NI  PRI COMMAND
    1   0   20 systemd
 1234  10   30 firefox
 5678  -5   15 jackd

6. systemd y systemctl

systemd es el sistema de inicialización y gestión de servicios en Linux moderno

Gestión de servicios con systemctl:

Comando Descripción
systemctl start servicio Iniciar servicio
systemctl stop servicio Detener servicio
systemctl status servicio Ver estado del servicio
systemctl enable servicio Habilitar al inicio

8. Práctica Guiada Híbrida

📋 Laboratorio Complementario

Para profundizar en la gestión de procesos con ejercicios prácticos y scripts avanzados, consulta el Laboratorio 3: Gestión de Procesos.

Actividad 1: Explorar procesos

Tiempo: 10 minutos

  1. Abre una terminal
  2. Ejecuta ps aux | less para ver todos los procesos
  3. Identifica el proceso con mayor uso de CPU
  4. Identifica el proceso con mayor uso de memoria
  5. Busca procesos zombie: ps aux | grep Z

Actividad 2: Monitoreo en tiempo real

Tiempo: 10 minutos

  1. Ejecuta top
  2. Observa los procesos que más CPU consumen
  3. Presiona M para ordenar por memoria
  4. Presiona P para volver a ordenar por CPU
  5. Abre otra terminal y ejecuta htop (si está instalado)

Actividad 3: Gestionar procesos

Tiempo: 15 minutos

  1. Inicia un proceso en segundo plano: sleep 300 &
  2. Obtén su PID: ps aux | grep sleep
  3. Cámbialo a estado stopped: kill -STOP [PID]
  4. Verifica que está en estado T: ps -p [PID] -o pid,stat,cmd
  5. Continúa el proceso: kill -CONT [PID]
  6. Termina el proceso: kill [PID]

Actividad 4: Gestión de servicios

Tiempo: 10 minutos

  1. Verifica si SSH está corriendo: systemctl status ssh
  2. Lista todos los servicios activos: systemctl list-units --type=service --state=running
  3. Verifica si un servicio está habilitado: systemctl is-enabled cron
  4. Reinicia un servicio (si tienes permisos): sudo systemctl restart cron

Actividad 5: Análisis de Procesos Zombie

Tiempo: 15 minutos

  1. Busca procesos en estado zombie: ps aux | grep 'Z'
  2. Identifica el PPID (padre) de los procesos zombie encontrados
  3. Verifica el árbol de procesos: pstree -p | grep -A2 -B2 [PPID]
  4. Documenta: ¿Cuántos zombies hay? ¿Quién es su padre?
  5. Investiga: Si el padre termina, ¿qué pasa con los zombies? (Pista: init/systemd)
Nota: Los procesos zombie son normales en sistemas Linux y no consumen recursos. Solo indican que el padre no ha llamado a wait() para leer el estado de salida del hijo.

Actividad 6: Jerarquía de Procesos con pstree

Tiempo: 15 minutos

  1. Visualiza todo el árbol de procesos: pstree -p
  2. Encuentra el proceso init/systemd (PID 1) y sus hijos directos
  3. Busca tu shell actual y traza su línea de ancestros hasta init
  4. Compara: ¿Cuántos niveles de profundidad hay desde init hasta tu terminal?
  5. Ejecuta: pstree -p | grep -E "(systemd|bash|ssh)" | head -20 y analiza

Actividad 7: Cambio de Prioridades (nice y renice)

Tiempo: 15 minutos

  1. Inicia un proceso con prioridad baja: nice -n 10 sleep 300 &
  2. Obtén su PID: pgrep sleep
  3. Verifica su valor nice: ps -o pid,ni,cmd -p [PID]
  4. Cambia la prioridad a más alta (como root): sudo renice -n -5 -p [PID]
  5. Verifica el cambio: ps -o pid,ni,cmd -p [PID]
  6. Explica: ¿Por qué no puedes poner nice negativo sin ser root?

Actividad 8: Script de Monitoreo Avanzado

Tiempo: 20 minutos

  1. Crea un script que monitoree un proceso específico por nombre
  2. El script debe aceptar el nombre del proceso como parámetro
  3. Debe mostrar: PID, uso de CPU, uso de memoria, tiempo de ejecución
  4. Debe verificar si el proceso existe antes de mostrar datos
  5. Bonus: Agregar opción para matar el proceso si supera cierto umbral de CPU
#!/bin/bash
# Ejemplo de estructura:
# ./monitor_proceso.sh firefox

PROCESO=$1

if [ -z "$PROCESO" ]; then
    echo "Uso: $0 "
    exit 1
fi

Ejercicio de Refuerzo: Script de Monitoreo

Objetivo: Crear un script que muestre información útil de tu sistema.

Actividad sugerida:

Intenta crear un script llamado mi_reporte.sh que:

  1. Muestre la fecha y hora actual
  2. Liste los 5 procesos que más CPU consumen
  3. Liste los 5 procesos que más memoria consumen
  4. Muestre la carga del sistema (comando uptime)
  5. Guarde todo en un archivo de texto

Código de ejemplo para empezar:

#!/bin/bash
# mi_reporte.sh
# Mi primer script de monitoreo

# Obtener fecha
fecha=$(date +"%Y-%m-%d %H:%M:%S")
echo "Reporte generado el: $fecha"

# Aquí puedes agregar más comandos...
# ps aux --sort=-%cpu | head -6
# ps aux --sort=-%mem | head -6
# uptime
Consejo: No te preocupes si no te sale todo de una vez. Empieza con algo simple (solo mostrar la fecha) y ve agregando paso a paso. La práctica es la clave.

Actividad 05: Monitoreo y Control

Tipo: Avance para Fase 2 (E2)
