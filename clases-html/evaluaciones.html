PASO 1: Script de Monitoreo en Linux (Bash)

Crear archivo: monitor_procesos.sh

El script DEBE hacer:

  1. Listar los 5 procesos que más RAM consumen usando ps aux --sort=-%mem | head -6

  5. Mostrar alerta si algún proceso usa más de 50% de CPU

PASO 2: Script de Servicios en Windows (PowerShell)

Crear archivo: gestionar_servicios.ps1

El script DEBE hacer:

  1. Verificar estado del servicio "Spooler" (cola de impresión):
    • Comando: Get-Service -Name Spooler
  2. Si está detenido (Stopped):
    • Intentar iniciarlo: Start-Service -Name Spooler
    • Mostrar mensaje: "ALERTA: Servicio Spooler iniciado automáticamente"
  3. Verificar servicios críticos adicionales:
    • Windows Update (wuauserv)
    • Firewall (MpsSvc)
    • Antivirus (Windows Defender)
  4. Generar reporte en C:\Reportes\servicios_estado.txt
PASO 3: Análisis de Estados de Procesos
  1. Ejecutar ps aux y encontrar ejemplos de cada estado:
    • R (Running): Proceso ejecutándose activamente
    • S (Sleeping): Proceso esperando evento (interrumpible)
    • Z (Zombie): Proceso hijo terminado pero no reclamado por padre
  2. Capturar pantalla mostrando al menos 3 procesos en cada estado
  3. Escribir explicación técnica de qué significa cada estado (1 párrafo cada uno)
PASO 4: Control de Prioridades (Laboratorio Híbrido)
  1. En Linux: Inicie un proceso en background (sleep 300 &) y use sudo renice 15 -p [PID] para bajar su prioridad. Verifique en htop la columna NI.
  2. En Windows: Use PowerShell para iniciar un proceso con prioridad baja: Start-Process notepad.exe -PriorityClass BelowNormal.
  3. Evidencia: Capturar el cambio de prioridad en el Task Manager (Windows) y en htop (Linux).
PASO 5: Documentar Bitácora de Pruebas

Crear PDF con:

  1. Código fuente completo de ambos scripts (con comentarios explicativos)
  2. Screenshots de ejecución de cada script
  3. Archivos de salida generados (bitacora_procesos.txt y servicios_estado.txt)
  4. Análisis de estados de procesos con evidencias
  5. Explicación del cambio de prioridades nice

🛠️ INSTRUCCIONES DETALLADAS - QUÉ DEBE HACER EL ESTUDIANTE

Objetivo: Asegurar el sistema implementando hardening, control de acceso y políticas de seguridad

PASO 1: Firewall y Reglas de Red

En Linux (UFW - Uncomplicated Firewall):

  1. Verificar estado: sudo ufw status
  2. Restablecer reglas: sudo ufw reset
  3. Política por defecto DENY: sudo ufw default deny incoming
  4. Permitir SSH: sudo ufw allow 22/tcp
  5. Permitir HTTP: sudo ufw allow 80/tcp
  6. Permitir HTTPS: sudo ufw allow 443/tcp
  7. Activar firewall: sudo ufw enable
  8. Verificar reglas: sudo ufw status verbose

En Windows (Firewall):

  1. Abrir PowerShell como Administrador
  2. Ver perfil activo: Get-NetFirewallProfile
  3. Bloquear todo entrante: Set-NetFirewallProfile -Profile Domain,Public,Private -DefaultInboundAction Block
  4. Permitir RDP si es necesario: New-NetFirewallRule -DisplayName "Allow RDP" -Direction Inbound -Protocol TCP -LocalPort 3389 -Action Allow
  5. Verificar reglas: Get-NetFirewallRule | Where-Object {$_.Enabled -eq 'True'}
PASO 2: Control de Acceso (ACLs) en Linux
  1. Crear estructura de directorios: 
    sudo mkdir -p /datos/compartido
sudo groupadd desarrolladores
sudo useradd -G desarrolladores dev1
sudo useradd -G desarrolladores dev2
  2. Configurar ACLs:
    • Dar permisos al grupo: sudo setfacl -m g:desarrolladores:rx /datos/compartido
    • Usuario específico solo lectura: sudo setfacl -m u:dev1:r /datos/compartido
    • Ver ACLs: getfacl /datos/compartido
  3. Probar accesos:
    • Iniciar sesión como dev1, intentar crear archivo (debe fallar)
    • Iniciar sesión como dev2, intentar crear archivo (debe funcionar)
  4. Capturar pantalla de getfacl mostrando las ACLs configuradas
PASO 3: Políticas de Seguridad Windows
  1. Abrir editor de políticas: secpol.msc (o gpedit.msc en versiones Pro)
  2. Navegar a: Configuración de seguridad → Directivas de cuenta → Directiva de contraseñas
  3. Configurar:
    • Edad máxima de contraseña: 30 días
    • Longitud mínima: 8 caracteres
    • Debe cumplir requisitos de complejidad: Habilitado
    • Historial de contraseñas: Recordar las últimas 5
  4. Capturar pantalla de cada configuración
  5. Verificar con PowerShell: net accounts
PASO 4: Matriz de Riesgos

Crear tabla con 8 vulnerabilidades identificadas:

# Vulnerabilidad Impacto Mitigación Técnica
1 Acceso root por SSH habilitado Alto Editar /etc/ssh/sshd_config → PermitRootLogin no
2 Sin snapshots de VM Medio Crear snapshot antes de cada evaluación

Agregar 6 vulnerabilidades más: password débil, servicios innecesarios corriendo, sin actualizaciones, puertos abiertos no necesarios, etc.

PASO 5: Script de Auditoría (Bonus)

Crear script que verifique automáticamente:

  • Estado del firewall (Linux: ufw status, Windows: Get-NetFirewallProfile)
  • Servicios críticos innecesarios corriendo

🛠️ INSTRUCCIONES DETALLADAS - QUÉ DEBE HACER EL ESTUDIANTE

Objetivo: Poner en producción un sistema web completo con Apache, IIS, almacenamiento persistente y monitoreo integrado

PASO 1: Configurar Apache con Virtual Host y HTTPS
  1. Instalar Apache: 
    sudo apt update
sudo apt install apache2 -y
sudo systemctl enable apache2
sudo systemctl start apache2
  2. Crear Virtual Host: 
    sudo mkdir -p /var/www/ucs/html
sudo chown -R $USER:$USER /var/www/ucs/html
sudo chmod -R 755 /var/www/ucs
  3. Crear archivo de configuración: 
    sudo nano /etc/apache2/sites-available/ucs.conf

# Contenido:
<VirtualHost *:80>
    ServerAdmin webmaster@localhost
    ServerName ucs.local
    DocumentRoot /var/www/ucs/html
    ErrorLog ${APACHE_LOG_DIR}/error.log
    CustomLog ${APACHE_LOG_DIR}/access.log combined
</VirtualHost>
  4. Activar sitio y reiniciar: 
    sudo a2ensite ucs.conf
sudo a2dissite 000-default.conf
sudo systemctl restart apache2
  5. Crear página index.html con nombres de integrantes
  6. Configurar HTTPS (certificado auto-firmado): 
    sudo a2enmod ssl
sudo mkdir /etc/apache2/ssl
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/apache2/ssl/apache.key \
  -out /etc/apache2/ssl/apache.crt
PASO 2: Configurar IIS en Windows
  1. Instalar rol IIS (como administrador): 
    Install-WindowsFeature -name Web-Server -IncludeManagementTools
  2. Crear sitio web en puerto 8080:
    • Abrir IIS Manager
    • Clic derecho en Sites → Add Website
    • Site name: UCS_Web
    • Physical path: C:\inetpub\wwwroot\ucs
    • Port: 8080
  3. Crear Application Pool dedicado:
    • Application Pools → Add Application Pool
    • Name: UCS_Pool
    • .NET CLR version: No Managed Code
    • Pipeline: Integrated
  4. Crear index.html con mismo contenido que en Linux
  5. Verificar acceso: http://localhost:8080
PASO 3: Almacenamiento Profesional Híbrido
  1. En Linux (Persistencia): Agregue un disco de 5GB, formatéelo y asegure el montaje automático editando /etc/fstab usando el UUID del dispositivo.
  2. En Windows (Redundancia): Use Espacios de Almacenamiento para crear una unidad lógica de 5GB con resistencia tipo "Reflejo" (Mirror) usando dos discos virtuales pequeños.
  3. Evidencia: Captura de df -h en Linux tras reinicio y captura del "Grupo de Almacenamiento" en Windows.
PASO 4: Dashboard de Integración

Crear script dashboard_salud.sh que verifique:

  1. Disponibilidad de servicios: 
    # Apache corriendo?
systemctl is-active apache2

# Puerto 80 accesible?
nc -zv localhost 80

# Puerto 443 accesible?
nc -zv localhost 443
  2. Espacio en disco: 
    df -h | grep -E '(/dev/sda|/dev/sdb)'
  3. Carga de CPU: 
    top -bn1 | grep "Cpu(s)" | awk '{print $2}' | awk -F% '{print $1}'
  4. Generar reporte consolidado en /tmp/reporte_salud.txt
