Glosario de Seguridad Windows

  • ACL: Access Control List (Lista de Control de Acceso).
  • ACE: Access Control Entry (Cada entrada individual en una ACL).
  • SID: Security Identifier (ID único para usuarios y grupos en Windows).
  • SMB: Server Message Block (Protocolo para compartir archivos en red).

1. Introducción a Permisos en Windows

Concepto fundamental: Windows Server utiliza un modelo de seguridad basado en ACLs (Access Control Lists) mucho más granular que el modelo UGO de Linux.

Modelo de Seguridad de Windows

  • ACLs: Listas de Control de Acceso
  • ACEs: Entradas de Control de Acceso (Access Control Entries)
  • SIDs: Security Identifiers (identificadores únicos)
  • Tokens de acceso: Contienen información de seguridad del usuario

Jerarquía de Permisos

  • Permisos NTFS: Controlan acceso local a archivos y carpetas
  • Permisos de Compartido (Share): Controlan acceso vía red
  • Permisos Combinados: Se aplica el más restrictivo de ambos

Permisos Avanzados

  • Traverse folder: Navegar carpetas

  • Delete: Borrar

Herencia de Permisos

Herencia: Por defecto, las subcarpetas y archivos heredan los permisos de la carpeta padre. Puedes desactivar la herencia para configurar permisos explícitos. 
# Ver permisos con PowerShell
Get-Acl C:\Carpeta | Format-List

# Ver permisos en formato tabla
Get-Acl C:\Carpeta | Select-Object -ExpandProperty Access

4. Gestión con PowerShell

Ver Permisos

# Ver ACL de una carpeta
Get-Acl C:\Datos\Proyectos

# Ver ACL en formato legible
Get-Acl C:\Datos\Proyectos | Format-List

# Exportar ACL a archivo
Get-Acl C:\Datos\Proyectos | Export-Clixml acl.xml

Configurar Permisos NTFS

# Variables
$carpeta = "C:\Datos\Proyectos"
$usuario = "DOMAIN\juanperez"

# Dar permisos de lectura
$acl = Get-Acl $carpeta
$accessRule = New-Object System.Security.AccessControl.FileSystemAccessRule(
    $usuario,
    "ReadAndExecute",
    "ContainerInherit,ObjectInherit",
    "None",
    "Allow"
)
$acl.SetAccessRule($accessRule)
Set-Acl $carpeta $acl

# Dar permisos completos
$fullControl = New-Object System.Security.AccessControl.FileSystemAccessRule(
    $usuario,
    "FullControl",
    "Allow"
)
$acl.SetAccessRule($fullControl)
Set-Acl $carpeta $acl

Script Completo de Configuración

# Script para configurar carpeta compartida
$carpeta = "C:\Compartido\Documentos"
$grupoLectura = "DOMAIN\Lectores"
$grupoEscritura = "DOMAIN\Editores"

# Crear carpeta si no existe
if (-not (Test-Path $carpeta)) {
    New-Item -ItemType Directory -Path $carpeta -Force
}

# Obtener ACL actual
$acl = Get-Acl $carpeta

# Deshabilitar herencia
$acl.SetAccessRuleProtection($true, $false)

# Agregar permisos de lectura
$ruleLectura = New-Object System.Security.AccessControl.FileSystemAccessRule(
    $grupoLectura,
    "ReadAndExecute",
    "ContainerInherit,ObjectInherit",
    "None",
    "Allow"
)
$acl.AddAccessRule($ruleLectura)

# Agregar permisos de escritura
$ruleEscritura = New-Object System.Security.AccessControl.FileSystemAccessRule(
    $grupoEscritura,
    "Modify",
    "ContainerInherit,ObjectInherit",
    "None",
    "Allow"
)
$acl.AddAccessRule($ruleEscritura)

# Aplicar ACL
Set-Acl $carpeta $acl

Write-Host "Permisos configurados correctamente"

Quitar Permisos

# Quitar permiso específico
$acl = Get-Acl C:\Datos\Proyectos
$usuario = "DOMAIN\usuario_antiguo"

# Buscar y eliminar regla
$ruleToRemove = $acl.Access | Where-Object {
    $_.IdentityReference.Value -eq $usuario
}

if ($ruleToRemove) {
    $acl.RemoveAccessRule($ruleToRemove)
    Set-Acl C:\Datos\Proyectos $acl
}

5. Compartir Archivos (SMB)

Diferencia: Permisos NTFS vs Share

Permisos NTFS

  • Se aplican localmente
  • Funcionan siempre
  • Más granulares
  • Se aplican primero

Permisos Share

  • Se aplican vía red
  • Solo para SMB/NFS
  • Menos granulares
  • Luego se combinan con NTFS
Regla: El acceso final es el MÁS RESTRICTIVO entre permisos NTFS y Share. Si NTFS es Read y Share es Full Control, el resultado es Read.

Crear Compartido SMB con PowerShell

# Crear carpeta
$carpeta = "C:\Compartido\Publico"
New-Item -ItemType Directory -Path $carpeta -Force

# Crear usuario para pruebas (opcional)
$Password = ConvertTo-SecureString "P@ssw0rd123" -AsPlainText -Force
New-LocalUser -Name "usuario1" -Password $Password -FullName "Usuario de Prueba"

# Compartir carpeta
New-SmbShare -Name "Publico" -Path $carpeta -FullAccess "Administradores","usuario1" -ReadAccess "Todos"

# Verificar el compartido
Get-SmbShare

Configurar Permisos de Compartido

# Ver permisos actuales del share
Get-SmbShareAccess -Name "Publico"

# Agregar usuario con permisos de lectura
Grant-SmbShareAccess -Name "Publico" -AccountName "DOMAIN\usuario" -AccessRight Read -Force

# Agregar usuario con permisos completos
Grant-SmbShareAccess -Name "Publico" -AccountName "DOMAIN\admin" -AccessRight Full -Force

# Quitar permiso
Revoke-SmbShareAccess -Name "Publico" -AccountName "DOMAIN\usuario_antiguo" -Force

Verificar desde Cliente Linux

# Instalar smbclient
sudo apt install smbclient

# Listar shares disponibles
smbclient -L //192.168.1.100 -U usuario1

# Acceder a un share
smbclient //192.168.1.100/Publico -U usuario1

# Comandos dentro de smbclient
smb: \> ls
smb: \> get archivo.txt
smb: \> put subida.txt
smb: \> exit

Montar Share en Linux

# Crear punto de montaje
sudo mkdir -p /mnt/compartido

# Montar temporalmente
sudo mount -t cifs //192.168.1.100/Publico /mnt/compartido \
    -o username=usuario1,password=P@ssw0rd123

# Montar permanentemente (en /etc/fstab)
//192.168.1.100/Publico /mnt/compartido cifs \
    username=usuario1,password=P@ssw0rd123,uid=1000,gid=1000 0 0

6. Usuarios y Grupos en Windows Server

Gestión de Usuarios con PowerShell

# Crear usuario local
$Password = ConvertTo-SecureString "P@ssw0rd123" -AsPlainText -Force
New-LocalUser -Name "juanperez" -Password $Password -FullName "Juan Perez" -Description "Usuario de Desarrollo"

# Ver todos los usuarios locales
Get-LocalUser

# Habilitar/deshabilitar usuario
Disable-LocalUser -Name "juanperez"
Enable-LocalUser -Name "juanperez"

# Eliminar usuario
Remove-LocalUser -Name "juanperez"

Gestión de Grupos

# Crear grupo local
New-LocalGroup -Name "Desarrollo" -Description "Equipo de Desarrollo"

# Ver todos los grupos
Get-LocalGroup

# Agregar usuario a grupo
Add-LocalGroupMember -Group "Desarrollo" -Member "juanperez"

# Ver miembros de un grupo
Get-LocalGroupMember -Group "Desarrollo"

# Quitar usuario de grupo
Remove-LocalGroupMember -Group "Desarrollo" -Member "juanperez"

Usuarios de Dominio (Active Directory)

# Crear usuario de dominio
New-ADUser -SamAccountName "maria.lopez" `
    -UserPrincipalName "maria.lopez@domain.local" `
    -Name "Maria Lopez" `
    -GivenName "Maria" `
    -Surname "Lopez" `
    -Enabled $true `
    -ChangePasswordAtLogon $true `
    -AccountPassword (ConvertTo-SecureString "P@ssw0rd123" -AsPlainText -Force)

# Agregar a grupo de dominio
Add-ADGroupMember -Identity "Domain Admins" -Members "maria.lopez"
Nota: Los comandos de Active Directory requieren el módulo RSAT-AD-PowerShell y privilegios de administrador de dominio.

7. Actividad Práctica

Ejercicio 1: Configurar Servidor de Archivos

Objetivo: Crear servidor de archivos con 3 usuarios y permisos diferenciados

Paso 1: Crear Estructura

# Crear directorios
New-Item -ItemType Directory -Path "C:\ServidorArchivos\Publico" -Force
New-Item -ItemType Directory -Path "C:\ServidorArchivos\Proyectos" -Force
New-Item -ItemType Directory -Path "C:\ServidorArchivos\Confidencial" -Force

Paso 2: Crear Usuarios

# Crear usuarios
$pass1 = ConvertTo-SecureString "User1Pass" -AsPlainText -Force
$pass2 = ConvertTo-SecureString "User2Pass" -AsPlainText -Force
$pass3 = ConvertTo-SecureString "User3Pass" -AsPlainText -Force

New-LocalUser -Name "usuario1" -Password $pass1 -FullName "Usuario 1"
New-LocalUser -Name "usuario2" -Password $pass2 -FullName "Usuario 2"
New-LocalUser -Name "usuario3" -Password $pass3 -FullName "Usuario 3"

Paso 3: Configurar Permisos NTFS

# Público: todos pueden leer y escribir
$aclPublico = Get-Acl "C:\ServidorArchivos\Publico"
$ruleTodos = New-Object System.Security.AccessControl.FileSystemAccessRule(
    "Todos","Modify","ContainerInherit,ObjectInherit","None","Allow"
)
$aclPublico.AddAccessRule($ruleTodos)
Set-Acl "C:\ServidorArchivos\Publico" $aclPublico

# Proyectos: usuario1 y usuario2 pueden editar
$aclProyectos = Get-Acl "C:\ServidorArchivos\Proyectos"
$aclProyectos.SetAccessRuleProtection($true,$false)

$ruleUser1 = New-Object System.Security.AccessControl.FileSystemAccessRule(
    "usuario1","Modify","ContainerInherit,ObjectInherit","None","Allow"
)
$aclProyectos.AddAccessRule($ruleUser1)

$ruleUser2 = New-Object System.Security.AccessControl.FileSystemAccessRule(
    "usuario2","Modify","ContainerInherit,ObjectInherit","None","Allow"
)
$aclProyectos.AddAccessRule($ruleUser2)

Set-Acl "C:\ServidorArchivos\Proyectos" $aclProyectos

Paso 4: Crear Compartidos SMB

# Crear shares
New-SmbShare -Name "Publico" -Path "C:\ServidorArchivos\Publico" -FullAccess "Administradores" -ReadAccess "Todos"
New-SmbShare -Name "Proyectos" -Path "C:\ServidorArchivos\Proyectos" -FullAccess "usuario1","usuario2"
New-SmbShare -Name "Confidencial" -Path "C:\ServidorArchivos\Confidencial" -FullAccess "Administradores"

Ejercicio 2: Verificar desde Cliente

Objetivo: Conectarse desde Linux y verificar permisos

# Desde cliente Linux
# Listar shares
smbclient -L //IP_DEL_SERVIDOR -U usuario1

# Acceder a share público
smbclient //IP_DEL_SERVIDOR/Publico -U usuario1
smb: \> ls
smb: \> put prueba.txt

# Intentar acceder a confidencial (debería fallar)
smbclient //IP_DEL_SERVIDOR/Confidencial -U usuario1

Tiempo estimado: 60 minutos

8. Entregable

Servidor de Archivos Configurado

Requisitos:

  1. Servidor Windows Server con:
    • 3 usuarios de prueba creados
    • 3 grupos: Lectores, Editores, Administradores
    • Estructura de directorios compartidos
  2. Permisos configurados:
    • carpeta Pública: todos pueden leer/escribir
