1. El Modelo de Seguridad NTFS

Windows trata a cada archivo como un **Objeto**. Cada objeto tiene un Descriptor de Seguridad que contiene una DACL (Lista de Control de Acceso Discrecional).

Permisos NTFS

Se aplican localmente. Son muy granulares (ej: permiso de "Sincronizar" o "Escribir Atributos").

Permisos Share

Solo se aplican vía red. Regla: El permiso final es el MÁS RESTRICTIVO de los dos.

Herencia de Permisos

Por defecto, un archivo "hereda" los permisos de su carpeta padre. Para crear una carpeta privada, debes **Romper la Herencia** y eliminar al grupo "Users" de la lista.

2. Directivas de Seguridad Local (secpol.msc)

Aquí es donde blindamos el sistema operativo a nivel global. Definimos el "comportamiento" del servidor.

  • Políticas de Cuenta: Longitud de clave, complejidad, historial.
  • Bloqueo de Cuenta: Bloquear al usuario tras 3 intentos fallidos por 15 minutos.
  • Asignación de Derechos: ¿Quién puede apagar el servidor? ¿Quién puede cambiar la hora?

3. UAC (User Account Control): El Guardián de Windows

UAC es el mecanismo de seguridad que pide confirmación antes de realizar acciones privilegiadas. Es la versión Windows de "mínimo privilegio".

¿Cómo funciona UAC?

Cuando un proceso necesita privilegios de administrador:

  1. Windows crea un Token de Filtrado sin privilegios elevados.
  2. Si la aplicación pide admin, UAC muestra una promesa de consentimiento.
  3. Si el usuario aprueba, el proceso obtiene un Token Elevado.
# Ver estado de UAC
Get-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" | Select-Object EnableLUA

# Ver nivel de notificación UAC
# (1=Always, 2=WhenAppsTry, 3=SameDesktop, 4=Silent)
(Get-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System").ConsentPromptBehaviorAdmin

UAC en el Entorno Corporativo

En un dominio (Active Directory), UAC se configura vía GPO:

  • Admin Approval Mode: Requiere aprobación para roles admin.
  • Elevation Prompt: Comportamiento de la ventana.
  • Secure Desktop: Pantalla oscurecida durante el consentimiento.

Consejo Profesional

NUNCA deshabilites UAC en servidores. Si lo делаешь, cualquier malware tendrá permisos totales instantáneamente.

4. Auditoría y Visor de Eventos

La seguridad profesional requiere rastro. Windows puede grabar en el **Visor de Eventos** (Log de Seguridad) cada vez que alguien abre un archivo sensible.

Evento 4625: El Delator

Este ID de evento indica un "Fallo de inicio de sesión". Si ves miles de estos en un minuto, tu servidor está bajo un ataque de fuerza bruta por RDP o SMB.

5. Comandos de Auditoría y Hardening

Gestión de Permisos (icacls)

# Ver permisos de una carpeta
icacls C:\www\ucs

# Dar permiso de lectura solo a un usuario
icacls C:\data /grant:r "estudiante":(R)

# Quitar todos los permisos heredados
icacls C:\private /inheritance:d

Red y Auditoría (PS/CMD)

# Ver puertos abiertos y procesos
netstat -abno | findstr LISTENING

# Ver políticas de auditoría activas
auditpol /get /category:*

# Ver reglas del Firewall de Windows
Get-NetFirewallRule -Enabled True | 
Select-Object DisplayName, Action

Casos Reales: Seguridad Windows en Producción

Caso 1: Permisos NTFS Conflictivos

Escenario: Un usuario no puede acceder a una carpeta compartida aunque está en el grupo correcto. Otros usuarios con mismos permisos sí pueden.

Diagnóstico:

# Ver permisos efectivos de un usuario específico
    icacls C:\carpeta_compartida /findsid "dominio\usuario"

    # Ver permisos efectivos reales
    icacls C:\carpeta /t /c /q

Caso 2: Cuenta Bloqueada por Política

Escenario: El administrador no puede iniciar sesión. La cuenta está bloqueada tras múltiples intentos fallidos.

Solución:

# Desbloquear cuenta desde otra sesión admin
    net user administrador /domain /unlock

    # O desde ADUC (Active Directory Users and Computers)

Caso 3: Auditoría No Registra Eventos

Escenario: Se configuró auditoría de acceso a archivos pero el Log de Seguridad no muestra eventos.

Causa: La auditoría solo se activa si el objeto tiene habilitado el auditing en sus SACL.

Solución:

# Habilitar auditoría en el objeto
    auditpol /set /subcategory:"File System" /success:enable /failure:enable

    # Ver configuración actual
    auditpol /get /category:*
