1. El Modelo de Seguridad NTFS

Windows trata a cada archivo como un **Objeto**. Cada objeto tiene un Descriptor de Seguridad que contiene una DACL (Lista de Control de Acceso Discrecional).

Permisos NTFS

Se aplican localmente. Son muy granulares (ej: permiso de "Sincronizar" o "Escribir Atributos").

Permisos Share

Solo se aplican vía red. Regla: El permiso final es el MÁS RESTRICTIVO de los dos.

Herencia de Permisos

Por defecto, un archivo "hereda" los permisos de su carpeta padre. Para crear una carpeta privada, debes **Romper la Herencia** y eliminar al grupo "Users" de la lista.

2. Directivas de Seguridad Local (secpol.msc)

Aquí es donde blindamos el sistema operativo a nivel global. Definimos el "comportamiento" del servidor.

  • Políticas de Cuenta: Longitud de clave, complejidad, historial.
  • Bloqueo de Cuenta: Bloquear al usuario tras 3 intentos fallidos por 15 minutos.
  • Asignación de Derechos: ¿Quién puede apagar el servidor? ¿Quién puede cambiar la hora?

3. UAC (User Account Control): El Guardián de Windows

UAC es el mecanismo de seguridad que pide confirmación antes de realizar acciones privilegiadas. Es la versión Windows de "mínimo privilegio".

¿Cómo funciona UAC?

Cuando un proceso necesita privilegios de administrador:

  1. Windows crea un Token de Filtrado sin privilegios elevados.
  2. Si la aplicación pide admin, UAC muestra una promesa de consentimiento.
  3. Si el usuario aprueba, el proceso obtiene un Token Elevado.
# Ver estado de UAC
Get-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" | Select-Object EnableLUA

# Ver nivel de notificación UAC
# (1=Always, 2=WhenAppsTry, 3=SameDesktop, 4=Silent)
(Get-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System").ConsentPromptBehaviorAdmin

UAC en el Entorno Corporativo

En un dominio (Active Directory), UAC se configura vía GPO:

  • Admin Approval Mode: Requiere aprobación para roles admin.
  • Elevation Prompt: Comportamiento de la ventana.
  • Secure Desktop: Pantalla oscurecida durante el consentimiento.

Consejo Profesional

NUNCA deshabilites UAC en servidores. Si lo делаешь, cualquier malware tendrá permisos totales instantáneamente.

4. Auditoría y Visor de Eventos

La seguridad profesional requiere rastro. Windows puede grabar en el **Visor de Eventos** (Log de Seguridad) cada vez que alguien abre un archivo sensible.

Evento 4625: El Delator

Este ID de evento indica un "Fallo de inicio de sesión". Si ves miles de estos en un minuto, tu servidor está bajo un ataque de fuerza bruta por RDP o SMB.

5. Comandos de Auditoría y Hardening

Gestión de Permisos (icacls)

# Ver permisos de una carpeta
icacls C:\www\ucs

# Dar permiso de lectura solo a un usuario
icacls C:\data /grant:r "estudiante":(R)

# Quitar todos los permisos heredados
icacls C:\private /inheritance:d

Red y Auditoría (PS/CMD)

# Ver puertos abiertos y procesos
netstat -abno | findstr LISTENING

# Ver políticas de auditoría activas
auditpol /get /category:*

# Ver reglas del Firewall de Windows
Get-NetFirewallRule -Enabled True | 
Select-Object DisplayName, Action

Casos Reales: Seguridad Windows en Producción

Caso 1: Permisos NTFS Conflictivos

Escenario: Un usuario no puede acceder a una carpeta compartida aunque está en el grupo correcto. Otros usuarios con mismos permisos sí pueden.

Diagnóstico:

# Ver permisos efectivos de un usuario específico
    icacls C:\carpeta_compartida /findsid "dominio\usuario"

    # Ver permisos efectivos reales
    icacls C:\carpeta /t /c /q

Caso 2: Cuenta Bloqueada por Política

Escenario: El administrador no puede iniciar sesión. La cuenta está bloqueada tras múltiples intentos fallidos.

Solución:

# Desbloquear cuenta desde otra sesión admin
    net user administrador /domain /unlock

    # O desde ADUC (Active Directory Users and Computers)

Caso 3: Auditoría No Registra Eventos

Escenario: Se configuró auditoría de acceso a archivos pero el Log de Seguridad no muestra eventos.

Causa: La auditoría solo se activa si el objeto tiene habilitado el auditing en sus SACL.

Solución:

# Habilitar auditoría en el objeto
    auditpol /set /subcategory:"File System" /success:enable /failure:enable

    # Ver configuración actual
    auditpol /get /category:*

🛠️ Práctica Laboral

Checklist de Hardening: Windows Server CIS Benchmarks Simplificado

Aplica estos controles básicos de seguridad en entornos corporativos:

  • Políticas de contraseñas: Mínimo 12 caracteres, complejidad habilitada, historial de 12 contraseñas.
  • Bloqueo de cuentas: 5 intentos fallidos, bloqueo de 30 minutos, restablecimiento automático.
  • UAC: Configurar en nivel máximo - "Notificar siempre".
  • Windows Defender: Habilitar protección en tiempo real y escaneos programados.
  • Firewall: Perfil de dominio activo, bloquear conexiones entrantes no solicitadas.
  • Auditoría: Habilitar logs para eventos de inicio de sesión, cambios de privilegios y acceso a archivos sensibles.

Herramientas: Microsoft Baseline Security Analyzer

Microsoft ofrece herramientas nativas para evaluar la seguridad del sistema:

# Microsoft Baseline Security Analyzer (MBSA) - Reemplazado por
# Security Compliance Toolkit actualmente

# Verificar configuraciones de seguridad con PowerShell
Get-ChildItem -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies" -Recurse | 
    Where-Object { $_.Property -eq "EnableLUA" }

# Auditar directivas de seguridad locales
secedit /export /cfg C:\security_audit.txt
Get-Content C:\security_audit.txt | Select-String -Pattern "Password|Lockout|Audit"

Security Compliance Toolkit: Descarga plantillas de seguridad pre-configuradas de Microsoft para Windows Server 2022.

Casos Reales: Análisis de Vulnerabilidades Críticas de Windows

Caso 1: EternalBlue (MS17-010)

  • Vulnerabilidad en SMBv1 explotada por WannaCry (2017).
  • Mitigación: Deshabilitar SMBv1, aplicar parches KB4013389.

Caso 2: PrintNightmare (CVE-2021-34527)

  • Escalación de privilegios a través del servicio de impresión.
  • Mitigación: Deshabilitar servicio Print Spooler si no es necesario.

Caso 3: Zerologon (CVE-2020-1472)

  • Ataque al protocolo Netlogon en controladores de dominio.
  • Mitigación: Aplicar KB4565349, habilitar modo de aplicación.

Laboratorio: Script de Auditoría de Seguridad en PowerShell

# Script: SecurityAudit.ps1 - Auditoría completa de seguridad
# Autor: [Tu nombre]
# Fecha: $(Get-Date)

# Crear carpeta de resultados
$AuditPath = "C:\SecurityAudit_$(Get-Date -Format 'yyyyMMdd')"
New-Item -ItemType Directory -Path $AuditPath -Force

# 1. Verificar usuarios con contraseñas que nunca expiran
Write-Host "=== Usuarios con contraseñas que nunca expiran ===" -ForegroundColor Yellow
$NeverExpires = Get-LocalUser | Where-Object { $_.PasswordNeverExpires -eq $true -and $_.Enabled -eq $true }
$NeverExpires | Select-Object Name, LastLogonDate | Export-Csv "$AuditPath\PasswordNeverExpires.csv" -NoTypeInformation
$NeverExpires | Format-Table Name, LastLogonDate

# 2. Verificar intentos de inicio de sesión fallidos
Write-Host "=== Eventos de inicio de sesión fallidos (últimas 24h) ===" -ForegroundColor Yellow
Get-WinEvent -FilterHashtable @{LogName='Security'; ID=4625; StartTime=(Get-Date).AddDays(-1)} -ErrorAction SilentlyContinue |
    Select-Object TimeCreated, Message | Export-Csv "$AuditPath\FailedLogins.csv" -NoTypeInformation

# 3. Verificar puertos abiertos y procesos asociados
Write-Host "=== Puertos abiertos y procesos ===" -ForegroundColor Yellow
Get-NetTCPConnection -State Listen | 
    Select-Object LocalAddress, LocalPort, @{Name="ProcessName";Expression={(Get-Process -Id $_.OwningProcess).ProcessName}} |
    Export-Csv "$AuditPath\OpenPorts.csv" -NoTypeInformation

# 4. Verificar servicios innecesarios en ejecución
Write-Host "=== Servicios potencialmente innecesarios ===" -ForegroundColor Yellow
$RiskyServices = @("Telnet", "FTP", "SMB1", "RemoteRegistry")
Get-Service | Where-Object { $RiskyServices -contains $_.Name -and $_.Status -eq "Running" } |
    Export-Csv "$AuditPath\RiskyServices.csv" -NoTypeInformation

# 5. Verificar Firewall habilitado
Write-Host "=== Estado del Firewall ===" -ForegroundColor Yellow
Get-NetFirewallProfile | Select-Object Name, Enabled | Export-Csv "$AuditPath\FirewallStatus.csv" -NoTypeInformation

Write-Host "`n✅ Auditoría completada. Resultados guardados en: $AuditPath" -ForegroundColor Green

Laboratorio Práctico: Firewall con Reglas Complejas

# Configurar reglas de firewall avanzadas con PowerShell

# 1. Bloquear todo el tráfico entrante por defecto
New-NetFirewallRule -DisplayName "Block_All_Inbound" -Direction Inbound -Action Block -Profile Any

# 2. Permitir solo conexiones SSH desde subnet específica
New-NetFirewallRule -DisplayName "Allow_SSH_Subnet" -Direction Inbound -Protocol TCP -LocalPort 22 -RemoteAddress "192.168.1.0/24" -Action Allow

# 3. Permitir HTTP/HTTPS desde cualquier origen
New-NetFirewallRule -DisplayName "Allow_HTTP" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow
New-NetFirewallRule -DisplayName "Allow_HTTPS" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow

# 4. Bloquear RDP desde internet, permitir solo desde LAN
New-NetFirewallRule -DisplayName "Block_RDP_Internet" -Direction Inbound -Protocol TCP -LocalPort 3389 -RemoteAddress Internet -Action Block
New-NetFirewallRule -DisplayName "Allow_RDP_LAN" -Direction Inbound -Protocol TCP -LocalPort 3389 -RemoteAddress LocalSubnet -Action Allow

# 5. Regla para SMB solo en red privada
New-NetFirewallRule -DisplayName "Allow_SMB_Private" -Direction Inbound -Protocol TCP -LocalPort 445 -Profile Private -Action Allow

# Verificar reglas aplicadas
Get-NetFirewallRule -Enabled True | Select-Object DisplayName, Direction, Action | Format-Table -AutoSize
