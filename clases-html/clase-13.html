Objetivos de Aprendizaje

Al finalizar esta clase, serás capaz de:

  1. Comprender la estructura interna de un sistema de archivos
  2. Explicar el mecanismo de journaling y recuperación
  3. Gestionar el montaje y desmontaje de sistemas de archivos
  4. Diferenciar los niveles de RAID básicos
  5. Implementar configuraciones de almacenamiento

Glosario de Implementación

  • UUID (Universally Unique Identifier): Identificador único universal para dispositivos y particiones.
  • fstab (File System Table): Archivo de configuración que define cómo se montan los dispositivos al arrancar.
  • RAID: Matriz redundante de discos independientes, técnica para mejorar velocidad o seguridad.
  • Mount Point (Punto de Montaje): Directorio donde se "engancha" el contenido de un disco externo o partición.

1. Estructura Interna de un Sistema de Archivos

Layout General

Disco particionado con sistema de archivos:

┌─────────────────────────────────────────────────────────────┐
│  Sector 0: Boot Block (reservado para arranque)            │
├─────────────────────────────────────────────────────────────┤
│  Superblock: Metadatos del sistema de archivos             │
│  - Tamaño del FS, bloques libres, inodos libres            │
│  - Tamaño de bloque, versión, UUID                         │
├─────────────────────────────────────────────────────────────┤
│  Group Descriptor Table: Información de grupos de bloques  │
├─────────────────────────────────────────────────────────────┤
│  Block Bitmap: Mapa de bits de bloques libres/ocupados     │
├─────────────────────────────────────────────────────────────┤
│  Inode Bitmap: Mapa de bits de inodos libres/ocupados      │
├─────────────────────────────────────────────────────────────┤
│  Inode Table: Tabla de inodos                              │
├─────────────────────────────────────────────────────────────┤
│  Data Blocks: Bloques de datos de archivos y directorios   │
└─────────────────────────────────────────────────────────────┘

Superblock

CampoDescripción
s_inodes_countNúmero total de inodos
s_blocks_countNúmero total de bloques
s_free_blocks_countBloques libres
s_free_inodes_countInodos libres
s_first_data_blockPrimer bloque de datos
s_block_sizeTamaño de bloque
s_magicFirma mágica (0xEF53 para EXT4)
s_stateEstado: limpio o dañado
s_last_mountedÚltimo punto de montaje
Backup del Superblock: EXT4 mantiene copias de respaldo del superblock dispersas en el disco para recuperación.

2. Journaling

¿Qué es el Journaling?

Técnica que registra cambios pendientes antes de aplicarlos, permitiendo recuperación consistente tras fallos.

Problema: Inconsistencia tras Fallo

Sin journaling - Operación de escritura:
1. Asignar bloque de datos
2. Escribir datos en bloque
3. Actualizar inodo con nuevo bloque
4. Actualizar bitmap de bloques

Falla entre paso 2 y 3 → Bloque perdido (inodo no apunta a él)
Falla entre paso 3 y 4 → Bloque asignado dos veces

El Journaling Resuelve Esto

Con journaling:
1. Escribir operación completa en journal (commit record)
2. Aplicar cambios al sistema de archivos
3. Marcar operación como completada en journal

Tras fallo:
- Si hay commit sin completion → Reaplicar (redo)
- Si no hay commit → Ignorar (no se aplicó nada)

Tipos de Journaling

TipoRegistroSeguridadRendimiento
WritebackSolo metadatosBajaMáximo
OrderedMetadatos + datos primeroMediaBueno
DataMetadatos + datosAltaBajo

Proceso de Recuperación (fsck)

  1. Verificar superblock y alternativas si está dañado
  2. Verificar consistencia de group descriptors
  3. Verificar bitmaps vs inodos reales
  4. Verificar contadores de bloques en inodos
  5. Reconstruir árbol de directorios
  6. Verificar inodos huérfanos (lost+found)

3. Montaje y Desmontaje de Sistemas de Archivos

Concepto de Montaje

El montaje conecta un sistema de archivos a la jerarquía de directorios del sistema operativo:

Antes de montar:
┌─────────────────────┐
│ Directorio /mnt/usb │ ← Vacío
└─────────────────────┘

Montaje: mount /dev/sdb1 /mnt/usb

Después de montar:
┌─────────────────────┐
│ Directorio /mnt/usb │ ← Contenido de /dev/sdb1
│   ├── archivo1.txt  │
│   ├── carpeta/      │
│   └── ...           │
└─────────────────────┘

Archivo /etc/fstab

Configuración de montajes persistentes:

# /etc/fstab - File System Table
#                        
UUID=abc123       /          ext4    defaults        0       1
UUID=def456       /home      ext4    defaults        0       2
/dev/sdb1         /mnt/data  ext4    rw,noatime      0       2
/dev/sr0          /media/cdrom  iso9660  ro,noauto   0       0
tmpfs             /tmp       tmpfs   defaults        0       0

Opciones Comunes de Montaje

OpciónDescripción
ro / rwSolo lectura / Lectura-escritura
noatimeNo actualizar tiempo de acceso (rendimiento)
sync / asyncSíncrono / Asíncrono
auto / noautoMontar en boot / No montar automáticamente
user / nouserPermitir montaje a usuarios
exec / noexecPermitir / Prohibir ejecución
Comandos útiles:
  • mount -a - Montar todo desde fstab
  • mount | grep /dev/sda - Ver opciones de montaje
  • umount /mnt/punto - Desmontar
  • fuser -m /mnt/punto - Ver procesos usando el punto

4. RAID Básico

RAID (Redundant Array of Independent Disks) combina múltiples discos para mejorar rendimiento o redundancia:

Niveles de RAID Básicos

RAID 0 - Striping

Datos divididos entre discos:
┌─────────────────┬─────────────────┐
│   Disco 0       │   Disco 1       │
│   [Bloque 0]    │   [Bloque 1]    │
│   [Bloque 2]    │   [Bloque 3]    │
│   [Bloque 4]    │   [Bloque 5]    │
└─────────────────┴─────────────────┘
Ventaja: Velocidad ×N
Desventaja: Si falla un disco, se pierde todo

RAID 1 - Mirroring

Datos duplicados en ambos discos:
┌─────────────────┬─────────────────┐
│   Disco 0       │   Disco 1       │
│   [Bloque 0]    │   [Bloque 0]    │
│   [Bloque 1]    │   [Bloque 1]    │
│   [Bloque 2]    │   [Bloque 2]    │
└─────────────────┴─────────────────┘
Ventaja: Tolerancia a fallos (un disco)
Desventaja: Capacidad = ½ del total

RAID 5 - Striping con Paridad

Datos y paridad distribuidos:
┌─────────────────┬─────────────────┬─────────────────┐
│   Disco 0       │   Disco 1       │   Disco 2       │
│   [Datos A]     │   [Datos B]     │   [Paridad AB]  │
│   [Datos C]     │   [Paridad CD]  │   [Datos D]     │
│   [Paridad EF]  │   [Datos E]     │   [Datos F]     │
└─────────────────┴─────────────────┴─────────────────┘
Ventaja: Balance rendimiento/redundancia
Capacidad: (N-1) × tamaño menor disco

Comparación de Niveles RAID

RAIDMín. DiscosCapacidadToleranciaUso típico
02100%NingunaDatos temporales
1250%1 discoSistemas críticos
53(n-1)/n1 discoServidores de archivos
64(n-2)/n2 discosAlmacenamiento masivo
10450%1 por mirrorBases de datos
RAID no es backup: RAID protege contra fallo de disco, no contra:
  • Borrado accidental de archivos
  • Corrupción por malware
  • Desastres físicos

5. Práctica en Linux

Comandos para gestión avanzada:

# Ver información del superblock
sudo dumpe2fs /dev/sda1 | head -50

# Verificar sistema de archivos
sudo e2fsck -n /dev/sda1    # Solo verificar (no modificar)
sudo e2fsck -f /dev/sda1    # Forzar verificación

# Cambiar opciones de montaje
sudo tune2fs -o ^acl /dev/sda1  # Desactivar ACLs

# Ver journal de un FS ext4
sudo debugfs -R 'stat <12>' /dev/sda1

# Crear sistema de archivos
sudo mkfs.ext4 -L "MiDisco" /dev/sdb1

# Ver particiones y UUIDs
sudo blkid
lsblk -f

# Montar por UUID
sudo mount UUID="abc123" /mnt/punto

# Crear RAID (con mdadm)
# RAID 1:
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1

# Ver estado RAID
cat /proc/mdstat

# Guardar configuración RAID
sudo mdadm --detail --scan >> /etc/mdadm/mdadm.conf
