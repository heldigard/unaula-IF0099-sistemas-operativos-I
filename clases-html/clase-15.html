Glosario de Seguridad Linux

  • UGO: User (Propietario), Group (Grupo), Others (Otros).
  • rwx: Read (Lectura), Write (Escritura), eXecute (Ejecución).
  • ACL: Access Control List (Listas de Control de Acceso para permisos más granulares).
  • Sticky Bit: Permiso que asegura que solo el dueño del archivo pueda borrarlo, aunque otros tengan permiso de escritura en la carpeta.

1. Introducción a Permisos en Linux

Concepto fundamental: Linux es un sistema multiusuario diseñado para la seguridad. Cada archivo y directorio tiene permisos que controlan quién puede leer, escribir o ejecutar.

¿Por qué son importantes los permisos?

  • Seguridad: Protegen información confidencial
  • Integridad: Evitan modificaciones no autorizadas
  • Privacidad: Cada usuario tiene su espacio privado
  • Control: El administrador decide quién accede a qué

Modelo de Seguridad UGO

Linux utiliza el modelo UGO (User, Group, Others):

  • User (u): El propietario del archivo
  • Group (g): El grupo del archivo
  • Others (o): Todos los demás usuarios

2. Permisos Básicos (rwx)

Tipos de Permisos

r - Read    (lectura)    - Puede leer el contenido
w - Write   (escritura)  - Puede modificar el contenido
x - eXecute (ejecución)  - Puede ejecutar como programa

Estructura de Permisos

-rwxr-xr--  1 juan developers 1024 Feb 15 10:30 archivo.txt
│  │  │     │     │       │        │       │
│  │  │     │     │       │        │       └─ Nombre del archivo
│  │  │     │     │       │        └─ Tamaño y fecha
│  │  │     │     │       └─ Grupo propietario
│  │  │     │     └─ Usuario propietario
│  │  │     └─ Número de hard links
│  │  └─ Permisos Others (r--)
│  └─ Permisos Group (r-x)
└─ Permisos User (rwx)

Notación Octal

Permiso Valor Binario Significado
---0000Sin permisos
--x1001Solo ejecución
-w-2010Solo escritura
-wx3011Escritura y ejecución
r--4100Solo lectura
r-x5101Lectura y ejecución
rw-6110Lectura y escritura
rwx7111 Todos los permisos
Cálculo rápido: r = 4, w = 2, x = 1 → Suma los valores que quieras activar
ej: rwx = 4+2+1 = 7, r-x = 4+1 = 5

3. Comando chmod (Change Mode)

El comando chmod modifica los permisos de archivos y directorios.

Sintaxis Simbólica

# Agregar permiso
chmod +x script.sh           # Hacer ejecutable

# Quitar permiso
chmod -w archivo.txt         # Quitar escritura

# Específico por categoría
chmod u+x script.sh          # Usuario: ejecutar
chmod g+r archivo.txt        # Grupo: leer
chmod o-w archivo.txt        # Otros: no escribir

# Múltiples cambios
chmod u+x,g+r,o-w archivo.txt

Sintaxis Octal

# Formato: chmod [usuario][grupo][otros] archivo
chmod 644 archivo.txt        # rw-r--r--
chmod 755 script.sh          # rwxr-xr-x
chmod 700 privado.txt        # rwx------
chmod 777 publico.txt        # rwxrwxrwx (NO RECOMENDADO)

Permisos Comunes

Octal Permiso Uso típico
644rw-r--r--Archivos de texto
755rwxr-xr-xScripts y programas
600rw-------Archivos confidenciales
700rwx------Directorios privados
Advertencia: Nunca uses 777 en servidores de producción. Da permisos totales a todos los usuarios.

4. Comando chown (Change Owner)

El comando chown cambia el propietario y grupo de un archivo.

Cambiar Propietario

# Cambiar solo el usuario
sudo chown nuevo_usuario archivo.txt

# Cambiar usuario y grupo
sudo chown usuario:grupo archivo.txt

# Cambiar solo el grupo
sudo chown :grupo archivo.txt

# Recursivo (directorios)
sudo chown -R usuario:grupo /directorio/

Ejemplos Prácticos

# Servidor web: archivos pertenecen a www-data
sudo chown -R www-data:www-data /var/www/html

# Proyecto compartido: grupo developers
sudo chown -R juan:developers /proyecto/compartido

# Directorio personal: usuario y su grupo
sudo chown -R $USER:$USER ~/documentos

5. Permisos Especiales

SUID (Set User ID)

El archivo se ejecuta con los privilegios del propietario, no del usuario que lo ejecuta.

# Ejemplo: /usr/bin/passwd
$ ls -l /usr/bin/passwd
-rwsr-xr-x  1 root root 73465 Feb 15 10:30 /usr/bin/passwd
 │             │
 │             └─ Dueño = root
 └─ s = SUID activo

Cualquier usuario puede cambiar su contraseña porque passwd se ejecuta temporalmente como root.

# Activar SUID
chmod u+s archivo
chmod 4755 archivo            # 4 = SUID
Peligro: SUID puede ser un vector de escalada de privilegios. Solo usar cuando sea absolutamente necesario.

SGID (Set Group ID)

Los archivos nuevos heredan el grupo del directorio padre.

# Crear directorio colaborativo
mkdir /proyecto/compartido
sudo chown -R :developers /proyecto/compartido
sudo chmod g+s /proyecto/compartido

# Verificar
ls -ld /proyecto/compartido
drwxrwsr-x  2 juan developers 4096 Feb 15 10:30 /proyecto/compartido
 │                │
 │                └─ s = SGID activo
# Activar SGID
chmod g+s directorio
chmod 2755 directorio           # 2 = SGID

Sticky Bit

Solo el propietario puede borrar sus archivos (útil en directorios compartidos).

# Ejemplo: /tmp
$ ls -ld /tmp
drwxrwxrwt  10 root root 4096 Feb 15 10:30 /tmp
 │                │
 │                └─ t = Sticky bit activo
# Activar sticky bit
chmod +t directorio
chmod 1755 directorio           # 1 = Sticky bit
Uso típico: Directorios compartidos donde múltiples usuarios pueden crear archivos, pero solo pueden borrar los suyos propios (como /tmp).

6. Usuarios y Grupos en Linux

Archivos de Configuración

Archivo Contenido
/etc/passwdInformación de usuarios
/etc/shadowContraseñas encriptadas
/etc/groupInformación de grupos
/etc/gshadowContraseñas de grupos

Gestión de Usuarios

# Crear usuario
sudo useradd -m -s /bin/bash nuevo_usuario

# Establecer contraseña
sudo passwd nuevo_usuario

# Ver información de usuario
id nuevo_usuario
groups nuevo_usuario

# Eliminar usuario
sudo userdel usuario
sudo userdel -r usuario       # Eliminar también home

Gestión de Grupos

# Crear grupo
sudo groupadd desarrolladores

# Agregar usuario a grupo
sudo usermod -aG desarrolladores usuario

# Ver miembros de un grupo
getent group desarrolladores

# Eliminar grupo
sudo groupdel desarrolladores

Estructura de /etc/passwd

juan:x:1000:1000:Juan Perez:/home/juan:/bin/bash
│  │ │   │    │            │           │
│  │ │   │    │            │           └─ Shell predeterminado
│  │ │   │    │            └─ Directorio home
│  │ │   │    └─ Comentario (nombre completo)
│  │ │   └─ GID (grupo primario)
│  │ └─ UID (ID de usuario)
│  └─ x = contraseña en /etc/shadow
└─ Nombre de usuario

7. ACLs (Access Control Lists)

¿Qué son las ACLs? Permiten permisos más granulares que el modelo UGO tradicional. Puedes dar permisos a múltiples usuarios y grupos específicos.

Instalar ACL

# Debian/Ubuntu
sudo apt install acl

# RHEL/CentOS
sudo yum install acl

Ver ACL

# Ver ACL de un archivo
getfacl archivo.txt

# Salida ejemplo:
# file: archivo.txt
# owner: juan
# group: developers
user::rw-
user:maria:rw-
group::r--
mask::rw-
other::r--

Modificar ACL

# Dar permisos a usuario específico
setfacl -m u:maria:rw archivo.txt

# Dar permisos a grupo específico
setfacl -m g:equiporh:rx documento.txt

# Eliminar permiso de usuario
setfacl -x u:maria archivo.txt

# Eliminar todas las ACLs
setfacl -b archivo.txt

ACLs por Defecto para Directorios

# Establecer ACLs predeterminadas (nuevos archivos heredan)
setfacl -d -m u:maria:rw /directorio/compartido

# Ver ACLs predeterminadas
getfacl -d /directorio/compartido
Ventaja de ACLs: No necesitas crear nuevos grupos para cada combinación de permisos. Puedes dar permisos específicos a usuarios individuales sin afectar al modelo UGO.

8. Actividad Práctica

📋 Laboratorio Complementario

Para aplicar técnicas de aseguramiento y hardening en tu servidor Linux, consulta el Laboratorio 6: Seguridad y Hardening.

Ejercicio 1: Permisos Básicos

Objetivo: Practicar con chmod y chown

# 1. Crear archivo de prueba
touch prueba.txt

# 2. Ver permisos iniciales
ls -l prueba.txt

# 3. Cambiar a 644 (rw-r--r--)
chmod 644 prueba.txt
ls -l prueba.txt

# 4. Quitar permiso de lectura a otros
chmod o-r prueba.txt
ls -l prueba.txt

# 5. Hacer ejecutable
chmod +x prueba.txt
ls -l prueba.txt

Ejercicio 2: Permisos Especiales

Objetivo: Configurar directorio compartido con SGID

# 1. Crear directorio compartido
mkdir -p ~/proyecto/compartido

# 2. Crear grupo de desarrolladores
sudo groupadd desarrolladores

# 3. Agregarte al grupo
sudo usermod -aG desarrolladores $USER

# 4. Configurar directorio
sudo chown -R :desarrolladores ~/proyecto/compartido
sudo chmod g+s ~/proyecto/compartido

# 5. Verificar (inicia nueva sesión para que surta efecto)
newgrp desarrolladores
ls -ld ~/proyecto/compartido

Ejercicio 3: ACLs

Objetivo: Dar acceso específico a otro usuario

# 1. Crear archivo confidencial
echo "Datos importantes" > confidencial.txt

# 2. Ver ACL actual
getfacl confidencial.txt

# 3. Dar permiso de lectura a usuario compañero
sudo setfacl -m u:compañero:r confidencial.txt

# 4. Verificar ACL
getfacl confidencial.txt

Tiempo estimado: 60 minutos
