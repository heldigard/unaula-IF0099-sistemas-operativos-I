1. ¿Qué es IIS (Internet Information Services)?

Es el servidor web nativo de Windows Server. Su gran diferencia con otros servidores es que utiliza un driver de kernel dedicado llamado HTTP.SYS para manejar las conexiones.

El rol de HTTP.SYS (Ring 0)

Este driver reside en el modo privilegiado. Él se encarga de escuchar los puertos 80 y 443, poner las peticiones en cola y entregarlas al proceso de usuario correspondiente. Esto permite que el servidor web sea extremadamente estable.

2. Application Pools: El muro de contención

En el mundo real, no corremos todos los sitios web en el mismo proceso. IIS usa Application Pools para el aislamiento.

  • Aislamiento de Seguridad: Cada pool puede correr con un usuario diferente.
  • Aislamiento de Fallos: Si el proceso del Sitio A crashea, el Sitio B sigue vivo.
  • Reciclado: El SO puede reiniciar procesos automáticamente si consumen demasiada RAM.

3. Automatización con PowerShell

Para el proyecto UCS, configuraremos el servidor usando el módulo WebAdministration.

# Instalar el rol completo
Install-WindowsFeature -name Web-Server -IncludeManagementTools

# Crear el sitio web del proyecto
New-Website -Name "UCS_Portal" -PhysicalPath "C:\www\ucs" -Port 8080

# Crear un pool dedicado
New-WebAppPool -Name "UCS_Pool"
Set-ItemProperty "IIS:\Sites\UCS_Portal" -name applicationPool -value "UCS_Pool"

Casos Reales: IIS en Producción

Caso 1: IIS No Inicia - Puerto en Uso

Escenario: IIS no puede iniciar. Muestra "The process cannot access the file because it is being used by another process".

Diagnóstico:

# Ver qué proceso usa el puerto 80
netstat -ano | findstr :80

# Matar el proceso si es innecesario
Stop-Process -Id [PID] -Force

# Si esSkype/TeamViewer, configurarlos para no usar puertos web

Caso 2: Application Pool se Detiene Constantemente

Escenario: El sitio web funciona 5 minutos y luego muestra error 503.

Causa: El pool de aplicaciones está colapsando por excepciones no manejadas.

Solución:

  1. Revisa el Event Viewer → Windows Logs → Application
  2. Configura "Rapid-Fail Protection" para que no se Deshabilite automáticamente
  3. Revisa el código de la aplicación para excepciones

Caso 3: Error 403 - Forbidden

Escenario: Los usuarios ven "403 Forbidden" al acceder al sitio.

Solución:

  1. Verifica permisos en la carpeta: IIS_IUSRS necesita lectura
  2. Revisa los permisos de NTFS en la carpeta raíz
  3. Ejecuta: icacls C:\inetpub\wwwroot\ucs /grant "IIS_IUSRS:(OI)(CI)RX"

📊 Monitoreo: Integración con Performance Monitor

Contadores clave de IIS:

  • \ASP.NET Applications(>)\Requests/Sec - Rendimiento de la app
  • \W3SVC_W3WP(*)\Active Requests - Peticiones activas
  • \Process(w3wp)\Private Bytes - Memoria del worker process
  • \Web Service(*)\Current Connections - Conexiones activas
# Crear Data Collector Set en PowerShell
$collectorName = "IIS_Performance"
New-PerfCounterDataCollectorSet -Name $collectorName -Counters @(
    "\ASP.NET Applications(*)\Requests/Sec",
    "\W3SVC_W3WP(*)\Active Requests",
    "\Process(w3wp)\Private Bytes"
) -SampleInterval 5 -MaxSize 100MB

# Iniciar colección
Start-PerfCounterDataCollectorSet -Name $collectorName

⚙️ Ejercicio: Configuración Completa de Application Pools

# Crear Application Pool avanzado con PowerShell

# 1. Crear pool con configuración específica
New-WebAppPool -Name "UCS_Production_Pool"

# 2. Configurar versión de .NET (si aplica)
Set-ItemProperty IIS:\AppPools\UCS_Production_Pool managedRuntimeVersion "v4.0"

# 3. Configurar modo de pipeline (Integrated = moderno)
Set-ItemProperty IIS:\AppPools\UCS_Production_Pool managedPipelineMode "Integrated"

# 4. Configurar identidad (mejor seguridad)
Set-ItemProperty IIS:\AppPools\UCS_Production_Pool processModel.identityType "ApplicationPoolIdentity"

# 5. Configurar reciclaje automático
Set-ItemProperty IIS:\AppPools\UCS_Production_Pool recycling.periodicRestart.time "02:00:00"
Set-ItemProperty IIS:\AppPools\UCS_Production_Pool recycling.periodicRestart.requests 10000

# 6. Límites de memoria (evitar fugas)
Set-ItemProperty IIS:\AppPools\UCS_Production_Pool recycling.periodicRestart.privateMemory 1048576 # 1GB

# 7. Configurar Rapid-Fail Protection
Set-ItemProperty IIS:\AppPools\UCS_Production_Pool failure.rapidFailProtection "True"
Set-ItemProperty IIS:\AppPools\UCS_Production_Pool failure.rapidFailProtectionInterval "00:05:00"
Set-ItemProperty IIS:\AppPools\UCS_Production_Pool failure.rapidFailProtectionMaxCrashes 5

# 8. Asignar pool al sitio
Set-ItemProperty IIS:\Sites\UCS_Portal -Name applicationPool -Value "UCS_Production_Pool"

# 9. Iniciar el pool
Start-WebAppPool -Name "UCS_Production_Pool"

# Verificar configuración
Get-ItemProperty IIS:\AppPools\UCS_Production_Pool | Select-Object *

✅ Checklist de Application Pool seguro:

  • Identidad: ApplicationPoolIdentity (no NetworkService)
  • Reciclaje: Cada 24h o X peticiones
  • Límite de memoria: Según capacidad del servidor
  • Rapid-Fail: Activado con 5 fallos máximo
  • Pipeline: Integrated (para apps modernas)
