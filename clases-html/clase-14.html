1. ¿Qué es IIS (Internet Information Services)?

Es el servidor web nativo de Windows Server. Su gran diferencia con otros servidores es que utiliza un driver de kernel dedicado llamado HTTP.SYS para manejar las conexiones.

El rol de HTTP.SYS (Ring 0)

Este driver reside en el modo privilegiado. Él se encarga de escuchar los puertos 80 y 443, poner las peticiones en cola y entregarlas al proceso de usuario correspondiente. Esto permite que el servidor web sea extremadamente estable.

2. Application Pools: El muro de contención

En el mundo real, no corremos todos los sitios web en el mismo proceso. IIS usa Application Pools para el aislamiento.

  • Aislamiento de Seguridad: Cada pool puede correr con un usuario diferente.
  • Aislamiento de Fallos: Si el proceso del Sitio A crashea, el Sitio B sigue vivo.
  • Reciclado: El SO puede reiniciar procesos automáticamente si consumen demasiada RAM.

3. Automatización con PowerShell

Para el proyecto UCS, configuraremos el servidor usando el módulo WebAdministration.

# Instalar el rol completo
Install-WindowsFeature -name Web-Server -IncludeManagementTools

# Crear el sitio web del proyecto
New-Website -Name "UCS_Portal" -PhysicalPath "C:\www\ucs" -Port 8080

# Crear un pool dedicado
New-WebAppPool -Name "UCS_Pool"
Set-ItemProperty "IIS:\Sites\UCS_Portal" -name applicationPool -value "UCS_Pool"

4. Comandos de Diagnóstico y Control

Mundo Windows (PowerShell)

# Ver sitios activos
Get-Website

# Ver estado de los pools
Get-WebAppPoolState

# Reiniciar IIS completo
iisreset /restart

# Probar acceso local
Invoke-WebRequest http://localhost:8080

Consola Clásica (AppCmd)

# Listar procesos de worker (w3wp.exe)
appcmd list wp

# Ver sitios corriendo
appcmd list site

# Reiniciar un sitio específico
appcmd stop site "UCS_Portal"
appcmd start site "UCS_Portal"

5. Actividad Práctica: Despliegue IIS (Insumo E5)

Laboratorio: El Portal Administrativo UCS

Objetivo: Montar la infraestructura web en el nodo Windows del proyecto.

Pasos a realizar:

  1. Habilite IIS en su VM de Windows Server.
  2. Cree la carpeta raíz: C:\inetpub\wwwroot\ucs_admin.
  3. Seguridad: Asigne permisos de "Solo Lectura" al usuario local IIS_IUSRS sobre esa carpeta.
  4. Configuración: Cambie el puerto por defecto a 8080 para evitar conflictos con el nodo Linux.
  5. Firewall: Abra el puerto 8080 en el Firewall de Windows usando PowerShell: 
    New-NetFirewallRule -DisplayName "UCS Web Port" -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow

Entregable: Una captura de pantalla de su navegador mostrando el mensaje "UCS Windows Node Active" accediendo por el puerto 8080.

Casos Reales: IIS en Producción

Caso 1: IIS No Inicia - Puerto en Uso

Escenario: IIS no puede iniciar. Muestra "The process cannot access the file because it is being used by another process".

Diagnóstico:

# Ver qué proceso usa el puerto 80
netstat -ano | findstr :80

# Matar el proceso si es innecesario
Stop-Process -Id [PID] -Force

# Si esSkype/TeamViewer, configurarlos para no usar puertos web

Caso 2: Application Pool se Detiene Constantemente

Escenario: El sitio web funciona 5 minutos y luego muestra error 503.

Causa: El pool de aplicaciones está colapsando por excepciones no manejadas.

Solución:

  1. Revisa el Event Viewer → Windows Logs → Application
  2. Configura "Rapid-Fail Protection" para que no se Deshabilite automáticamente
  3. Revisa el código de la aplicación para excepciones

Caso 3: Error 403 - Forbidden

Escenario: Los usuarios ven "403 Forbidden" al acceder al sitio.

Solución:

  1. Verifica permisos en la carpeta: IIS_IUSRS necesita lectura
  2. Revisa los permisos de NTFS en la carpeta raíz
  3. Ejecuta: icacls C:\inetpub\wwwroot\ucs /grant "IIS_IUSRS:(OI)(CI)RX"
