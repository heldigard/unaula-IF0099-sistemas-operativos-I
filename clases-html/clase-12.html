Glosario de Sistemas de Archivos

  • UID / GID: User ID / Group ID (Identificadores numéricos de usuario y grupo).
  • MFT (Master File Table): Tabla maestra de archivos, el corazón del sistema NTFS.
  • Journaling: Registro de transacciones para evitar corrupción de datos tras un fallo.
  • Extent: Área contigua de almacenamiento asignada a un archivo para mejorar el rendimiento.

1. Inodos (Index Nodes)

¿Qué es un inodo?

Estructura de datos que almacena metadatos de un archivo (excepto su nombre). Cada archivo tiene un inodo único.

Estructura de un Inodo

Inodo (128 bytes en ext4):
┌─────────────────────────────────────────────┐
│ Modo/Tipo          (2 bytes)               │
│ Número de enlaces  (2 bytes)               │
│ UID del propietario (2 bytes)              │
│ GID del grupo       (2 bytes)              │
│ Tamaño del archivo  (8 bytes)              │
│ Timestamps (3):                           │
│   - Último acceso (atime)                  │
│   - Última modificación (mtime)            │
│   - Último cambio de inodo (ctime)         │
│ Bloques directos (12) × 4 bytes = 48 bytes │
│ Bloque indirecto simple  (4 bytes)         │
│ Bloque indirecto doble   (4 bytes)         │
│ Bloque indirecto triple  (4 bytes)         │
└─────────────────────────────────────────────┘

Punteros a Bloques

TipoNúmeroBloques apuntadosTamaño máx (4KB)
Directos1212 bloques48 KB
Indirecto simple11024 bloques4 MB
Indirecto doble11024² bloques4 GB
Indirecto triple11024³ bloques4 TB
Extents en EXT4: Modernamente se usan extents (rango de bloques contiguos) en lugar de lista de bloques individuales para archivos grandes, mejorando rendimiento y reduciendo fragmentación.

2. Directorios

Estructura de un Directorio

Un directorio es un archivo especial que contiene una tabla de nombres e inodos:

Contenido de un directorio:
┌──────────────────┬──────────────────┐
│ Nombre de archivo│ Número de inodo  │
├──────────────────┼──────────────────┤
│ .                │ 2341 (self)      │
│ ..               │ 1200 (parent)    │
│ archivo.txt      │ 4523             │
│ subdir/          │ 3891             │
│ enlace.lnk       │ 4523 (hard link) │
└──────────────────┴──────────────────┘

Jerarquía de Archivos en Linux (FHS)

DirectorioContenido
/Raíz del sistema
/binBinarios esenciales del sistema
/etcArchivos de configuración
/homeDirectorios de usuarios
/varDatos variables (logs, correo)
/tmpArchivos temporales
/usrProgramas y bibliotecas
/devDispositivos del sistema
/procInformación de procesos (virtual)

Tipos de Archivos

  • - Archivo regular
  • d Directorio
  • l Enlace simbólico
  • c Dispositivo de caracteres
  • b Dispositivo de bloques
  • p Pipe (tubería con nombre)
  • s Socket

3. Permisos de Archivos

Modelo de Permisos Unix

Notación simbólica: -rwxr-xr-x
                    │└┬┘└┬┘└┬┘
                    │ │  │  └── Otros (others)
                    │ │  └───── Grupo (group)
                    │ └──────── Usuario (owner)
                    └────────── Tipo (- = archivo, d = directorio)

Bits de permiso:
r = read (4)     - Leer contenido
w = write (2)    - Modificar contenido  
x = execute (1)  - Ejecutar como programa

Permisos en Directorios

PermisoEfecto en directorios
rListar contenido (ls)
wCrear/borrar archivos
xAcceder al directorio (cd)

Permisos Especiales

PermisoValorEfecto
SUID4000 (u+s)Ejecutar con permisos del propietario
SGID2000 (g+s)Ejecutar con permisos del grupo
Sticky1000 (+t)Solo propietario puede borrar
Ejemplo de Sticky bit: /tmp tiene permisos drwxrwxrwt. Cualquiera puede escribir, pero solo puedes borrar tus propios archivos.

4. Sistema de Archivos EXT4

Características Principales

  • Extents: Almacenan rangos de bloques contiguos
  • Journaling: Registro de cambios para recuperación
  • Backward compatible: Puede montar EXT2/EXT3
  • Delayed allocation: Mejora asignación de bloques
  • Defragmentación online: Sin desmontar

Modos de Journaling

ModoDescripciónRendimiento vs Seguridad
journalJournaling de datos y metadatosSeguro, más lento
orderedJournaling de metadatos + datos antesBalance (default)
writebackSolo metadatosRápido, menos seguro

Comandos de Mantenimiento EXT4

# Verificar sistema de archivos
e2fsck /dev/sda1

# Ver información del superblock
tune2fs -l /dev/sda1

# Cambiar modo de journaling
tune2fs -o journal_data /dev/sda1

# Defragmentar (si es necesario)
e4defrag /ruta/al/archivo

5. Sistema de Archivos NTFS

Características de NTFS

CaracterísticaDescripción
Journaling$LogFile para recuperación
ACLsListas de control de acceso detalladas
CompresiónCompresión a nivel de archivo
EncriptaciónEFS (Encrypting File System)
Streams alternativosMúltiples flujos de datos por archivo
QuotesLímites de espacio por usuario

Estructura NTFS

Estructura básica:
┌──────────────┬──────────────┬──────────────┬──────────────┐
│ Boot Sector  │ Master File  │ System Files │ User Data    │
│              │ Table (MFT)  │ (Metadata)   │              │
└──────────────┴──────────────┴──────────────┴──────────────┘

MFT (Master File Table):
- Cada archivo/directorio tiene entrada en MFT (1KB típico)
- Contiene atributos: nombre, fechas, permisos, datos
- Archivos pequeños pueden estar residentes en MFT

Comparación EXT4 vs NTFS

AspectoEXT4NTFS
Sistema principalLinuxWindows
PermisosUnix (rwx)ACLs complejas
Sensibilidad a mayúsculasSíNo (preserva)
EnlacesHard y symbolic linksHard links, junctions
Soporte LinuxNativoVia ntfs-3g

6. Práctica en Linux

📋 Laboratorio Complementario

Para profundizar en inodos, enlaces y permisos avanzados, consulta el Laboratorio 5: Sistemas de Archivos Avanzados.

Comandos para inodos y permisos:

# Ver inodo de un archivo
ls -i archivo.txt

# Ver información detallada de inodo
stat archivo.txt

# Listar con permisos
ls -la

# Cambiar permisos
chmod 755 archivo
chmod u+x script.sh
chmod g-w archivo

# Cambiar propietario
sudo chown usuario:grupo archivo

# Ver sistema de archivos de cada partición
df -T

# Ver información de superblock
sudo dumpe2fs /dev/sda1 | head -30

# Buscar inodos libres
df -i

# Crear enlace duro (mismo inodo)
ln archivo.txt enlace_duro.txt

# Crear enlace simbólico
ln -s archivo.txt enlace_simbolico.txt

Ejercicio práctico:

Ejercicio: Análisis de Inodos y Permisos

  1. Crear varios archivos y directorios
  2. Ver sus inodos con ls -i y stat
  3. Crear un hard link y ver que comparte inodo
  4. Crear un symbolic link y comparar
  5. Configurar diferentes permisos y probar acceso
  6. Ver información del sistema de archivos
