1. ¿Qué es un Sistema Operativo?

Definición Simple

Un Sistema Operativo (SO) es el software que gestiona el hardware de tu computadora y provee servicios para los programas. Sin él, tu computadora sería un conjunto de componentes inútiles.

Definición Clave

Sistema Operativo = Software que gestiona hardware + provee servicios a programas

¿Por qué es necesario?

Imagina que tu computadora es una fábrica:

  • Hardware = Máquinas, edificios, herramientas
  • Programas = Trabajadores que producen cosas
  • Sistema Operativo = El gerente que organiza todo

Sin el gerente (SO), los trabajadores (programas) pelearían por las máquinas (hardware), causando caos y colapsos.

2. Funciones Principales del Sistema Operativo

El SO realiza cuatro funciones fundamentales:

Función Descripción Ejemplo
Gestión de Procesos Administra qué programas se ejecutan y cuándo Permite que Chrome, Word y Spotify corran al mismo tiempo
Gestión de Memoria Controla el uso de la RAM Asigna memoria a programas y la libera cuando terminan
Gestión de Archivos Organiza cómo se guardan y recuperan los datos Carpetas, archivos, permisos de lectura/escritura
Gestión de Entrada/Salida Controla dispositivos como teclado, mouse, disco Lee lo que escribes, guarda archivos, muestra en pantalla

Analogía Simple

Procesos = Clientes en un restaurante | Memoria = Mesas disponibles | Archivos = Pedidos en cocina | E/S = Camareros tomando pedidos

3. Tipos de Arquitectura de Sistema Operativo

Los SO se organizan internamente de diferentes maneras. Entender estas arquitecturas es fundamental para comprender cómo funciona cada sistema operativo.

3.1 Arquitectura Monolítica

En una arquitectura monolítica, TODO el código del sistema operativo está en un solo bloque grande en el kernel. Todos los servicios (gestión de procesos, memoria, archivos, drivers) corren en el mismo espacio de memoria.

Características del Kernel Monolítico:

Aspecto Descripción
Estructura Todos los servicios del SO están en un único bloque de código
Comunicación Las funciones se llaman directamente (sin pasar mensajes)
Espacio de memoria Todo corre en modo kernel (espacio privilegiado)
Tamaño del kernel Muy grande (millones de líneas de código)

Ventajas:

  • Rendimiento superior: Al no haber capas intermedias, las llamadas son muy rápidas
  • Simplicidad de diseño: Fácil de entender conceptualmente
  • Eficiencia: Menor sobrecarga (overhead) en comunicación

Desventajas:

  • Si falla algo, falla todo: Un error en un driver puede crashear todo el sistema
  • Difícil de mantener: Cambiar algo requiere recompilar todo el kernel
  • Menor seguridad: Todo corre con los mismos privilegios
  • Tamaño grande: El kernel es enorme

💡 Ejemplo del Mundo Real: Linux

Linux usa un kernel monolítico. Por eso es tan rápido y eficiente en servidores. Linux tiene más de 30 millones de líneas de código, pero todo está integrado en el kernel.

Dato curioso: Android también usa Linux (kernel monolítico) modificado para móviles.

3.2 Arquitectura Microkernel

En una arquitectura microkernel, SOLO lo mínimo indispensable está en el kernel. El resto de los servicios corren como procesos normales en espacio de usuario.

Características del Microkernel:

Aspecto Descripción
Estructura Solo funciones críticas en el kernel (IPC, scheduling, memoria básica)
Comunicación Se hace mediante paso de mensajes (message passing)
Servicios Corren como procesos separados en espacio de usuario
Tamaño del kernel Muy pequeño (solo miles de líneas de código)

Ventajas:

  • Mayor estabilidad: Si un driver falla, solo se reinicia ese servicio
  • Mayor seguridad: Cada servicio tiene sus propios privilegios
  • Fácil de extender: Agregar servicios sin recompilar el kernel
  • Más modular: Cada componente es independiente

Desventajas:

  • Más lento: La comunicación por mensajes tiene overhead
  • Más complejo: Diseño más difícil de implementar
  • Mayor uso de memoria: Cada servicio consume su propia memoria

💡 Ejemplo del Mundo Real: MINIX 3

MINIX 3 es un microkernel usado para enseñar SO. También se usa en Intel ME (Management Engine) por su seguridad y estabilidad.

QNX es otro microkernel usado en sistemas críticos como automóviles y equipos médicos.

3.3 Arquitectura Híbrida

La arquitectura híbrida combina lo mejor de ambos mundos: mantiene algunos servicios en el kernel (por rendimiento) y otros fuera (por seguridad).

Característica Descripción
Enfoque Algunos servicios en kernel, otros en espacio de usuario
Flexibilidad Puede decidir qué va en cada espacio según necesidades
Rendimiento Mejor que microkernel, peor que monolítico puro

Ejemplos Híbridos:

  • Windows NT: Drivers en kernel, servicios en usuario
  • macOS (XNU): Parte monolítica (BSD) + parte microkernel (Mach)
  • Linux con módulos: Monolítico pero permite cargar/descargar componentes

4. VirtualBox y Ubuntu Server 22.04 LTS

TIEMPO ESTIMADO: 45 minutos

4.1 ¿Qué es VirtualBox?

VirtualBox es un programa que te permite ejecutar sistemas operativos completos DENTRO de tu computadora como si fueran aplicaciones normales.

¿Por qué usamos VirtualBox?

  • Es GRATIS - No cuesta nada
  • Es seguro - Si algo sale mal, tu computadora real no se afecta
  • Permite experimentar - Puedes borrar y crear VMs sin riesgo
  • Funciona en cualquier sistema - Windows, macOS, Linux

4.2 ¿Qué es Ubuntu Server?

Ubuntu Server es una versión de Linux sin interfaz gráfica. Todo se hace mediante comandos de texto. Es la versión usada en servidores reales de internet.

Importante: Sin Interfaz Gráfica

Ubuntu Server NO tiene ventanas, ni mouse, ni iconos. Todo es texto negro con comandos. Esto es intencional: los servidores no necesitan interfaz gráfica.

4.3 Instalación Paso a Paso

Paso 1: Descargar VirtualBox

  1. Entra a: https://www.virtualbox.org/wiki/Downloads
  2. Descarga la versión para tu sistema operativo (Windows hosts)
  3. Ejecuta el instalador
  4. Haz clic en "Next" en todos los pasos (opciones por defecto)
  5. Haz clic en "Install" y espera a que termine
  6. Reinicia tu computadora cuando te lo pida

Paso 2: Descargar Ubuntu Server 22.04 LTS

  1. Entra a: https://ubuntu.com/download/server
  2. Haz clic en "Download" (archivo ISO de aproximadamente 3 GB)
  3. Guarda el archivo en una carpeta donde puedas encontrarlo fácilmente

¿Qué es un archivo ISO?

Un archivo ISO es una imagen exacta de un disco de instalación. VirtualBox usará este archivo como si fuera un DVD de instalación.

Paso 3: Crear la Máquina Virtual

  1. Abre VirtualBox
  2. Haz clic en el botón azul "Nueva" (New)
  3. Nombre: Escribe "Ubuntu-Server-SO01"
  4. Carpeta: Elige una ubicación con suficiente espacio (mínimo 20 GB libres)
  5. Tipo: Linux
  6. Versión: Ubuntu (64-bit)
  7. Haz clic en "Siguiente"
  8. Memoria RAM: 2048 MB (2 GB) - Si tienes 8 GB o menos en tu PC, usa 1024 MB
  9. Haz clic en "Siguiente"
  10. Disco Duro: Selecciona "Crear ahora un disco duro virtual"
  11. Haz clic en "Crear"
  12. Tipo de archivo: VDI (VirtualBox Disk Image)
  13. Haz clic en "Siguiente"
  14. Almacenamiento: Dinámicamente asignado
  15. Haz clic en "Siguiente"
  16. Tamaño: 20.00 GB
  17. Haz clic en "Crear"

Advertencia de Espacio

Asegúrate de tener al menos 25 GB libres en tu disco duro. La máquina virtual ocupará espacio a medida que la uses.

Paso 4: Configurar la Máquina Virtual

  1. En VirtualBox, selecciona tu VM "Ubuntu-Server-SO01"
  2. Haz clic en "Configuración" (Settings)
  3. Sistema → Procesador: Asigna 2 CPU si tu computadora tiene 4 o más
  4. Almacenamiento: Haz clic en el icono de disco vacío
  5. Haz clic en el icono de disco pequeño a la derecha
  6. Selecciona "Elegir un archivo de disco óptico"
  7. Navega a donde descargaste el ISO de Ubuntu Server
  8. Selecciona el archivo ISO y haz clic en "Abrir"
  9. Haz clic en "Aceptar" para cerrar la configuración

Paso 5: Instalar Ubuntu Server

  1. Haz doble clic en tu VM "Ubuntu-Server-SO01"
  2. La VM arrancará y verás una pantalla de instalación de Ubuntu
  3. Selecciona el idioma (recomendado: English)
  4. Selecciona "Update to the new installer" si aparece
  5. Configuración del teclado: selecciona el correcto para tu idioma
  6. Network connections: Deja la que aparece por defecto
  7. Configure proxy: Deja en blanco y haz clic en "Done"
  8. Configure Ubuntu archive mirror: Deja el de defecto y haz clic en "Done"
  9. Guided storage configuration: Selecciona "Use an entire disk"
  10. Haz clic en "Done" y luego confirma "Continue"
  11. Storage configuration: Haz clic en "Done" y confirma "Continue"
  12. Profile setup:
    • Your name: Estudiante SO
    • Your server's name: ubuntu-server-so01
    • Choose a username: estudiante
    • Choose a password: [Elige una contraseña segura que recuerdes]
  13. Haz clic en "Done"
  14. SSH Setup: Selecciona "Install OpenSSH server"
  15. Haz clic en "Done"
  16. Featured Server Snaps: NO selecciones nada (déjalo vacío)
  17. Haz clic en "Done"
  18. Espera a que termine la instalación
  19. Cuando diga "Installation complete", selecciona "Reboot now"

¡Instalación Completada!

Cuando la VM reinicie y veas una pantalla de login negra pidiendo usuario y contraseña, ¡felicidades! Ubuntu Server está instalado y funcionando.

¿Qué significa sudo?

sudo significa "superuser do" - te da permisos de administrador. Cuando lo usas, el sistema te pedirá tu contraseña.

4.5 Crear un Snapshot (Punto de Restauración)

Antes de continuar, crea un snapshot para poder volver a este estado si algo sale mal:

  1. En la VM, ejecuta: sudo poweroff
  2. En VirtualBox, haz clic derecho en tu VM
  3. Selecciona "Snapshots" → "Tomar snapshot" (Take snapshot)
  4. Nombre: Ubuntu Server - Instalación limpia
  5. Descripción: Ubuntu Server 22.04 LTS recién instalado y actualizado
  6. Haz clic en "Aceptar"

¡Snapshot Creado!

Ahora puedes experimentar sin miedo. Si algo sale mal, solo restaura este snapshot y vuelves al estado inicial.
