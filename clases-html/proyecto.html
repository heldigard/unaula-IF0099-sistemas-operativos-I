🏢 El Caso de Negocio: "UNAULA Cloud Services (UCS)"

🎯 Contexto del Proyecto

Usted ha sido contratado como Ingeniero de Infraestructura para la startup UCS. La empresa necesita desplegar un entorno de servidores locales robusto para hospedar las aplicaciones de sus clientes internos.

Su misión: Construir desde cero un entorno de servidores (Linux y Windows) que sea monitoreable, optimizado, seguro y escalable, utilizando exclusivamente VirtualBox como plataforma de virtualización.

✅ Requerimientos Técnicos Base

  • Hipervisor: VirtualBox 7.x
  • Nodo Linux: Ubuntu Server 22.04 LTS (Sin GUI)
  • Nodo Windows: Windows 10/11 Pro o Windows Server 2022
  • Red: Configuración de Adaptador Puente (Bridge) para visibilidad externa

📊 Modelo de Evaluación

Este curso implementa un proyecto incremental de 6 fases donde cada evaluación corresponde a un resultado de aprendizaje PANDORA. Las evaluaciones son 100% prácticas - no hay exámenes teóricos de memorización.

🎯 Objetivo del Proyecto

🎯 Propósito

Diseñar, implementar y asegurar una infraestructura de servidores híbrida (Linux + Windows) para una empresa ficticia, aplicando todos los conceptos del curso de forma incremental y demostrando competencias reales de administración de sistemas.

🎓 Producto Final

Al finalizar el curso, tendrás un portafolio profesional que demuestra:

  • Servidores Linux y Windows configurados y funcionando
  • Servicios web desplegados (Apache + IIS) con HTTPS
  • Sistema de monitoreo automatizado en funcionamiento
  • Almacenamiento redundante (RAID/Storage Spaces)
  • Documentación técnica completa de infraestructura
  • Scripts de automatización funcionales (Bash + PowerShell)
  • Sistema asegurado con hardening aplicado

🗓️ Las 6 Fases del Proyecto UCS

Cada fase corresponde a una evaluación y está alineada con un Resultado de Aprendizaje (RA) del sistema PANDORA:

🚀 FASE 1: Fundamentos y Arquitectura (E1) - 15%

Fecha: 25 Febrero 2026
RA: RA1 - Identifica estructura y tipos de SO
Tipo: Informe PDF
Clases que alimentan esta fase: C01 Intro al SO C02 Linux Terminal C04 Kernel & Shell

Objetivo: Establecer la base técnica del proyecto. Configurar el entorno de virtualización profesional donde las máquinas virtuales se vean entre sí.

📋 Entregables Checklist:
  • Diagrama de red local con IPs estáticas asignadas a cada VM
  • Tabla comparativa de Sistemas Operativos (Linux vs Windows vs macOS)
  • Justificación técnica de hardware asignado (RAM, CPU, Disco)
  • Instalación base documentada con captura de uname -a y systeminfo
  • Evidencia de conectividad (ping entre VMs funcionando)
🔗 Recursos: Ver resumen ejecutivo → Ver rúbrica →

⚙️ FASE 2: Procesos y Monitoreo (E2) - 15%

Fecha: 11 Marzo 2026
RA: RA2 - Gestiona procesos del SO
Tipo: Scripts + Video
Clases que alimentan esta fase: C05 Procesos Linux C06 Procesos Windows C07 Hilos y Sincronización

Objetivo: Implementar visibilidad operativa. Como ingeniero, no debes entrar a la VM para saber que algo falló; el sistema debe avisarte automáticamente.

📋 Entregables Checklist:
  • Script Bash (monitor.sh) que reporte CPU, RAM y alerte si CPU > 80%
  • Script PowerShell (services.ps1) que vigile el servicio Spooler y lo reinicie si se detiene
  • Configuración de ejecución automática (systemd en Linux, Scheduled Task en Windows)
  • Video demostrando el monitoreo en tiempo real (máx 5 min)
  • Bitácora de pruebas con errores encontrados y soluciones

🔬 FASE 3: Laboratorio de Optimización (E3) - 20%

Fecha: 25 Marzo 2026
RA: RA3 - Administra memoria, E/S, archivos
Tipo: Laboratorio Individual
Clases que alimentan esta fase: C03 Cambio de Contexto C08 Gestión de Memoria C09 Paginación C10 Memoria Virtual C11 Discos y E/S C12 Sistemas de Archivos

Objetivo: Evaluar capacidad de resolver problemas de rendimiento bajo presión. Checkpoint práctico antes de Semana Santa.

⚠️ Importante: Es un laboratorio individual con 5 escenarios técnicos reales proporcionados el día de la sesión. No incluye temas avanzados de sistemas de archivos (RAID, Journaling) - esos van en Fase 5.
📋 Entregables Checklist:
  • PDF de Análisis Forense con 5 escenarios resueltos
  • Cada escenario debe incluir: Problema identificado + Datos que lo prueban + Solución aplicada + Captura del resultado
  • Ejemplos de escenarios: Memory Pressure (fugas de memoria), I/O Bottleneck (cuellos de botella), Forense de archivos (inodos huérfanos)

🔒 FASE 4: Seguridad y Hardening (E4) - 15%

Fecha: 22 Abril 2026
RA: RA4 - Evalúa seguridad de SO
Tipo: Software/Auditoría
Clases que alimentan esta fase: C15 Seguridad Linux C16 Seguridad Windows C17 Servidor Apache (puente de seguridad)

Objetivo: Transformar el sistema de "funcional" a "seguro y a prueba de ataques". Aplicar hardening en ambos sistemas operativos.

📋 Entregables Checklist:
  • Matriz de Riesgos con mínimo 8 vulnerabilidades identificadas y su mitigación técnica
  • Configuración de Firewall (UFW en Linux, Windows Firewall) con reglas específicas
  • ACLs (Access Control Lists) granulares en directorios de datos
  • Evidencia de desactivación de servicios innecesarios
  • Reporte de auditoría con capturas de configuraciones aplicadas

🌐 FASE 5: Integración de Servicios (E5) - 15%

Fecha: 06 Mayo 2026
RA: RA5 - Comprende integración de conceptos
Tipo: Software/Integración
Clases que alimentan esta fase: C13 RAID, Journaling, fstab C14 Servidor IIS C17 Apache y SSL C18 Interoperabilidad Híbrida

Objetivo: Puesta en marcha definitiva. Los nodos Linux y Windows deben colaborar para servir la aplicación web UCS, con almacenamiento redundante y monitoreo end-to-end.

📌 Integración de Temas Avanzados: Esta fase incluye temas de sistemas de archivos avanzados de C13 (RAID, Journaling, fstab) junto con la integración de servicios web.
📋 Entregables Checklist:
  • Video Técnico (máx 5 min): Demostración de Apache HTTPS, IIS, RAID tolerando fallo, y reinicio con montaje automático.
  • Servidor Apache (Linux) con VirtualHost y HTTPS (certificado SSL auto-firmado).
  • Servidor IIS (Windows) con Application Pool dedicado en puerto 8080.
  • Almacenamiento redundante: RAID 1 configurado en Linux con mdadm (2 discos, tolerancia a fallo demostrada).
  • Persistencia: Configuración de /etc/fstab para montaje automático del RAID al reiniciar.
  • Archivos de configuración: VirtualHost Apache, configuración RAID, y fstab.

💡 Simplificación: No es necesario configurar Storage Spaces en Windows ni Dashboard de salud (conceptos ya demostrados en evaluaciones anteriores).

🎓 FASE 6: Sustentación Final (E6) - 20%

Fecha: 27 Mayo 2026
RA: RA6 - Estudia interfaces del SO
Tipo: Presentación/Sustentación Oral
Clases que alimentan esta fase: C19 Documentación Técnica C20 SRE y QA

Objetivo: Defensa profesional de la ingeniería realizada durante el semestre. Demostrar dominio del sistema UCS completo ante el grupo.

📋 Entregables Checklist:
  • Portafolio Ejecutivo: PDF único (máx 20 págs) consolidando Fases 1-5 con correcciones
  • Pitch Técnico: Presentación máximo 8 diapositivas (arquitectura, retos, seguridad, demo)
  • Live Demo: Demostración en vivo del sistema completo funcionando
  • Repositorio Git: Link a GitHub/GitLab con todo el código organizado
  • Manual Técnico: Guía para administrar el sistema
  • Manual de Operación: Procedimientos rutinarios
⏱️ Estructura de la Sustentación (20-25 minutos):
  • Pitch Técnico: 5 minutos
  • Demo Servidores Web: 5 minutos
  • Demo Monitoreo: 5 minutos
  • Tareas en Vivo (solicitadas por docente): 5-8 minutos
  • Preguntas y Defensa: 5 minutos

🧭 Especificación Operativa del Proyecto

📌 Regla de ejecución por fase

Cada fase se evalúa con evidencia verificable en laboratorio. No basta con describir: se debe demostrar en Linux/Windows con comandos, scripts y resultados reproducibles.

Fase Qué debe hacer el estudiante Evidencia obligatoria Cómo se valida
E1 Diseñar arquitectura técnica y justificar decisiones Linux/Windows para el caso de empresa. Diagrama de red, matriz de servicios, justificación técnica. Revisión de consistencia arquitectura↔requisitos y sustentación corta.
E2 Implementar monitoreo de procesos/servicios y control operacional básico. Scripts Bash/PowerShell funcionales + bitácora de pruebas. Ejecución en vivo de scripts con interpretación de salida.
E3 Resolver escenarios de optimización (memoria, E/S, procesos, sincronización, FS básico). Respuestas técnicas + pruebas en VM (hasta C12). Checklist de solución, comandos ejecutados y justificación técnica.
E4 Aplicar hardening y control de acceso en Linux y Windows. Matriz de riesgos, scripts de seguridad, evidencia de políticas activas. Auditoría guiada de configuraciones y verificación de mitigaciones.
E5 Integrar Apache + IIS, almacenamiento avanzado (RAID/fstab de C13) y monitoreo end-to-end. Servicios web accesibles, scripts, reporte de integración, video técnico. Prueba funcional de disponibilidad, seguridad y trazabilidad operativa.
E6 Sustentar el sistema completo con demostración en vivo y defensa técnica. Repositorio final, manual técnico, manual de operación, presentación. Rúbrica de demostración (60%) + defensa/presentación (40%).

✅ Criterio mínimo de aprobación por fase

  • Evidencia ejecutable y reproducible en laboratorio (no solo capturas).
  • Coherencia entre diseño, implementación y resultados observados.
  • Respuesta técnica a preguntas de validación del docente.

📊 Evolución del Proyecto

🔄 Flujo de Trabajo Incremental

  1. Fase 1 (E1): Diseñas la arquitectura → Entregas: Diagrama + justificación
  2. Fase 2 (E2): Implementas monitoreo → Entregas: Scripts + video
  3. Fase 3 (E3): Evaluación de conocimientos → Checkpoint Optimización
  4. Fase 4 (E4): Aseguras el sistema → Entregas: Hardening + auditoría
  5. Fase 5 (E5): Integras servicios web + RAID → Entregas: Proyecto integrado funcionando
  6. Fase 6 (E6): Presentas todo → Sustentación final en vivo

🔗 Conexión entre Fases

Cada fase construye sobre la anterior:

  • Fase 2 implementa lo diseñado en Fase 1
  • Fase 3 valida conocimientos antes de continuar
  • Fase 4 protege lo construido en Fases 1-2
  • Fase 5 integra TODO en un sistema funcional + agrega RAID/fstab de C13
  • Fase 6 muestra el producto final profesional
