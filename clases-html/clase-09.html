1. Introducción a la Paginación

¿Qué es la paginación?

Técnica de gestión de memoria que divide el espacio físico y lógico en bloques de tamaño fijo llamados marcos y páginas respectivamente.

Ventajas sobre la asignación contigua:

  • Elimina la fragmentación externa
  • Permite compartir memoria entre procesos
  • Facilita la implementación de memoria virtual
  • Simplifica la asignación y liberación de memoria

2. Paginación de Memoria

💡 Analogía: La Paginación es como un Libro

Para entender la diferencia entre memoria lógica y física, imagina un libro de texto:

  • Páginas Lógicas: Son las páginas numeradas del libro (1, 2, 3...). Tú, como lector, accedes al contenido por número de página.
  • Marcos Físicos: Son las hojas de papel físicas en las que está impreso el libro.
  • Tabla de Páginas: Es como el Índice al principio del libro. Te dice que el Capítulo 2 (Página lógica 20) está impreso en la Hoja física 45.
  • Offset (Desplazamiento): Es el renglón específico dentro de una página. No importa en qué hoja física se imprima la página, la frase que buscas siempre estará en el mismo renglón relativo.

Conceptos Clave

ConceptoTamañoDescripción
Página4KB (típico)Bloque de memoria lógica
Marco4KB (típico)Bloque de memoria física
Offset12 bitsPosición dentro de la página
Número de página20 bits (x86)Identifica la página

Estructura de una Dirección Lógica

Dirección Lógica (32 bits):
┌─────────────────────────────┬─────────────┐
│   Número de Página (p)      │   Offset(d) │
│       20 bits               │   12 bits   │
└─────────────────────────────┴─────────────┘
         ↓ Tabla de Páginas
Dirección Física (32 bits):
┌─────────────────────────────┬─────────────┐
│   Número de Marco (f)       │   Offset(d) │
│       20 bits               │   12 bits   │
└─────────────────────────────┴─────────────┘
Ejemplo de traducción:
  • Dirección lógica: 0x00401234
  • Número de página: 0x00401 (página 1025)
  • Offset: 0x234 (posición 564)
  • Si el marco es 0x00005 → Dirección física: 0x00005234

3. Tablas de Páginas

La tabla de páginas mapea páginas lógicas a marcos físicos:

Estructura de una Entrada de Tabla de Páginas (PTE)

┌──────────────────────────────────────────────────────────────┐
│ Número de Marco │ Flags (Presente, Modificado, Referenciado) │
│    20 bits      │   Protección (R/W/X), Cache, etc.          │
└──────────────────────────────────────────────────────────────┘

Bits de Control Comunes

BitNombreDescripción
PPresentePágina cargada en memoria física
R/WLectura/EscrituraPermisos de acceso
U/SUsuario/SupervisorNivel de privilegio requerido
AAccedidoPágina ha sido leída
DSucioPágina ha sido modificada

Tablas de Páginas Multinivel

Problema: Una tabla de páginas de un nivel para 32 bits necesitaría 4MB (2^20 entradas × 4 bytes).

Solución: Tablas multinivel (x86 usa 2 niveles, x86-64 usa 4 niveles).

4. TLB (Translation Lookaside Buffer)

El TLB es una caché de traducciones de direcciones que acelera el acceso a memoria:

Funcionamiento

  1. CPU genera dirección lógica
  2. Se busca en TLB (acceso rápido: ~1 ciclo)
  3. Si TLB hit: obtener marco directamente
  4. Si TLB miss: consultar tabla de páginas en RAM (~100 ciclos)
  5. Actualizar TLB con nueva traducción

Rendimiento del TLB

Tiempo de acceso efectivo = (TLB_hit × TLB_time) + (TLB_miss × Memory_time)

Ejemplo:
- TLB hit rate: 98%
- TLB access: 1 ns
- Memory access: 100 ns
- Tiempo efectivo = 0.98 × 1 + 0.02 × 100 = 2.98 ns
TLB hit rate típico: 95-99% gracias a la localidad temporal y espacial.

5. Segmentación

La segmentación divide la memoria en bloques lógicos de tamaño variable:

Segmentos Típicos

SegmentoContenidoCaracterísticas
CódigoInstrucciones del programaRead-only, Ejecutable
DatosVariables globalesLectura/Escritura
PilaVariables locales, parámetrosLectura/Escritura, Crece hacia abajo
HeapMemoria dinámica (malloc)Lectura/Escritura, Crece hacia arriba

Dirección en Segmentación

Dirección Lógica:
┌────────────────────┬──────────────────────────────┐
│  Selector (s)      │         Offset (d)           │
│    16 bits         │         32 bits              │
└────────────────────┴──────────────────────────────┘

Traducción:
1. Selector → Tabla de Segmentos → Base + Límite
2. Verificar: 0 ≤ offset < límite
3. Dirección física = Base + offset

Paginación vs Segmentación

CaracterísticaPaginaciónSegmentación
Tamaño de unidadFijo (4KB)Variable
VisibilidadTransparente al programadorVisible al programador
FragmentaciónInterna (última página)Externa
ProtecciónPor páginaPor segmento
Segmentación paginada: Linux y Windows combinan ambas técnicas. La segmentación divide el espacio lógico y cada segmento se pagina.

6. Práctica en Linux

Comandos para analizar paginación y memoria:

# Ver tamaño de página del sistema
getconf PAGE_SIZE

# Ver información de memoria virtual de un proceso
cat /proc/[PID]/maps

# Ver estadísticas de TLB (si disponible)
cat /proc/vmstat | grep -i tlb

# Ver uso de memoria con detalles de paginación
vmstat -s

# Información detallada de memoria del sistema
cat /proc/meminfo

# Ver tabla de páginas (requiere permisos de root)
sudo cat /proc/[PID]/pagemap

Ejercicios Prácticos de Paginación:

Ejercicio 1: Análisis de Tamaño de Página

Tiempo: 15 minutos

  1. Verificar tamaño de página base: getconf PAGE_SIZE
  2. Verificar si el sistema soporta "Huge Pages": grep -i huge /proc/meminfo
  3. Calcular: Si un proceso usa 1MB de RAM, ¿cuántas páginas de 4KB requiere?
  4. Investigar: ¿Cuál es el beneficio de usar páginas de 2MB (HugePages) en bases de datos?

Ejercicio 2: Simulación de Traducción de Direcciones

Escenario: Sistema de 32 bits, páginas de 4KB (Offset = 12 bits)

Tabla de Páginas: Página 0 -> Marco 5, Página 1 -> Marco 12, Página 2 -> Marco 8

  1. Dirección Lógica: 0x00000500 (Página 0, Offset 0x500) -> ¿Física? _______
  2. Dirección Lógica: 0x00001ABC (Página 1, Offset 0xABC) -> ¿Física? _______
  3. Dirección Lógica: 0x00002001 (Página 2, Offset 0x001) -> ¿Física? _______
Pista: Dirección Física = (Número de Marco * Tamaño de Página) + Offset

Ejercicio 3: Mapa de Memoria Real (Fase 3 Prep)

Objetivo: Identificar segmentos paginados en un proceso real

  1. Lanzar un proceso: top & y anotar su PID
  2. Ver su mapa: cat /proc/[PID]/maps
  3. Identificar la región con permisos r-xp (Código/Texto)
  4. Identificar la región con permisos rw-p (Datos/Heap)
  5. Identificar la región con el nombre [stack]
  6. Calcula el tamaño en KB de la pila (Restar dirección final - dirección inicial)

Ejercicio de Refuerzo: Explorando Paginación

Objetivo: Ver cómo funciona la paginación en tu sistema.

Actividades sugeridas:

  1. Descubre el tamaño de página:
    • Ejecuta: getconf PAGE_SIZE
    • El resultado suele ser 4096 (bytes) = 4KB
    • Este es el tamaño de cada "página" de memoria en tu sistema
  2. Observa el mapa de memoria:
    • Abre una terminal y ejecuta: cat /proc/self/maps
    • Verás direcciones de memoria asignadas a tu propia terminal
    • Cada línea representa una región de memoria
  3. Dibuja la traducción:
    • En una hoja de papel, dibuja: Dirección Lógica → Tabla de Páginas → Dirección Física
    • Divide la dirección lógica en "Número de Página" y "Offset"
    • No tiene que ser perfecto, solo para entender el flujo
Consejo: La paginación puede parecer compleja, pero es solo una forma de organizar la memoria. La práctica la hace más clara.

Actividad Práctica: Paginación Profesional

Actividad 09: Análisis de Memoria Paginada

Objetivo: Ver cómo los SO modernos reportan el tamaño de página y las estadísticas de memoria.

Parte A (Linux):

  1. Use el comando getconf PAGESIZE para identificar el tamaño de página (ej: 4096 bytes).
  2. Inspeccione /proc/meminfo y busque el campo Mapped.

Parte B (Windows):

  1. Abra una consola de PowerShell como Administrador.
  2. Ejecute el comando: Get-WmiObject Win32_PageFileUsage
  3. Identifique el archivo pagefile.sys y su tamaño actual. Este archivo es la extensión de la memoria física mediante paginación a disco.

Entregable: Documentar por qué Windows recomienda que el archivo de paginación sea gestionado por el sistema y no fijado manualmente.
