1. Portafolio Ejecutivo Consolidado

Es el documento maestro que recopila todo el trabajo del semestre. No es una simple unión de archivos, sino un informe profesional corregido.

REQUISITO OBLIGATORIO

Contenido del PDF (Máx 20 páginas):

  • Fase 1: Arquitectura y diseño final.
  • Fase 2: Scripts de monitoreo optimizados.
  • Fase 4: Matriz de riesgos y configuraciones de seguridad aplicadas.
  • Fase 5: Detalles técnicos de la integración Apache/IIS y RAID.
  • Conclusiones: Lecciones aprendidas sobre la gestión de SO.

2. Pitch Técnico (Presentación)

Tienes 20 minutos totales. No gastes tiempo leyendo conceptos; enfócate en el valor técnico de tu solución UCS.

Estructura Recomendada (8 Diapositivas):

  1. Portada y Equipo.
  2. El Problema: Caso UCS y requerimientos.
  3. Arquitectura Híbrida: Diagrama de red y VMs.
  4. Monitoreo y Automatización: Qué scripts crearon y por qué.
  5. Seguridad (Hardening): Cómo protegieron los datos.
  6. Integración Final: Servicios web y almacenamiento.
  7. Resultados: El sistema funcionando.
  8. Conclusiones técnicas.

3. Demostración en Vivo (Live Demo)

Es la parte más importante. El docente solicitará pruebas en tiempo real sobre tus máquinas virtuales.

Posibles retos durante la demo:

  • "Detén un servicio en Windows y muéstrame cómo el script de Linux lo detecta".
  • "Reinicia el servidor Linux y demuestra que el RAID sigue montado".
  • "Cambia el puerto de Apache y actualiza el Firewall en vivo".
  • "Crea un archivo y demuestra que los permisos ACL funcionan para un usuario específico".

4. Repositorio y Manuales

UCS debe ser entregado como un producto listo para ser operado por otros ingenieros.

  • Manual Técnico: Guía de instalación y configuración de las VMs (para quien quiera replicar el proyecto).
  • Manual de Operación: Cómo usar los scripts de monitoreo y cómo reiniciar servicios básicos.
  • Scripts Limpios: Todo el código debe estar comentado y organizado en carpetas.
