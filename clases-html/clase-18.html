1. El Protocolo SMB/CIFS

SMB (Server Message Block) es el lenguaje nativo de Windows para compartir archivos e impresoras. En el mundo Linux, usamos una implementación llamada Samba para hablar este mismo lenguaje.

Casos Profesionales

  • Servidores de archivos empresariales (NAS).
  • Autenticación integrada con Active Directory.
  • Transferencia de backups entre nodos Linux y Windows.

2. NFS (Network File System)

Es el estándar de facto para compartir archivos entre sistemas Unix/Linux. Es mucho más rápido que SMB para pequeñas lecturas constantes (como archivos de código).

ProtocoloOrigenUso Ideal
SMBWindowsRedes de oficina, usuarios humanos.
NFSUnixClusters de servidores, computación de alto rendimiento.

3. Implementación: Samba en Ubuntu

Para que nuestro Nodo Windows pueda leer datos del Nodo Linux, debemos configurar un servidor Samba.

# Instalación
sudo apt install samba -y

# Configuración de un recurso compartido (/etc/samba/smb.conf)
[ucs_files]
   path = /srv/ucs_storage
   read only = no
   browsable = yes
   guest ok = no

# Crear usuario de red (Debe ser usuario local primero)
sudo smbpasswd -a estudiante

4. El reto del mapeo de identidades

Windows usa SIDs (Security Identifiers) y Linux usa UIDs (User IDs). Cuando un archivo pasa de un sistema a otro, el SO debe traducir los permisos.

Pérdida de Atributos

Si mueves un archivo de Linux (EXT4) a un compartido Windows (NTFS) vía SMB, los permisos especiales como SUID o Sticky Bit se perderán porque NTFS no los soporta de la misma manera.

5. Actividad Práctica: La Carpeta Compartida UCS

Laboratorio: Interoperabilidad de Nodos

Objetivo: Compartir una carpeta desde Linux y mapearla como unidad de red en Windows.

Tarea 1: Servidor Samba (Linux)

  1. Cree la carpeta /srv/compartido_ucs.
  2. Configure Samba para compartir esa carpeta.
  3. Reinicie el servicio: sudo systemctl restart smbd.
  4. Permita el puerto 445 en el firewall: sudo ufw allow samba.

Tarea 2: Cliente Windows

  1. Desde su nodo Windows, abra el Explorador de Archivos.
  2. En la barra de direcciones escriba: \\[IP_LINUX]\ucs_files.
  3. Autentíquese con las credenciales creadas en smbpasswd.
  4. Mapeo: Clic derecho en la carpeta → "Conectar a unidad de red". Asígnele la letra S:.

Entregable: Una captura de pantalla de su explorador de Windows mostrando la unidad S: montada y con un archivo creado desde Linux visible dentro.

Casos Reales: Problemas de Interoperabilidad en Producción

Caso 1: Windows No Accede al Recurso Samba

Escenario: El servidor Samba está corriendo pero desde Windows aparece "Windows no puede acceder a \\192.168.x.x\recurso".

Diagnóstico:

# Verificar que Samba está escuchando en el puerto correcto
sudo netstat -tlnp | grep smb

# Probar conectividad desde Linux a Linux
smbclient -L //192.168.x.x -U estudiante

# Ver logs de autenticación
sudo tail -f /var/log/samba/log.smbd

Solución:

# 1. Verificar firewall
sudo ufw status
sudo ufw allow 445/tcp
sudo ufw allow 139/tcp

# 2. Reiniciar Samba
sudo systemctl restart smbd nmbd

# 3. Verificar que el usuario existe en el sistema Y en Samba
sudo pdbedit -L

Caso 2: NFS Monta pero Permission Denied

Escenario: El cliente Linux monta el export NFS pero al acceder dice "Permission denied".

Diagnóstico:

# En el SERVIDOR: Ver exports activos
sudo exportfs -v

# En el CLIENTE: Ver permisos de montaje
mount | grep nfs
ls -ld /mnt/nfs_point

# Verificar UID del usuario en ambos lados
id usuario

Solución:

# En el servidor: Editar /etc/exports para permitir acceso
# Usar opción no_root_squash SI es necesario (con precaución)
/srv/nfs    192.168.1.0/24(rw,sync,no_subtree_check,no_root_squash)

# Luego recargar exports
sudo exportfs -ra

Caso 3: Mapeo de Unidades Windows No Persiste tras Reinicio

Escenario: El usuario mapea la unidad S: pero tras reiniciar Windows debe volver a hacerlo manualmente.

Solución - Opción 1: Script de inicio

# Guardar como conectar_ucs.ps1

net use S: \\192.168.1.100\ucs_files /user:estudiante "contraseña" /persistent:yes
