1. Inodos (Index Nodes)

En Unix/Linux, un archivo no es su nombre. El archivo es su **Inodo**. El nombre es solo un puntero en un directorio hacia un número de inodo.

Metadatos guardados en el inodo

  • UID/GID (Dueño/Grupo).
  • Permisos (rwx).
  • Timestamps (atime, mtime, ctime).
  • Punteros a Bloques: La ubicación física de los bits.

2. Enlaces: Múltiples nombres para un dato

Hard Link

Dos nombres apuntando al **mismo número de inodo**. Si borras el original, el dato sobrevive en el link duro.

Symbolic Link (Symlink)

Un archivo especial que contiene una ruta de texto. Tiene su propio inodo. Si borras el original, el link se rompe.

3. El Estándar Corporativo: EXT4 vs NTFS

CaracterísticaEXT4 (Linux)NTFS (Windows)
JournalingBasado en bloques (Metadata/Data).$LogFile (Transaccional).
MetadataTablas de inodos pre-asignadas.Master File Table (MFT).
SensibilidadCase-Sensitive (A.txt != a.txt).Case-Insensitive.

4. Comandos de Inspección Forense

Auditoría en Linux (Bash)

# Ver número de inodo
ls -li

# Ver toda la info del inodo
stat archivo.txt

# Ver inodos libres en el disco
df -i

# Ver superblock de ext4
sudo tune2fs -l /dev/sda1

# Ver journal interno
sudo debugfs -R "stat <8>" /dev/sda1

Auditoría en Windows (CMD/PS)

# Ver info de NTFS
fsutil fsinfo ntfsinfo C:

# Ver si el volumen está sucio
chkntfs C:

# Ver estadísticas de la MFT
fsutil mft query C:

# Crear Symlink (PowerShell)
New-Item -ItemType SymbolicLink -Path .\link.txt -Target .\original.txt

Casos Reales: Sistemas de Archivos en Producción

Caso 1: Archivo Eliminado Pero Ainda Occupando Espacio

Escenario: Borraste un archivo grande pero el disco sigue igual.

Causa: Otro proceso tiene el archivo abierto.

Solución:

# Linux: Ver archivos borrados pero abiertos
lsof +L1

# Matar el proceso que lo mantiene abierto
kill -9 [PID]

Caso 2: Sistema de Archivos Corrompido Tras Apagón

Escenario: El servidor se apagó inesperadamente. Al iniciar, pide "fsck".

Solución:

  1. Ejecuta fsck -n /dev/sda1 para ver errores sin modificar
  2. Desmonta el filesystem: umount /dev/sda1
  3. Ejecuta reparación: fsck -y /dev/sda1

Prevención: Usar UPS y journaled filesystems (EXT4, XFS, NTFS).

Caso 3: Permisos "Access Denied" en Archivo Compartido

Escenario: Un usuario no puede acceder a un archivo en el servidor de archivos.

Diagnóstico Linux:

# Ver permisos exactos
ls -la /shared/archivo.txt

# Ver Ownership
stat /shared/archivo.txt

# Ver permisos efectivos del usuario
id nombre_usuario
