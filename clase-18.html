1. El Protocolo SMB/CIFS

SMB (Server Message Block) es el lenguaje nativo de Windows para compartir archivos e impresoras. En el mundo Linux, usamos una implementación llamada Samba para hablar este mismo lenguaje.

Casos Profesionales

  • Servidores de archivos empresariales (NAS).
  • Autenticación integrada con Active Directory.
  • Transferencia de backups entre nodos Linux y Windows.

2. NFS (Network File System)

Es el estándar de facto para compartir archivos entre sistemas Unix/Linux. Es mucho más rápido que SMB para pequeñas lecturas constantes (como archivos de código).

ProtocoloOrigenUso Ideal
SMBWindowsRedes de oficina, usuarios humanos.
NFSUnixClusters de servidores, computación de alto rendimiento.

3. Implementación: Samba en Ubuntu

Para que nuestro Nodo Windows pueda leer datos del Nodo Linux, debemos configurar un servidor Samba.

# Instalación
sudo apt install samba -y

# Configuración de un recurso compartido (/etc/samba/smb.conf)
[ucs_files]
   path = /srv/ucs_storage
   read only = no
   browsable = yes
   guest ok = no

# Crear usuario de red (Debe ser usuario local primero)
sudo smbpasswd -a estudiante

4. El reto del mapeo de identidades

Windows usa SIDs (Security Identifiers) y Linux usa UIDs (User IDs). Cuando un archivo pasa de un sistema a otro, el SO debe traducir los permisos.

Pérdida de Atributos

Si mueves un archivo de Linux (EXT4) a un compartido Windows (NTFS) vía SMB, los permisos especiales como SUID o Sticky Bit se perderán porque NTFS no los soporta de la misma manera.

5. Actividad Práctica: La Carpeta Compartida UCS

Laboratorio: Interoperabilidad de Nodos

Objetivo: Compartir una carpeta desde Linux y mapearla como unidad de red en Windows.

Tarea 1: Servidor Samba (Linux)

  1. Cree la carpeta /srv/compartido_ucs.
  2. Configure Samba para compartir esa carpeta.
  3. Reinicie el servicio: sudo systemctl restart smbd.
  4. Permita el puerto 445 en el firewall: sudo ufw allow samba.

Tarea 2: Cliente Windows

  1. Desde su nodo Windows, abra el Explorador de Archivos.
  2. En la barra de direcciones escriba: \\[IP_LINUX]\ucs_files.
  3. Autentíquese con las credenciales creadas en smbpasswd.
  4. Mapeo: Clic derecho en la carpeta → "Conectar a unidad de red". Asígnele la letra S:.

Entregable: Una captura de pantalla de su explorador de Windows mostrando la unidad S: montada y con un archivo creado desde Linux visible dentro.

Casos Reales: Problemas de Interoperabilidad en Producción

Caso 1: Windows No Accede al Recurso Samba

Escenario: El servidor Samba está corriendo pero desde Windows aparece "Windows no puede acceder a \\192.168.x.x\recurso".

Diagnóstico:

# Verificar que Samba está escuchando en el puerto correcto
sudo netstat -tlnp | grep smb

# Probar conectividad desde Linux a Linux
smbclient -L //192.168.x.x -U estudiante

# Ver logs de autenticación
sudo tail -f /var/log/samba/log.smbd

Solución:

# 1. Verificar firewall
sudo ufw status
sudo ufw allow 445/tcp
sudo ufw allow 139/tcp

# 2. Reiniciar Samba
sudo systemctl restart smbd nmbd

# 3. Verificar que el usuario existe en el sistema Y en Samba
sudo pdbedit -L

Caso 2: NFS Monta pero Permission Denied

Escenario: El cliente Linux monta el export NFS pero al acceder dice "Permission denied".

Diagnóstico:

# En el SERVIDOR: Ver exports activos
sudo exportfs -v

# En el CLIENTE: Ver permisos de montaje
mount | grep nfs
ls -ld /mnt/nfs_point

# Verificar UID del usuario en ambos lados
id usuario

Solución:

# En el servidor: Editar /etc/exports para permitir acceso
# Usar opción no_root_squash SI es necesario (con precaución)
/srv/nfs    192.168.1.0/24(rw,sync,no_subtree_check,no_root_squash)

# Luego recargar exports
sudo exportfs -ra

Caso 3: Mapeo de Unidades Windows No Persiste tras Reinicio

Escenario: El usuario mapea la unidad S: pero tras reiniciar Windows debe volver a hacerlo manualmente.

Solución - Opción 1: Script de inicio

# Crear script de conexión automática
# Guardar como conectar_ucs.ps1

net use S: \\192.168.1.100\ucs_files /user:estudiante "contraseña" /persistent:yes
"@
Invoke-Expression $netUse

Escenarios Empresariales: Migración de Datos entre Linux y Windows

Escenario 1: Migración de Servidor de Archivos Legacy

  • Situación: Empresa migrando de Windows Server 2008 a Ubuntu 22.04 LTS.
  • Desafío: Preservar permisos, shares, y políticas de acceso.
  • Solución: Usar robocopy para backup, luego Samba para replicar estructura.
# En Windows: Backup de permisos
robocopy "\\servidor\compartido" "D:\backup" /E /COPYALL /LOG:backup.log

# En Linux: Restaurar con rsync manteniendo permisos
rsync -av --progress /mnt/backup/ /srv/compartido/

Escenario 2: Integración de Datos entre Departamentos

  • Situación: Departamento de Finanzas usa Windows, Ingeniería usa Linux.
  • Desafío: Compartir datos en tiempo real sin duplicar.
  • Solución: Servidor Samba como punto central, accesible desde ambos sistemas.

Configuración de Active Directory con Clientes Linux

Pasos para unir Linux a dominio Windows:

# 1. Instalar paquetes necesarios
sudo apt update
sudo apt install realmd sssd sssd-tools libnss-sss libpam-sss adcli samba-common-bin

# 2. Descubrir el dominio
realm discover CORPORATIVO.LOCAL

# 3. Unirse al dominio (interactivo)
sudo realm join CORPORATIVO.LOCAL -U administrador

# 4. Verificar unión
realm list

# 5. Permitir inicio de sesión con usuarios del dominio
sudo realm permit -g "Domain Users"

# 6. Configurar SSSD (/etc/sssd/sssd.conf)
[sssd]
domains = CORPORATIVO.LOCAL
config_file_version = 2
services = nss, pam

[domain/CORPORATIVO.LOCAL]
default_shell = /bin/bash
krb5_store_password_if_offline = True
cache_credentials = True
id_provider = ad
auth_provider = ad
access_provider = ad

# 7. Reiniciar SSSD
sudo systemctl restart sssd

# 8. Verificar autenticación
id usuario@CORPORATIVO.LOCAL

# 9. Configurar sudo para usuarios del dominio
sudo visudo
# Agregar: %domain\ admins@CORPORATIVO.LOCAL ALL=(ALL:ALL) ALL

Compartir Impresoras en Red Heterogénea

Configuración en Linux (CUPS):

# 1. Instalar CUPS
sudo apt install cups cups-bsd

# 2. Configurar CUPS para compartir (/etc/cups/cupsd.conf)
# Permitir acceso desde red local

  Order allow,deny
  Allow from 192.168.1.0/24


# 3. Habilitar compartir impresoras
Browsing On
BrowseLocalProtocols dnssd
DefaultAuthType Basic

# 4. Reiniciar CUPS
sudo systemctl restart cups

# 5. Agregar impresora
sudo lpadmin -p HP_LaserJet -E -v socket://192.168.1.100 -m everywhere
sudo lpadmin -d HP_LaserJet  # Establecer como predeterminada

# 6. Compartir impresora
sudo lpadmin -p HP_LaserJet -o printer-is-shared=true

# 7. Verificar estado
lpstat -p -d

Acceso desde Windows:

  1. Ir a Configuración → Impresoras → Agregar impresora.
  2. Seleccionar "La impresora que quiero no está en la lista".
  3. Seleccionar "Seleccionar una impresora compartida por nombre".
  4. URL: http://192.168.1.10:631/printers/HP_LaserJet
  5. Instalar driver correspondiente.

Acceso desde Linux a impresora Windows:

# Usando smbspool
sudo lpadmin -p Windows_Printer -E -v smb://usuario:password@windows-pc/ImpresoraHP -m raw

# O usando GUI de CUPS
# http://localhost:631/admin

Ejercicios Prácticos: Configuración Completa de SAMBA

# /etc/samba/smb.conf - Configuración empresarial completa

[global]
# Nombre del servidor
workgroup = CORPORATIVO
server string = Servidor UCS Samba %v
netbios name = UCS-SERVER

# Seguridad
security = user
encrypt passwords = yes
smb encrypt = required
min protocol = SMB2
max protocol = SMB3

# Logs
log file = /var/log/samba/log.%m
max log size = 1000
logging = file

# Rendimiento
socket options = TCP_NODELAY SO_RCVBUF=131072 SO_SNDBUF=131072
read raw = yes
write raw = yes

# Soporte para ACLs
vfs objects = acl_xattr
map acl inherit = yes
store dos attributes = yes

#====================== Recursos Compartidos =====================

[publico]
comment = Carpeta Pública
path = /srv/samba/publico
browsable = yes
writable = yes
guest ok = yes
read only = no
force user = nobody
force group = nogroup
force create mode = 0664
force directory mode = 0775

[departamentos]
comment = Carpetas de Departamentos
path = /srv/samba/departamentos
browsable = yes
writable = yes
guest ok = no
valid users = @finanzas @ingenieria @ventas
read only = no
inherit permissions = yes

[finanzas]
comment = Departamento de Finanzas
path = /srv/samba/departamentos/finanzas
browsable = yes
writable = yes
guest ok = no
valid users = @finanzas
read only = no
force group = finanzas
create mask = 0660
directory mask = 0770

[ingenieria]
comment = Departamento de Ingeniería
path = /srv/samba/departamentos/ingenieria
browsable = yes
writable = yes
guest ok = no
valid users = @ingenieria
read only = no
force group = ingenieria
create mask = 0660
directory mask = 0770

[backups]
comment = Backups del Sistema
path = /srv/samba/backups
browsable = no
writable = yes
guest ok = no
valid users = @admin
read only = no
create mask = 0600
directory mask = 0700

[homes]
comment = Home Directories
browseable = no
writable = yes
guest ok = no
valid users = %S
read only = no
create mask = 0700
directory mask = 0700

Script de configuración completa:

#!/bin/bash
# setup-samba.sh - Configuración completa de Samba

# Crear estructura de directorios
sudo mkdir -p /srv/samba/{publico,departamentos/{finanzas,ingenieria,ventas},backups}

# Crear grupos
sudo groupadd finanzas
sudo groupadd ingenieria
sudo groupadd ventas
sudo groupadd admin

# Crear usuarios locales y Samba
sudo useradd -m -G finanzas juan.finanzas
sudo useradd -m -G ingenieria maria.ingenieria
sudo useradd -m -G admin admin

# Crear usuarios Samba (contraseñas diferentes a las del sistema)
sudo smbpasswd -a juan.finanzas
sudo smbpasswd -a maria.ingenieria
sudo smbpasswd -a admin

# Establecer permisos
sudo chown -R nobody:nogroup /srv/samba/publico
sudo chmod -R 755 /srv/samba/publico

sudo chown root:finanzas /srv/samba/departamentos/finanzas
sudo chmod 770 /srv/samba/departamentos/finanzas

sudo chown root:ingenieria /srv/samba/departamentos/ingenieria
sudo chmod 770 /srv/samba/departamentos/ingenieria

sudo chown root:admin /srv/samba/backups
sudo chmod 700 /srv/samba/backups

# Configurar SELinux/AppArmor si está activo
sudo setfacl -R -m g:finanzas:rwx /srv/samba/departamentos/finanzas
sudo setfacl -R -m g:ingenieria:rwx /srv/samba/departamentos/ingenieria

# Reiniciar Samba
sudo systemctl restart smbd nmbd

# Verificar configuración
testparm

echo "✅ Configuración de Samba completada exitosamente"

Acceso a Recursos Windows desde Linux y Viceversa

Desde Linux a Windows:

# Usando smbclient - Listar recursos compartidos
smbclient -L //192.168.1.100 -U usuario

# Conectarse a recurso compartido
smbclient //192.168.1.100/compartido -U usuario

# Montar recurso Windows en Linux
sudo mount -t cifs //192.168.1.100/compartido /mnt/windows \
    -o username=usuario,password=contraseña,uid=1000,gid=1000

# Montaje permanente (fstab)
//192.168.1.100/compartido  /mnt/windows  cifs  credentials=/home/usuario/.smbcredentials,uid=1000,gid=1000,iocharset=utf8,sec=ntlmssp  0  0

# Archivo .smbcredentials
username=usuario
password=contraseña
domain=CORPORATIVO

Desde Windows a Linux:

# Usando PowerShell - Conectar unidad de red
New-PSDrive -Name "S" -PSProvider FileSystem -Root "\\192.168.1.10\compartido" -Credential (Get-Credential) -Persist

# Mapeo persistente con net use
net use S: \\192.168.1.10\compartido /user:usuario contraseña /persistent:yes

# Desconectar
net use S: /delete

Resolución de Problemas de Permisos en Entornos Mixtos

Problema 1: Permisos de archivos creados desde Windows no se ven desde Linux

  • Causa: Mapeo de permisos NTFS a Unix no está configurado.
  • Solución: Configurar create mask, directory mask, y force user/group en smb.conf.

Problema 2: Usuario puede escribir desde Windows pero no desde Linux

  • Diagnóstico: Verificar permisos Unix del directorio físico.
  • Solución: Asegurar que los permisos Unix permitan escritura al grupo.
# Verificar permisos Unix
ls -la /srv/samba/compartido/

# Corregir permisos
sudo chown -R root:sambashare /srv/samba/compartido/
sudo chmod -R 2770 /srv/samba/compartido/
# (2 = setgid, nuevo archivo hereda grupo del directorio)

Problema 3: Archivos con espacios o caracteres especiales

  • Solución: Usar comillas y escape adecuado.
# Ejemplo correcto
smbclient //servidor/compartido -c "get 'documento importante.pdf'"

# Montar con caracteres especiales
sudo mount -t cifs //servidor/compartido /mnt/punto -o "iocharset=utf8"

Problema 4: Autenticación falla aunque credenciales sean correctas

  • Verificar que el usuario existe en Samba: sudo pdbedit -L
  • Verificar sincronización de contraseñas: sudo smbpasswd usuario
  • Verificar que no hay conflictos con NTLM: agregar sec=ntlmssp en opciones de montaje.

Caso Real: "Cómo Netflix Maneja la Interoperabilidad"

Arquitectura de Netflix:

  • Servidores: Miles de instancias Linux (Amazon EC2).
  • Estaciones de trabajo: Windows y macOS para empleados.
  • Desafío: Acceso seguro y eficiente a recursos entre todos los sistemas.

Soluciones implementadas:

  1. Single Sign-On (SSO): Usan OAuth 2.0 y SAML para autenticación unificada.
  2. Protocolos estándar: SMB3 con encriptación para compartir archivos.
  3. Contenedores: Docker corre en Linux, accesible desde Windows vía WSL2.
  4. Infraestructura como Código: Terraform y Ansible funcionan en Linux, administrados desde cualquier SO.

Lecciones aplicables al proyecto UCS:

  • Usar protocolos estándar (SMB, NFS, HTTP/HTTPS) en lugar de soluciones propietarias.
  • Implementar autenticación centralizada (LDAP/AD) si el entorno crece.
  • Documentar toda la configuración para facilitar el mantenimiento.
  • Automatizar configuraciones con scripts reutilizables.
