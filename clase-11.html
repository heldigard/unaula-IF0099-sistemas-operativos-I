1. Estructura Interna del Filesystem

┌──────────────────────────────────────┐
│         SUPERBLOQUE                   │
├──────────────────────────────────────┤
│    Bitmaps (bloques / inodos libres)  │
├──────────────────────────────────────┤
│         Tabla de Inodos               │
├──────────────────────────────────────┤
│         Bloques de Datos              │
└──────────────────────────────────────┘

📋 Superblock

  • Tamaño total del FS
  • Tipo de filesystem
  • Estado (clean/dirty)
  • Contadores de bloques libres

🗺️ Bitmaps

  • Bitmap de bloques libres
  • Bitmap de inodos libres
  • 1 bit = 1 bloque/inodo
  • Bit 1 = ocupado, 0 = libre

📁 Inodos

  • Metadatos de archivos
  • Permisos y propietario
  • Tamaños y timestamps
  • Punteros a bloques de datos

💾 Bloques de Datos

  • Contenido real de archivos
  • Tamaño típico: 4KB
  • No guardan nombres
  • Se acceden vía inodos
Idea clave: El filesystem separa metadatos (inodos) de datos (bloques). Los directorios solo apuntan a inodos, no a datos directamente.

2. ¿Qué es un Inodo?

┌─────────────────────────────────┐
│         INODO #12345            │
├─────────────────────────────────┤
│ Tipo: Archivo regular           │
│ Permisos: -rw-r--r-- (644)      │
│ Propietario: UID 1000           │
│ Grupo: GID 1000                 │
│ Tamaño: 4,096 bytes             │
│ Fecha creación: 2026-01-31      │
│ Fecha modificación: 2026-01-31  │
│ Último acceso: 2026-01-31       │
│ Links: 1                        │
│ Bloques usados: 8               │
│ ┌─────────────────────────────┐ │
│ │  PUNTEROS A BLOQUES:        │ │
│ │  • Directos (12): → Bloques │ │
│ │  • Indirecto simple: → Tabla│ │
│ │  • Indirecto doble: → Tabla │ │
│ │  • Indirecto triple: → Tabla│ │
│ └─────────────────────────────┘ │
└─────────────────────────────────┘
Regla clave: El nombre del archivo está en el directorio, no en el inodo. El inodo contiene todos los metadatos excepto el nombre.

Campos del Inodo

Campo Descripción
modeTipo de archivo y permisos (rwx)
uidID del usuario propietario
gidID del grupo propietario
sizeTamaño en bytes
atimeTiempo de último acceso
mtimeTiempo de última modificación
ctimeTiempo de cambio de metadatos
linksContador de hard links

block[15]Punteros a bloques de datos

Directorios como Tablas

NombreInodo
documento.txt1052
foto.jpg2048
proyecto/3021
Concepto importante: Un directorio es simplemente un archivo especial que contiene una tabla de mapeo nombre → inodo.

Cuando ejecutas cat archivo.txt:

  1. El kernel busca "archivo.txt" en el directorio actual
  2. Encuentra el número de inodo (ej: 12345)
  3. Carga el inodo 12345 desde la tabla de inodos
  4. Lee los punteros a bloques del inodo
  5. Carga los bloques de datos y muestra el contenido

3. Asignación de Espacio en Disco

📦 Contigua

  • Idea: Bloques consecutivos
  • Ventaja: Acceso secuencial rápido
  • Desventaja: Fragmentación externa
  • Difícil de: Expandir archivos
[████████][████████][████████] Bloque 100 → 101 → 102

🔗 Enlazada

  • Idea: Cada bloque apunta al siguiente
  • Ventaja: Fácil crecer
  • Desventaja: Acceso secuencial lento
  • No hay: Acceso directo
[→102] [→205] [→410] 100 207 512

📑 Indexada

  • Idea: Bloque índice con punteros
  • Ventaja: Acceso directo
  • Ventaja: Fácil crecer
  • Desventaja: Usa bloques extra
Inodo → [Índice] [100,207,512,620] ↑ ↑ ↑ ↑ Datos...
Unix/Linux usa asignación indexada con múltiples niveles: punteros directos, indirecto simple, doble y triple.

4. Ejemplo: ext4 (Linux)

El filesystem ext4 es el estándar en muchas distribuciones Linux. Combina varias técnicas optimizadas:

📝 Journaling

  • Transacciones de metadatos
  • Recuperación rápida tras crash
  • Journal circular en disco
  • Garantiza consistencia

📊 Extents

  • Reemplaza bitmap clásico
  • Un extent = bloque contiguo
  • Reduce fragmentación
  • Hasta 128KB por extent

⚙️ Características

  • Bloques típicos: 4KB
  • Max tamaño: 16TB
  • Max archivo: 16TB
  • Subsegundos en timestamps

🎯 Ventaja Principal de ext4

Rápido y confiable para servidores. El journaling protege contra corrupción, los extents reducen fragmentación, y las técnicas de asignación indexada permiten archivos gigantes con acceso rápido.

5. Detalles Avanzados de Inodos

Un inodo (index node) es una estructura de datos que contiene metadatos sobre un archivo, excepto su nombre y datos reales.

Estructura de Punteros del Inodo

Cada inodo tiene 15 punteros:

  • 12 punteros directos → apuntan directamente a bloques de datos
  • 1 puntero indirecto simple → apunta a un bloque con punteros
  • 1 puntero indirecto doble → dos niveles de indirección
  • 1 puntero indirecto triple → tres niveles de indirección

Con bloques de 4KB:

Tipo de Puntero Cantidad Capacidad
Directos12 bloques48 KB
Indirecto simple1×1024 bloques4 MB
Indirecto doble1024² bloques4 GB
Indirecto triple1024³ bloques4 TB
Total-≈4 TB

5.1 Punteros Directos (12)

Apuntan directamente a bloques de datos. Sin indirección.

Inodo #12345
  │
  ├─→ Bloque 1001  [4KB de datos]
  ├─→ Bloque 1002  [4KB de datos]
  ├─→ Bloque 1003  [4KB de datos]
  ├─→ Bloque 1004  [4KB de datos]
  ├─→ Bloque 1005  [4KB de datos]
  ├─→ Bloque 1006  [4KB de datos]
  ├─→ Bloque 1007  [4KB de datos]
  ├─→ Bloque 1008  [4KB de datos]
  ├─→ Bloque 1009  [4KB de datos]
  ├─→ Bloque 1010  [4KB de datos]
  ├─→ Bloque 1011  [4KB de datos]
  └─→ Bloque 1012  [4KB de datos]

Capacidad: 12 × 4KB = 48 KB
⚡ Uso: Archivos pequeños (<48 KB) se acceden directamente, muy rápido. Un solo acceso a disco para leer el inodo, y accesos directos a los bloques.

5.2 Puntero Indirecto Simple

Apunta a un bloque que contiene punteros a bloques de datos.

Inodo #12345
  │
  └─→ Bloque 5000 [Bloque Indirecto - 1024 punteros]
       ├─→ Bloque 2001  [4KB de datos]
       ├─→ Bloque 2002  [4KB de datos]
       ├─→ Bloque 2003  [4KB de datos]
       ├─→ ...
       └─→ Bloque 3024  [4KB de datos]

Capacidad adicional: 1024 × 4KB = 4 MB
Total acumulado: 48 KB + 4 MB = 4.048 MB
Nota: Para leer un byte en esta región se necesitan 2 accesos a disco: 1) leer el bloque indirecto, 2) leer el bloque de datos.

5.3 Puntero Indirecto Doble

Apunta a un bloque con punteros a bloques de punteros que apuntan a datos.

Inodo #12345
  │
  └─→ Bloque 6000 [Bloque Indirecto Doble]
       ├─→ Bloque 6001 [Indirecto 1: 1024 punteros]
       │    ├─→ Bloque datos
       │    ├─→ Bloque datos
       │    ├─→ ...
       │    └─→ Bloque datos (1024 bloques)
       │
       ├─→ Bloque 6002 [Indirecto 2: 1024 punteros]
       │    └─→ ...
       │
       └─→ Bloque 7000 [Indirecto 1024: 1024 punteros]

Capacidad: 1024 × 1024 × 4KB = 4 GB
Total acumulado: 48 KB + 4 MB + 4 GB ≈ 4.04 GB
Costo de acceso: 3 accesos a disco para leer un byte (indirecto doble → indirecto simple → bloque de datos).

5.4 Puntero Indirecto Triple

Para archivos MUY grandes (>4 GB).

Inodo
  │
  └─→ [Indirecto Triple]
       ├─→ [Indirecto Doble 1]
       │    └─→ [Indirecto Simple 1]
       │         └─→ [Bloques de datos: 1024]
       │
       ├─→ [Indirecto Doble 2]
       │    └─→ ...
       │
       └─→ [Indirecto Doble 1024]
            └─→ ...

Capacidad: 1024³ × 4KB = 4 TB
📊 Total máximo teórico: 48 KB + 4 MB + 4 GB + 4 TB ≈ 4 TB por archivo

# Entrar en modo debug del filesystem
sudo debugfs /dev/sda1

🔗 Hard Links vs Symbolic Links

🔗 Hard Link

Mismo inodo, contador de links incrementado.

ln archivo.txt hardlink.txt
Directorio: "archivo.txt" → Inodo 12345 "hardlink.txt" → Inodo 12345 Inodo 12345: Links: 2 ← Contador aumenta

Eliminación: Solo se borra cuando Links = 0

🔀 Symbolic Link (Soft Link)

Nuevo inodo que contiene la ruta como texto.

ln -s archivo.txt symlink.txt
Directorio: "archivo.txt" → Inodo 12345 "symlink.txt" → Inodo 67890 Inodo 67890 (symlink): Datos: "archivo.txt"

Riesgo: Si se borra el original, el symlink queda "roto"

Aspecto Hard Link Symbolic Link
InodoMismo inodoNuevo inodo
Contador de linksIncrementaNo afecta
Funciona entre filesystemsNoSí
Apunta a directoriosNo (generalmente)Sí
Si borran el originalSigue accesibleLink roto

Actividad: Exploración de Inodos y Links

Ejercicio 1: Observar Inodos

# 1. Crear archivo de prueba
echo "Hola mundo" > test.txt

# 2. Ver su inodo
ls -i test.txt
# Anota el número: __________

# 3. Ver detalles completos
stat test.txt

# 4. Crear hard link
ln test.txt test_hardlink.txt

# 5. Verificar que tienen el mismo inodo
ls -i test*.txt

# 6. Ver contador de links
stat test.txt | grep Links
# Debe mostrar: Links: 2

Ejercicio 2: Hard Link vs Soft Link

# 1. Crear archivo original
echo "Contenido original" > original.txt

# 2. Crear hard link y soft link
ln original.txt hard.txt
ln -s original.txt soft.txt

# 3. Ver inodos (¿cuáles son iguales?)
ls -i original.txt hard.txt soft.txt

# 4. Eliminar el original
rm original.txt

# 5. Intentar leer ambos links
cat hard.txt      # ¿Funciona?
cat soft.txt      # ¿Funciona?

# 6. Explica: ¿Por qué uno funciona y otro no?

Ejercicio 3: Límite de Inodos

# Ver total de inodos en el filesystem
df -i

# Salida ejemplo:
# Filesystem      Inodes  IUsed   IFree IUse% Mounted on
# /dev/sda1      6000000 500000 5500000    9% /
Pregunta: ¿Qué pasa si IUse% llega a 100%, aunque haya espacio en disco?
Respuesta: No se pueden crear más archivos, aunque haya espacio libre. Cada archivo necesita un inodo. Es posible quedarse sin inodos antes de quedarse sin espacio en disco.

🎯 Concepto Fundamental

En Unix/Linux, todo es un archivo, y cada archivo tiene un inodo que contiene sus metadatos. Los nombres solo existen en los directorios, que mapean nombres a números de inodo. Esta separación permite hard links, renombrados rápidos y una estructura flexible.
