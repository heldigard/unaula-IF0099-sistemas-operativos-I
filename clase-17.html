1. ¿Qué es Apache HTTP Server?

Es el servidor web de código abierto más veterano y flexible del mercado. Su diseño se basa en un núcleo ligero que se extiende mediante **Módulos** cargables. A diferencia de IIS, Apache se configura mediante archivos de texto.

Filosofía de Configuración

En Linux Ubuntu, la configuración se divide para facilitar el mantenimiento:

  • /etc/apache2/apache2.conf: Archivo maestro.
  • sites-available/: Sitios web que "podrían" existir.
  • sites-enabled/: Sitios web que el servidor está sirviendo actualmente (links simbólicos).

2. Virtual Hosting: Múltiples dominios, un IP

Permite a una empresa alojar miles de dominios en un solo servidor físico.

# Estructura de un Virtual Host en /etc/apache2/sites-available/ucs.conf
<VirtualHost *:80>
    ServerName ucs.local
    DocumentRoot /var/www/ucs/html
    ErrorLog ${APACHE_LOG_DIR}/ucs_error.log
</VirtualHost>

3. Módulos y MPMs (Multi-Processing Modules)

Define cómo Apache usa la CPU y la RAM para atender miles de peticiones:

  • Event: (Estándar moderno) Usa hilos optimizados para conexiones persistentes.
  • Prefork: Usa un proceso por cada usuario. Muy estable pero consume mucha RAM.
  • Worker: Híbrido entre procesos e hilos.

4. Seguridad y SSL (HTTPS)

Usamos **TLS/SSL** para cifrar la comunicación. El puerto estándar es el 443.

  • Certificado (.crt): Documento público que identifica al servidor.
  • Llave Privada (.key): Código secreto que el servidor usa para descifrar datos. Debe protegerse con permisos 600.

5. Comandos de Gestión y Auditoría

Mantenimiento (Bash)

# Habilitar un sitio nuevo
sudo a2ensite ucs.conf

# Deshabilitar el sitio default
sudo a2dissite 000-default.conf

# Habilitar módulo de seguridad SSL
sudo a2enmod ssl

# Validar errores de sintaxis
sudo apache2ctl configtest

Diagnóstico en Vivo

# Ver sitios cargados en RAM
sudo apache2ctl -S

# Ver hilos de Apache en tiempo real
top -H -p $(pgrep apache2 | head -1)

# Ver ataques o errores en vivo
sudo tail -f /var/log/apache2/error.log

# Ver visitas en tiempo real
sudo tail -f /var/log/apache2/access.log

Casos Reales: Apache en Producción

Caso 1: Apache No Inicia tras Cambio de Config

Escenario: Después de modificar el archivo de configuración, Apache no quiere iniciar. Muestra "Syntax error".

Diagnóstico:

# Validar sintaxis sin iniciar
sudo apache2ctl configtest

# Ver error específico
sudo apachectl -t

# Si hay error en VirtualHost, revisar /var/log/apache2/error.log

Caso 2: Servidor Lento con Muchas Conexiones

Escenario: El servidor responde lento cuando hay más de 100 usuarios simultáneos.

Diagnóstico:

# Ver consumo de memoria por proceso Apache
ps aux | grep apache2 | awk '{sum+=$6} END {print sum/1024 " MB"}'

# Ver número de conexiones establecidas
netstat -tun | grep :80 | wc -l

# Cambiar MPM de Prefork a Event para mejor rendimiento
sudo a2dismod mpm_prefork
sudo a2enmod mpm_event

Caso 3: Error 403 Forbidden en Archivo Existente

Escenario: Los usuarios ven "403 Forbidden" al acceder a archivos que definitely existen.

Causa: Permisos incorrectos en la carpeta o archivo .htaccess restrictivo.

Solución:

# Verificar permisos (debe ser al menos 755 en carpetas, 644 en archivos)
ls -la /var/www/ucs/

# Verificar que Apache tiene permiso de ejecución en toda la ruta
namei -l /var/www/ucs/index.html

# Si usa .htaccess, verificar que AllowOverride está configurado

Troubleshooting SSL: Errores Comunes de Certificados

Error 1: ERR_CERT_AUTHORITY_INVALID

  • Causa: Certificado auto-firmado o CA no confiable.
  • Solución: En desarrollo: curl -k https://localhost. En producción: Usar certificado de Let's Encrypt o CA reconocida.

Error 2: ERR_CERT_DATE_INVALID

  • Causa: Certificado expirado o fecha del sistema incorrecta.
  • Solución: Verificar fecha: date. Renovación: sudo certbot renew (Let's Encrypt).

Error 3: SSL_ERROR_RX_RECORD_TOO_LONG

  • Causa: Puerto 443 sirviendo HTTP en lugar de HTTPS.
  • Solución: Verificar VirtualHost en /etc/apache2/sites-available/default-ssl.conf.

Error 4: SSL_ERROR_HANDSHAKE_FAILURE

  • Causa: Incompatibilidad de protocolos TLS (cliente vs servidor).
  • Solución: Configurar protocolos TLS 1.2+ en Apache.

Análisis con OpenSSL s_client para Diagnosticar Problemas

# 1. Verificar conexión SSL básica
openssl s_client -connect localhost:443 -servername ucs.local

# 2. Verificar certificado y cadena de confianza
openssl s_client -connect localhost:443 -showcerts /dev/null | 
    openssl x509 -noout -dates

# 5. Extraer información completa del certificado
echo | openssl s_client -connect localhost:443 2>/dev/null | 
    openssl x509 -noout -subject -issuer -dates -fingerprint

# 6. Verificar vulnerabilidades conocidas (Heartbleed, etc.)
nmap --script ssl-heartbleed,ssl-poodle,ssl-dh-params -p 443 localhost

# 7. Test de configuración SSL con SSL Labs (desde otra máquina)
# https://www.ssllabs.com/ssltest/

Optimización: Configuración de Apache para Alto Rendimiento

MPM Event (Recomendado para producción):

# /etc/apache2/mods-available/mpm_event.conf

    StartServers             3
    MinSpareThreads         25
    MaxSpareThreads         75
    ThreadLimit             64
    ThreadsPerChild         25
    MaxRequestWorkers      400
    MaxConnectionsPerChild   0

Configuración de Caching:

# Habilitar módulos
sudo a2enmod expires
sudo a2enmod headers

# /etc/apache2/conf-available/performance.conf

    ExpiresActive On
    ExpiresByType image/jpeg "access plus 1 month"
    ExpiresByType image/png "access plus 1 month"
    ExpiresByType text/css "access plus 1 week"
    ExpiresByType application/javascript "access plus 1 week"



    # Habilitar compresión Gzip
    
        AddOutputFilterByType DEFLATE text/html text/plain text/css application/javascript
    
    
    # Headers de caché
    
        Header set Cache-Control "max-age=2592000, public"

Keep-Alive y Timeouts:

# /etc/apache2/apache2.conf
KeepAlive On
MaxKeepAliveRequests 100
KeepAliveTimeout 5

# Timeouts
Timeout 300
RequestReadTimeout header=20-40,MinRate=500 body=20,MinRate=500

Seguridad: Headers de Seguridad HTTP

# /etc/apache2/conf-available/security-headers.conf

    # Prevenir clickjacking
    Header always set X-Frame-Options "SAMEORIGIN"
    
    # Prevenir MIME sniffing
    Header always set X-Content-Type-Options "nosniff"
    
    # Habilitar protección XSS del navegador
    Header always set X-XSS-Protection "1; mode=block"
    
    # Política de Referrer
    Header always set Referrer-Policy "strict-origin-when-cross-origin"
    
    # Content Security Policy (CSP)
    Header always set Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';"
    
    # HTTPS Strict Transport Security (HSTS)
    Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
    
    # Ocultar versión de Apache
    ServerTokens Prod
    ServerSignature Off

Protección contra Ataques Comunes

Protección contra DDoS básica con mod_evasive:

# Instalación: sudo apt install libapache2-mod-evasive

# /etc/apache2/mods-available/evasive.conf

    DOSHashTableSize    3097
    DOSPageCount        2
    DOSSiteCount        50
    DOSPageInterval     1
    DOSSiteInterval     1
    DOSBlockingPeriod   600
    
    DOSEmailNotify      admin@ucs.local
    DOSLogDir           "/var/log/mod_evasive"

Protección contra fuerza bruta con mod_security:

# Instalación: sudo apt install libapache2-mod-security2

# /etc/modsecurity/modsecurity.conf
SecRuleEngine On
SecRequestBodyAccess On
SecResponseBodyAccess On

# Limitar tamaño de requests
SecRequestBodyLimit 13107200
SecRequestBodyNoFilesLimit 131072

# Prevenir SQL Injection básico
SecRule REQUEST_COOKIES|REQUEST_COOKIES_NAMES|REQUEST_FILENAME|ARGS_NAMES|ARGS|XML:/* \
    "@rx (?i:(select\s*\*\s*from|union\s*select|insert\s*into|delete\s*from|drop\s*table))" \
    "id:942100,phase:2,deny,status:403,msg:'SQL Injection Attack Detected'"

Casos Reales: Configuraciones de Servidores Web en Empresas

Caso 1: Configuración de Netflix (High Traffic)

  • Balanceo de carga con múltiples instancias de Apache.
  • Caching agresivo con Varnish delante de Apache.
  • HTTP/2 habilitado para multiplexar conexiones.
# Habilitar HTTP/2
sudo a2enmod http2

# En VirtualHost
Protocols h2 http/1.1

Caso 2: Configuración de WordPress.com (Shared Hosting)

  • Separación de PHP-FPM para aislamiento de usuarios.
  • Limitación de recursos por VirtualHost.
  • Monitoreo en tiempo real con mod_status.
# Monitoreo de Apache

    SetHandler server-status
    Require host localhost

Caso 3: Configuración de GitHub (Static Assets)

  • CDN para contenido estático.
  • Compresión Brotli además de Gzip.
  • Long-term caching para assets versionados.

Ejercicio: Configuración Completa de Virtual Hosts con SSL

Objetivo: Crear una configuración empresarial completa con redirección HTTP→HTTPS, SSL, y optimizaciones.

# 1. Virtual Host HTTP - Redirección a HTTPS
# /etc/apache2/sites-available/ucs-http.conf

    ServerName ucs.local
    ServerAlias www.ucs.local
    
    # Redirección permanente a HTTPS
    RewriteEngine On
    RewriteCond %{HTTPS} off
    RewriteRule ^(.*)$ https://%{HTTP_HOST}$1 [R=301,L]
    
    # O alternativa:
    # Redirect permanent / https://ucs.local/


# 2. Virtual Host HTTPS - Configuración completa
# /etc/apache2/sites-available/ucs-ssl.conf


    ServerName ucs.local
    ServerAlias www.ucs.local
    ServerAdmin admin@ucs.local
    
    # Document Root
    DocumentRoot /var/www/ucs/html
    
    # Logs separados
    ErrorLog ${APACHE_LOG_DIR}/ucs_error.log
    CustomLog ${APACHE_LOG_DIR}/ucs_access.log combined
    
    # SSL Configuration
    SSLEngine on
    SSLCertificateFile      /etc/ssl/certs/ucs.crt
    SSLCertificateKeyFile   /etc/ssl/private/ucs.key
    
    # Protocolos y Cifrados seguros
    SSLProtocol all -SSLv3 -TLSv1 -TLSv1.1
    SSLCipherSuite ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256
    SSLHonorCipherOrder on
    SSLCompression off
    
    # Opciones SSL adicionales
    SSLOptions +StrictRequire
    
    # Directorios
    
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
        
        # Proteger archivos sensibles
        
            Require all denied
        
        
        
            Require all denied
        
    
    
    # Proteger directorios específicos
    
        AuthType Basic
        AuthName "Admin Area"
        AuthUserFile /etc/apache2/.htpasswd
        Require valid-user
    
    
    # Performance
    EnableSendfile On
    EnableMMAP On
