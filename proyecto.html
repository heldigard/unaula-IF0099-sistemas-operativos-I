📘 Guía del Proyecto

Administración de Servidores Linux/Windows

Proyecto Integrador - 6 Fases
← Acta de Concertación Evaluaciones Rúbricas

🎯 Objetivo del Proyecto

Propósito

Diseñar, implementar y asegurar una infraestructura de servidores híbrida (Linux + Windows) para una empresa ficticia, aplicando todos los conceptos del curso de forma incremental.

Producto Final

Al finalizar el curso, tendrás un portafolio profesional con:

  • Servidores Linux y Windows configurados y funcionando
  • Servicios web desplegados (Apache + IIS)
  • Sistema de monitoreo en funcionamiento
  • Documentación técnica completa
  • Scripts de automatización funcionales

🗓️ Fases del Proyecto

FASE 1: Fundamentos y Arquitectura (E1 - 15%)

Fecha: 25 Febrero
Tipo: Proyecto (avance incremental)
Eval: E1

Objetivo: Definir la arquitectura tecnológica de la empresa.

Entregables:
  • Análisis de necesidades de la empresa ficticia
  • Comparativa de arquitecturas SO (monolítico vs microkernel)
  • Selección de Ubuntu Server + Windows Server
  • Diagrama de arquitectura de red
  • Lista de servicios y requisitos

Fase 2: Gestión de Procesos y Servicios (E2 - 15%)

Fecha: 11 Marzo
Tipo: Proyecto (avance incremental)
Eval: E2

Objetivo: Implementar procesos críticos y servicios base.

Entregables:
  • Scripts de monitoreo (Bash + PowerShell)
  • Configuración de servicios esenciales
  • Gestión de prioridades y políticas
  • Matriz de procesos y servicios
  • Video demostración (5-7 min)

Fase 3: Checkpoint Optimización (E3 - 20%)

Fecha: 25 Marzo
Tipo: Checkpoint Práctico
Eval: E3

Objetivo: Evaluar comprensión de Memoria, E/S, Procesos y Sincronización antes de Semana Santa.

Alcance del Checkpoint:
  • Incluye: Memoria, Paginación, E/S, Procesos, Sincronización
  • Incluye: Sistemas de Archivos básico (C12: inodos, permisos, ext4/NTFS)
  • NO incluye: Journaling, RAID, fstab (se evalúa en Fase 5)
  • Análisis de escenarios prácticos con enfoque en resolución de problemas
  • Sin memorización - evalúa comprensión y aplicación

Fase 4: Seguridad y Hardening (E4 - 15%)

Fecha: 22 Abril
Tipo: Proyecto (avance incremental)
Eval: E4

Objetivo: Proteger la infraestructura implementada.

Entregables:
  • Matriz de riesgos (8+ identificados)
  • Scripts de hardening automatizado
  • Configuración de firewall básico
  • Auditoría de seguridad
  • Recomendaciones de mitigación

Fase 5: Proyecto Integrador (E5 - 15%) 🚀

Fecha: 06 Mayo
Tipo: Proyecto
Eval: E5

Objetivo: Integrar todo: servidores web + monitoreo.

Entregables:
  • Servidores web funcionando: Apache (Linux) + IIS (Windows)
  • Scripts integrales: Monitor de sistema completo
  • Sistema de monitoreo: CPU, memoria, disco, red, servicios y disponibilidad web
  • Documentación: Integración de Fases 1-4 + aplicación de C13 (journaling, RAID conceptual, fstab)
  • Video: Demostración del sistema (8-12 min)

Fase 6: Sustentación Final (E6 - 20%) 🎓

Fecha: 27 Mayo
Tipo: Proyecto Final
Eval: E6

Objetivo: Presentar el proyecto completo funcionando.

Entregables:
  • Sistema funcionando: Demostración en vivo (20-30 min)
  • Documentación técnica: Manual completo del sistema
  • Presentación: 15-20 diapositivas
  • Portafolio: Evidencias de todo el proceso
  • Sustentación: Defensa del proyecto + preguntas

🧭 Especificación Operativa del Proyecto (Qué y Cómo)

Regla de ejecución por fase

Cada fase se evalúa con evidencia verificable en laboratorio. No basta con describir: se debe demostrar en Linux/Windows con comandos, scripts y resultados reproducibles.

Fase Qué debe hacer el estudiante Evidencia obligatoria Cómo se valida
E1 Diseñar arquitectura técnica y justificar decisiones Linux/Windows para el caso de empresa. Diagrama de red, matriz de servicios, justificación técnica. Revisión de consistencia arquitectura↔requisitos y sustentación corta.
E2 Implementar monitoreo de procesos/servicios y control operacional básico. Scripts Bash/PowerShell funcionales + bitácora de pruebas. Ejecución en vivo de scripts con interpretación de salida.
E3 Resolver escenarios de optimización (memoria, E/S, procesos, sincronización, FS básico). Respuestas técnicas + pruebas en VM (hasta C12). Checklist de solución, comandos ejecutados y justificación técnica.
E4 Aplicar hardening y control de acceso en Linux y Windows. Matriz de riesgos, scripts de seguridad, evidencia de políticas activas. Auditoría guiada de configuraciones y verificación de mitigaciones.
E5 Integrar Apache + IIS, almacenamiento avanzado (C13) y monitoreo end-to-end. Servicios web accesibles, scripts, reporte de integración, video técnico. Prueba funcional de disponibilidad, seguridad y trazabilidad operativa.
E6 Sustentar el sistema completo con demostración en vivo y defensa técnica. Repositorio final, manual técnico, manual de operación, presentación. Rúbrica de demostración (60%) + defensa/presentación (40%).

Criterio mínimo de aprobación por fase

  • Evidencia ejecutable y reproducible en laboratorio (no solo capturas).
  • Coherencia entre diseño, implementación y resultados observados.
  • Respuesta técnica a preguntas de validación del docente.

📊 Evolución del Proyecto

Flujo de Trabajo

  1. Fase 1 (E1): Diseñas la arquitectura → Entregas: Diagrama + justificación
  2. Fase 2 (E2): Implementas servicios → Entregas: Scripts + video
  3. Fase 3 (E3): Evaluación de conocimientos → Checkpoint Optimización
  4. Fase 4 (E4): Aseguras el sistema → Entregas: Hardening + auditoría
  5. Fase 5 (E5): Integras servicios web → Entregas: Proyecto integrado funcionando
  6. Fase 6 (E6): Presentas todo → Sustentación final en vivo

Conexión entre Fases

Cada fase construye sobre la anterior:

  • Fase 2 implementa lo diseñado en Fase 1
  • Fase 3 valida conocimientos antes de continuar
  • Fase 4 protege lo construido en Fases 1-2
  • Fase 5 integra TODO en un sistema funcional
  • Fase 6 muestra el producto final profesional
