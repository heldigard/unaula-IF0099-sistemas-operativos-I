1. El Estándar de la Nube: Linux Bash

Bash (Bourne Again SHell) es la interfaz estándar para administrar servidores Linux. Su filosofía central es: "Todo es un flujo de texto".

Filosofía Linux: Todo es un archivo

Configurar un servidor en Linux es simplemente editar un archivo de texto en /etc. Por eso, dominar comandos de manipulación de texto como cat, grep, nano y sed es vital para un administrador cloud.

# Navegación y Archivos
ls -la          # Listar con permisos y ocultos
cd /var/log     # Ir a la carpeta de logs
pwd             # ¿Dónde estoy parado?
mkdir -p ucs/v1 # Crear carpetas anidadas
touch info.txt  # Crear archivo vacío
cat /etc/os-release # Ver info de la distribución

2. El Estándar Corporativo: Windows PowerShell

A diferencia de Bash, PowerShell no procesa texto; procesa Objetos .NET. Es el motor detrás de la administración de Windows Server y Azure.

La Ventaja del Objeto

Si le pides a Bash el tamaño de un archivo, te devuelve una cadena de caracteres "10MB". Si le pides a PowerShell un archivo, te devuelve un objeto con la propiedad .Length que puedes usar para cálculos matemáticos sin necesidad de recortar texto.

# Comandos equivalentes (Verbos-Sustantivos)
Get-ChildItem               # Equivalente a ls
Set-Location C:\            # Equivalente a cd
Get-Process | Select -First 5 # Ver procesos como objetos
$disco = Get-PSDrive C      # Guardar objeto disco en una variable

3. Tuberías (Piping) y Redirección

El símbolo | permite enviar la salida de un comando como entrada del siguiente. Es la base de la automatización compleja.

Filtrado en Linux (Texto)

# Buscar errores en logs ignorando mayúsculas
cat /var/log/syslog | grep "error" -i

# Contar líneas de un archivo
cat index.html | wc -l

Filtrado en Windows (Objetos)

# Buscar servicios detenidos
Get-Service | Where-Object {$_.Status -eq "Stopped"}

# Ver solo nombre y estado de servicios
Get-Service | Select-Object Name, Status

5. Laboratorio Híbrido: Dominio de la CLI (Insumo E1)

Actividad: Reto de Administración Cruzada

Objetivo: Realizar tareas administrativas idénticas en ambos ecosistemas para el proyecto UCS.

Tarea 1: Inventario de Red

  • Linux: Ejecute ip addr. Identifique su dirección IP privada y la interfaz de red (ej: eth0).
  • Windows: Ejecute Get-NetIPAddress -AddressFamily IPv4 en PowerShell.

Tarea 2: Automatización de Archivos

  • Linux: Cree un script setup.sh que cree la carpeta /tmp/ucs_data y dentro un archivo nota.txt con su nombre.
  • Windows: Haga lo mismo en C:\Temp\ucs_data usando New-Item en un script .ps1.

Tarea 3: El Poder de la Ayuda

  • Linux: Use man top para saber cómo ordenar procesos por memoria (tecla M).
  • Windows: Use Get-Help Get-Service -Examples para ver cómo filtrar servicios por nombre.

Entregable: Una tabla comparativa en su informe de Fase 1 con los comandos usados para ver IPs, crear carpetas y gestionar usuarios en ambos mundos, incluyendo capturas de éxito.

Casos Reales: CLI en el Trabajo Diario

La terminal es la herramienta principal de todo administrador de sistemas. Estos son escenarios reales:

Caso 1: Servidor que No Responde por SSH

Escenario: Intentar conectarte a un servidor por SSH y no responde.

Diagnóstico: systemctl status sshd, netstat -tulpn | grep :22

Caso 2: Disco Lleno en Producción

Escenario: Servidor muestra "No space left on device".

Diagnóstico: df -h, du -sh /* | sort -rh | head -10

Caso 3: Buscar Config en 50 Servidores

Solución: grep -r "database" /etc/ o con Ansible

🧩 Anatomía del Comando Linux

Entender la estructura de un comando es fundamental para trabajar eficientemente en la terminal:

COMANDO OPCIONES ARGUMENTOS | PIPE SIGUIENTE
ls -la /var/log | grep "error"
ComponenteFunciónEjemplo
ComandoLa acción a ejecutarls, cat, grep, find
OpcionesModifican el comportamiento (-l, -a)-la (listado largo + ocultos)
ArgumentosObjetivo de la acción/var/log, archivo.txt
Pipe (|)Envía salida a otro comandocat file | grep "texto"
RedirecciónGuarda salida en archivoecho "hola" > saludo.txt

🔧 Troubleshooting: "Mi comando no funciona"

¿El comando no existe?

└─> ¿Está instalado? → which comando o sudo apt install paquete

¿Permiso denegado?

└─> ¿Necesitas sudo? → sudo comando

¿Archivo no encontrado?

├─> ¿Estás en el directorio correcto? → pwd

└─> ¿El archivo existe? → ls -la

¿Sintaxis incorrecta?

├─> Revisa las comillas y espacios

└─> Consulta la ayuda → comando --help o man comando
