1. Paginación por Demanda (Demand Paging)

Los SO modernos no cargan todo el programa en la RAM al inicio. Solo cargan las páginas que el proceso necesita en ese instante.

Beneficios Profesionales

  • Menos I/O al inicio: El programa arranca más rápido.
  • Ahorro de RAM: No desperdiciamos memoria en código que el usuario no usa.
  • Más Multiprogramación: Podemos tener más procesos abiertos simultáneamente.

2. Page Faults: El Costo de la Memoria Virtual

Un Page Fault ocurre cuando la CPU intenta acceder a una página que no está cargada en la RAM física.

Proceso de Recuperación

  1. El hardware lanza una "Excepción" al Kernel.
  2. El Kernel busca la página en el disco (archivo executable o área de swap).
  3. Se elige un Marco libre en RAM. Si no hay, se aplica un Algoritmo de Reemplazo (LRU).
  4. Se carga la página y se actualiza la Tabla de Páginas.

Latencia Crítica

Un acceso a RAM tarda nanosegundos. Leer una página del disco tarda milisegundos. ¡Es un millón de veces más lento! Por eso, demasiados Page Faults destruyen el rendimiento.

3. Swapping y Áreas de Intercambio

Cuando la RAM se agota, el SO mueve páginas inactivas al disco para hacer espacio a las nuevas.

Linux: Swap Partitions/Files

Permite múltiples áreas de swap con prioridades. Se gestionan con swapon.

Windows: pagefile.sys

Windows usa un archivo oculto administrado dinámicamente por el kernel.

4. Thrashing: El Colapso del Sistema

Ocurre cuando el SO pasa más tiempo moviendo páginas de RAM a disco que ejecutando código útil. El uso de CPU cae, pero el uso de Disco está al 100%.

Detección Profesional:

  • Linux: Use vmstat 1. Observe las columnas si (swap-in) y so (swap-out).
  • Windows: Resource Monitor → Pestaña Disco → Observe colas de pagefile.sys.

5. Comandos de Tuning y Gestión

Optimización Linux (Bash)

# Ver agresividad del swap (0-100)
sysctl vm.swappiness

# Cambiar swappiness en vivo
sudo sysctl -w vm.swappiness=10

# Crear RAM comprimida (zRAM)
sudo zramctl --find --size 1G

# Ver fallos de página por proceso
ps -o pid,comm,minflt,majflt

Optimización Windows (PowerShell)

# Ver configuración del PageFile
Get-CimInstance Win32_PageFileSetting

# Monitorizar fallos de página duros
Get-Counter "\Memory\Pages/sec"

# Ver procesos con más fallos
Get-Process | Sort-Object PageFaults -Desc | 
Select-Object Name, PageFaults -First 10

6. Actividad Práctica Híbrida: Tuning de Swap

Laboratorio: Gestión de Memoria Virtual

Objetivo: Crear y optimizar el espacio de intercambio en ambos sistemas.

Tarea 1: Swap Manual (Linux)

  1. Cree un archivo de swap: sudo fallocate -l 1G /swap_ucs.
  2. Permisos: sudo chmod 600 /swap_ucs.
  3. Formatee: sudo mkswap /swap_ucs.
  4. Actívelo: sudo swapon /swap_ucs.
  5. Verifique con free -h.

Tarea 2: Análisis de Fallos (Windows)

  1. Abra Performance Monitor (perfmon).
  2. Agregue el contador: Memory \ Page Faults/sec.
  3. Abra una aplicación pesada y observe los picos. Diferencie entre fallos "Soft" (en RAM) y "Hard" (en Disco).

Entregable: Documente cómo afectó el cambio de swappiness al rendimiento de su servidor Linux bajo carga.

Casos Reales: Memoria Virtual en Producción

Caso 1: Servidor con Thrashing (Servidor Lentísimo)

Escenario: El servidor está extremadamente lento. El disco trabaja al 100% pero la CPU está ociosa. Los usuarios no pueden trabajar.

Diagnóstico y Solución:

  1. Linux: vmstat 1 - observa las columnas "si" y "so" (swap in/out)
  2. Si son > 0 constantemente, hay thrashing
  3. Solución inmediata:Reducir la carga (matar procesos)
  4. Solución permanente: Agregar más RAM o ajustar swappiness

Caso 2: swapusage en 99% - Servidor Sin Memoria

Escenario: El área de swap está llena. El kernel empieza a matar procesos ("OOM Killer" en Linux).

Diagnóstico:

# Ver uso de swap por proceso
for file in /proc/*/status; do grep VmSwap $file 2>/dev/null; done | sort -k2 -rn | head

# Ver qué procesos fueron matados
dmesg | grep -i "killed process"

Caso 3: Pagefile.sys Gigante en Windows

Escenario: El disco C: tiene poco espacio porque pagefile.sys creció demasiado.

Solución:

# Ver tamaño actual
Get-CimInstance Win32_PageFileUsage

# Configurar tamaño fijo (ej: 4GB mínimo, 8GB máximo)
SystemPropertiesPerformance -> Settings -> Change -> Custom size
