1. El Binomio Fundamental: Kernel y Shell

El Sistema Operativo se divide en capas de abstracción. Como administrador, interactúas con la Shell, pero tus servicios dependen del Kernel.

El Kernel (Núcleo)

Software que reside permanentemente en RAM. Es el único con permiso para ejecutar instrucciones de hardware directas.

  • Identificación (LX): El archivo /boot/vmlinuz.
  • Identificación (WN): El binario ntoskrnl.exe.
  • Misión: Gestión de interrupciones, memoria y drivers.

La Shell (Cáscara)

El programa que envuelve al kernel. Traduce el lenguaje humano a llamadas que el kernel entiende.

  • Interfaces: CLI (Bash, PowerShell) y GUI (Desktop Explorer).
  • Misión: Interpretar comandos y lanzar procesos.

2. Arquitecturas de Diseño de Sistemas Operativos

La forma en que se construyen los cimientos determina si el servidor es rápido o si es "indestructible".

Modelo Descripción Técnica Ejemplo Uso Profesional
Monolítico Todos los servicios (Red, FS, CPU) corren en el mismo bloque de memoria del kernel. Linux Máximo rendimiento (Cloud Servers).
Microkernel Solo lo mínimo en el kernel. Los drivers son procesos normales. QNX Sistemas de alta seguridad (Aviación).
Híbrido Estructura modular pero cargando módulos críticos en Ring 0 por velocidad. Windows NT Estaciones de trabajo corporativas.

Extensibilidad Profesional: LKM

En Linux moderno, no tienes que recompilar el kernel para agregar un driver. Los LKM (Loadable Kernel Modules) permiten insertar código en el espacio de kernel en caliente. Puedes auditarlos con lsmod.

3. Tuning del Kernel: sysctl y Registro

En el mundo laboral, los ingenieros ajustan el comportamiento del kernel sin reiniciar el servidor para optimizar el rendimiento.

Kernel Tuning en Linux (sysctl)

Linux permite modificar parámetros en el sistema de archivos virtual /proc/sys/.

# Ver el límite de archivos abiertos
sysctl fs.file-max

# Habilitar el reenvío de IP (para routers/VPN)
sudo sysctl -w net.ipv4.ip_forward=1

Kernel Tuning en Windows (Registry)

Windows usa la base de datos jerárquica del Registro (HKEY_LOCAL_MACHINE\SYSTEM).

Ejemplo: Ajustar el NonPagedPoolSize para mejorar la gestión de memoria de red.

5. El Proceso de Boot (Arranque)

Entender el arranque es vital para reparar servidores que no inician.

  1. POST: El hardware se autoverifica.
  2. BIOS/UEFI: Localiza el sector de arranque (MBR/GPT).
  3. Boot Loader (GRUB / Windows Boot Mgr): Carga el Kernel en RAM.
  4. Kernel Init: Detecta hardware real y monta el disco raíz (/).
  5. Init (PID 1): Arranca servicios esenciales (SSH, Red, GUI).

6. Actividad Práctica: Análisis Forense de Estructura

Laboratorio de Diagnóstico (Insumo E1)

Tarea 1: Rastreo de System Calls (Linux)

  1. Ejecute strace -c ls /etc.
  2. Identifique cuál es la syscall más usada (usualmente openat).
  3. Investigue: ¿Por qué el comando ls hace una llamada openat para listar una carpeta?

Tarea 2: Auditoría de Drivers (Windows)

  1. Abra PowerShell como Administrador.
  2. Use driverquery /V | Select-Object -First 10.
  3. Identifique un driver con extensión .sys y busque su fabricante.

Tarea 3: Mensajes del Kernel (Boot Logs)

  1. En Linux, ejecute dmesg | head -n 50.
  2. Identifique el momento exacto donde el kernel detectó su CPU y el modelo detectado.

Entregable: Documente en su informe de Fase 1 una captura de strace comentando al menos 2 llamadas al sistema y su función probable.

Casos Reales: El Kernel en Producción

Caso 1: Servidor que No Bootea

Escenario: Un servidor Linux no inicia después de una actualización del kernel. Se queda en "Loading...".

Diagnóstico:

  1. Acceder al menú de GRUB y seleccionar kernel anterior
  2. Verificar si el archivo /boot/vmlinuz existe
  3. Revisar dmesg para ver errores de carga

Caso 2: Módulo de Kernel que Causa Kernel Panic

Escenario: Después de instalar un driver propietario (NVIDIA), el servidor muestra "Kernel panic - not syncing".

Solución: Acceder en modo recovery, desinstalar el driver con modprobe -r nvidia

Ejercicio: Compilación de Kernel (Avanzado)

Investiga: ¿Por qué en producción NUNCA se recompila el kernel? ¿Qué alternativas existen para agregar funcionalidad sin recompilar?

Pista: Busca información sobre "Loadable Kernel Modules" (LKM).
