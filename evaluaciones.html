Fase 1: Fundamentos y Arquitectura

VALOR: 15%

El objetivo es establecer la base técnica del proyecto UNAULA Cloud Services (UCS), garantizando que el entorno de virtualización sea profesional y las máquinas se vean entre sí.

🛠️ Paso a Paso:

1 Instale VirtualBox 7.x y despliegue dos nodos: Ubuntu Server 22.04 (Nodo LX) y Windows Server o Windows 10/11 Pro (Nodo WN).
2 Configure la red en modo Adaptador Puente (Bridge). Verifique conectividad mediante ping entre el Host y ambas VMs.
3 Realice un inventario técnico de su hardware asignado (RAM, Cores, Almacenamiento).

Fase 2: Monitoreo y Automatización

VALOR: 15%

Implementar visibilidad operativa. Como ingeniero, no debe entrar a la VM para saber que algo falló; el sistema debe avisarle.

🛠️ Paso a Paso:

1 Linux: Desarrolle monitor.sh. El script debe ejecutarse cada N segundos, leer /proc/stat y alertar si el CPU supera el 80%.
2 Windows: Desarrolle services.ps1. El script debe vigilar el servicio de "Cola de Impresión" (Spooler) y reiniciarlo automáticamente si se detiene.
3 Integre ambos scripts en el arranque del sistema (systemd unit en Linux y Scheduled Task en Windows).

Fase 3: Laboratorio de Optimización

VALOR: 20%

Esta es la prueba de fuego de media mitad de semestre. Se evalúa su capacidad de resolver problemas de rendimiento bajo presión.

⚠️ Este laboratorio es Individual y se basa en 5 escenarios técnicos reales proporcionados por el docente el día de la sesión.

🔎 Ejemplos de lo que se evaluará:

  • Memory Pressure: Identificar qué proceso tiene un "Memory Leak" usando resmon y vmstat.
  • I/O Bottleneck: Analizar por qué el servidor web está lento usando colas de disco (PerfMon) y latencia await (iostat).
  • Forense de Archivos: Recuperar acceso a archivos con inodos huérfanos o links simbólicos rotos.

📦 ENTREGABLES OBLIGATORIOS:

📅 Fecha: 25 de Marzo, 2026 | ⏰ En clase (60 min)

📤 Formato: PDF | Nombre: E3_ApellidoNombre.pdf

  1. PDF de Análisis Forense (una sección por escenario):
    • Problema Identificado: Descripción clara del síntoma observado
    • Datos de Evidencia: Capturas de comandos ejecutados (vmstat, resmon, iostat, etc.)
    • Diagnóstico: Explicación técnica de la causa raíz
    • Solución Aplicada: Comando o acción correctiva ejecutada
    • Resultado: Captura del estado final corregido

Fase 4: Hardening y Seguridad

VALOR: 15%

Transformar un sistema funcional en un sistema seguro (A prueba de ataques).

🛠️ Paso a Paso:

1 Linux: Cierre todos los puertos con UFW. Cambie el puerto SSH. Implemente ACLs granulares en /var/www/ucs para que solo el grupo www-data tenga acceso.
2 Windows: Configure secpol.msc para forzar complejidad de contraseñas y bloqueo de cuenta. Audite el acceso al sistema mediante el Visor de Eventos.
3 Construya la Matriz de Riesgos del sistema UCS.

📅 Fecha límite: 22 de Abril, 2026 | ⏰ 11:59 PM

📤 Formato: PDF | Nombre: E4_ApellidoNombre.pdf

  1. Matriz de Riesgos (tabla):
    • 8 vulnerabilidades identificadas (4 Linux + 4 Windows)
    • Columnas: Vulnerabilidad | Nivel de Riesgo | Impacto | Mitigación Técnica | Estado
    • Incluir comandos específicos usados para cada mitigación
  2. Reporte de Auditoría Linux (capturas):
    • sudo ufw status verbose - Firewall configurado
    • getfacl /var/www/ucs - ACLs aplicadas
    • cat /etc/ssh/sshd_config | grep Port - Puerto SSH cambiado

  3. Reporte de Auditoría Windows (capturas):

Fase 5: Integración y Producción

VALOR: 15%

Puesta en marcha definitiva. Los nodos deben colaborar para servir la aplicación corporativa con alta disponibilidad.

🛠️ Paso a Paso:

1 Servidor Web Linux: Configure Apache con VirtualHost y HTTPS (certificado SSL auto-firmado). El sitio debe ser accesible por HTTPS.
2 Servidor Web Windows: Instale IIS, cree un sitio en puerto 8080 con Application Pool dedicado.
3 Almacenamiento Redundante: Configure RAID 1 (mirror) en Linux usando mdadm con dos discos virtuales. Demuestre que tolera fallo de un disco.
4 Persistencia: Configure /etc/fstab para que el RAID se monte automáticamente al reiniciar.

📦 Qué debe entregar:

📅 Fecha límite: 06 de Mayo, 2026 | ⏰ 11:59 PM

📤 Formato: Video + Configuraciones

  1. Video Técnico (máx 5 minutos):
    • Demostración de Apache funcionando con HTTPS
    • Demostración de IIS funcionando en puerto 8080
    • Prueba de RAID: Muestre el estado con cat /proc/mdstat, simule fallo de un disco, verifique que sigue funcionando
    • Reinicio de la VM Linux y verificación de que el RAID se monta automáticamente
  2. Archivos de Configuración:
    • VirtualHost de Apache (ucs.conf)
    • Configuración del RAID (/etc/mdadm/mdadm.conf o similar)
    • /etc/fstab con el montaje persistente
  3. URLs de Acceso: Liste las IPs y puertos donde se accede a cada servidor web

💡 Consejos para el Video

  • No necesita mostrar toda la instalación paso a paso, solo el resultado funcionando
  • Para el RAID: Muestre claramente el estado antes, durante y después del "fallo"
  • Use un timer visible o indique los timestamps importantes
  • Suba el video a YouTube (no listado) o Google Drive y comparta el link

Fase 6: Sustentación Final

VALOR: 20%

Defensa profesional de la ingeniería realizada durante el semestre.

💎 Componentes de la Sustentación:

Portafolio Ejecutivo: Un único documento PDF que consolida todas las fases anteriores, con las correcciones sugeridas por el docente incorporadas.
Pitch Técnico: Presentación de 8 diapositivas enfocadas en la arquitectura, retos de sincronización y estrategia de seguridad.
Live Demo: El docente pedirá realizar un cambio en vivo (ej: "Matar el proceso Apache y mostrar cómo el monitor lo detecta").
