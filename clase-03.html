Cambio de Contexto

¿Qué es el Cambio de Contexto?

El cambio de contexto (context switch) es el proceso mediante el cual el sistema operativo transfiere el control de la CPU de un proceso a otro. Este es un mecanismo fundamental que permite la multiprogramación y el funcionamiento eficiente de los sistemas operativos modernos.

Analogía: Imagina un professor con múltiples estudiantes preguntando. El professor atiende a un estudiante (proceso en ejecución), anota dónde se quedó (guarda estado), y atiende al siguiente (cambio de contexto). Cuando vuelve al primer estudiante, continúa desde donde lo dejó.

Componentes del Cambio de Contexto

  • Salvado del estado: Guardar registros, contador de programa, puntero de pila
  • Actualización del PCB: Guardar información del proceso que cede la CPU
  • Selección del nuevo proceso: El scheduler elige el siguiente proceso
  • Carga del estado: Restaurar registros y contador del nuevo proceso
  • Actualización de estructuras: Modificar tablas de memoria y descriptores
Tiempo de Cambio de Contexto: El cambio de contexto no es "gratis". El sistema operativo debe invertir tiempo de CPU en realizar este intercambio. Este tiempo depende de la arquitectura del hardware y de la eficiencia del kernel.

Costos del Cambio de Contexto

Componente Descripción Impacto
Salvado de registros Almacenar estado actual de CPU Alto
Actualización de tablas Cambiar punteros de memoria virtual Medio
Invalidación de caché Limpiar caché de CPU Alto
Cambio de privilegio kernel → usuario Bajo

PCB (Process Control Block)

El PCB es la estructura de datos principal que representa un proceso en el sistema operativo. Contiene toda la información necesaria para gestionar un proceso.

Campos del PCB

Identificación

  • PID: Identificador único del proceso
  • PPID: PID del proceso padre
  • Usuario propietario

Estado de CPU

  • Contador de programa
  • Registros generales
  • Puntero de pila
  • Flags de estado

Gestión de Memoria

  • Tabla de páginas
  • Límites de segmentos
  • Tabla de descriptores

Información de E/S

  • Lista de archivos abiertos
  • Dispositivos asignados
  • Estado de E/S

Estados del Proceso

Un proceso puede estar en diferentes estados durante su ciclo de vida. El modelo más común es el de 5 estados.

Estados del Modelo de 5 Estados

Estado Descripción Causa
NUEVO Proceso siendo creado fork(), CreateProcess()
LISTO Esperando asignación de CPU Listo para ejecutar
EJECUTANDO Instrucciones ejecutándose Tiene la CPU asignada
BLOQUEADO Esperando evento/E-S read(), wait()
TERMINADO Proceso finalizado exit(), return
Estado de "Suspensión": En sistemas modernos, existe un estado adicional de "suspendido" donde el proceso puede ser movido a memoria swap para liberar RAM.

Algoritmos de Planificación de CPU

El scheduler (planificador) decide qué proceso de la cola de "listos" debe ejecutarse next. Existen diferentes algoritmos con distintas propiedades.

Comparativa de Algoritmos

Algoritmo Tipo Ventaja Desventaja
FCFS (First Come, First Served) No expulsivo Simple, justo Efecto convoy
SJF (Shortest Job First) No expulsivo Tiempo de espera mínimo Inanición de procesos largos
SRTF (Shortest Remaining Time) Expulsivo Respuesta rápida Inanición
RR (Round Robin) Expulsivo 、公平, responsivo Overhead de cambios
Por Prioridad Expulsivo/No Importancia Inanición

FCFS - First Come, First Served

El proceso que llega primero se ejecuta primero. Es el algoritmo más simple.

Proceso | Tiempo de ráfaga | Tiempo de espera
--------|------------------|-----------------
  P1    |       24        |        0
  P2    |        3        |       24
  P3    |        3        |       27

Tiempo de espera promedio: (0 + 24 + 27) / 3 = 17 ms

SJF - Shortest Job First

Selecciona el proceso con menor tiempo de ráfaga de CPU.

Proceso | Tiempo de ráfaga | Tiempo de espera
--------|------------------|-----------------
  P1    |        6        |        3
  P2    |        8        |        9
  P3    |        7        |        0
  P4    |        3        |        7

Tiempo de espera promedio: (3 + 9 + 0 + 7) / 4 = 4.75 ms
(Mínimo posible)

RR - Round Robin

Cada proceso obtiene un quantum de tiempo fijo. Si no termina, vuelve a la cola.

Quantum = 4 ms

Proceso | Tiempo de ráfaga | Tiempo de espera
--------|------------------|-----------------
  P1    |       10        |        0
  P2    |        5        |        4
  P3    |        8        |        7

Secuencia: P1(4) → P2(4) → P3(4) → P1(4) → P2(1) → P3(4) → P1(2)
Ejemplo Interactivo: Ejecuta el siguiente comando para ver los procesos en estado "listos" y sus prioridades en Linux: 
ps -eo pid,ppid,stat,pri,ni,cmd --sort=pri

Práctica Guiada: Análisis de Procesos en Linux (30 min)

Objetivo: Visualizar en tiempo real los conceptos teóricos: cambio de contexto, estados de proceso y PCB.

Ejercicio 1: Explorando el PCB con ps (5 min)

El PCB contiene información de identificación, CPU y estado. Vamos a verlo en vivo:

# Ver campos del PCB de procesos en ejecución
ps -eo pid,ppid,stat,pri,ni,pcpu,pmem,cmd --sort=-pcpu | head -10

# Explicación de columnas:
# PID  = Process ID (identificador único)
# PPID = Parent PID (identificador del padre)
# STAT = Estado del proceso (R, S, D, Z, T)
# PRI  = Prioridad del proceso
# NI   = Nice value (valor de prioridad ajustable)
# %CPU = Uso de CPU
# %MEM = Uso de memoria
# CMD  = Comando ejecutado

# Ejemplo de salida:
#  PID  PPID STAT PRI  NI %CPU %MEM CMD
# 1234     1 S    20   0  5.2  2.1 apache2
# 5678  1234 S    20   0  3.1  1.8 mysql
Pregunta de análisis: ¿Qué relación ves entre PPID y PID? ¿Cuál es el proceso padre de tus procesos de terminal?

Ejercicio 2: Simulando Estados de Proceso (10 min)

Crearemos procesos en diferentes estados y los observaremos:

Paso 1: Proceso en Ejecución (Estado R)

# Terminal 1: Ejecutar un proceso que consuma CPU
yes > /dev/null &
# Guarda el PID que aparece (ej: [1] 1234)

# Terminal 2: Verificar estado
ps -eo pid,stat,cmd | grep yes
# Deberías ver: 1234 R yes

Paso 2: Proceso Dormido (Estado S)

# Ejecutar sleep (espera sin consumir CPU)
sleep 300 &
# Guarda el PID

# Verificar estado
ps -eo pid,stat,cmd | grep sleep
# Deberías ver: [PID] S sleep

Paso 3: Proceso Detenido (Estado T)

# Detener el proceso sleep con SIGSTOP
kill -STOP [PID_del_sleep]

# Verificar estado
ps -eo pid,stat,cmd | grep sleep
# Deberías ver: [PID] Tl sleep (T = Stopped)

Paso 4: Reanudar Proceso (Vuelve a S)

# Reanudar con SIGCONT
kill -CONT [PID_del_sleep]

# Verificar que vuelve a estado S
ps -eo pid,stat,cmd | grep sleep

Paso 5: Terminar Procesos

# Matar ambos procesos
kill %1  # Mata el job 1 (yes)
kill [PID_del_sleep]  # Mata el sleep

# Verificar que desaparecieron
ps -eo pid,stat,cmd | grep -E "yes|sleep"
Registra en tu cuaderno: Capturas de cada estado (R, S, T) con sus respectivos PIDs.

Ejercicio 3: Visualizando Cambios de Contexto con top (5 min)

# Ver cambios de contexto en tiempo real
top

# Dentro de top, presiona:
# 'c' - Mostrar línea de comandos completa
# 'k' - Matar proceso (pide PID)
# 'r' - Cambiar nice (prioridad)
# 'q' - Salir

# Observa:
# - %CPU cambiando entre procesos (cambio de contexto)
# - Estados cambiando entre R y S
# - Prioridades (PR y NI)

Ejercicio 4: Jerarquía de Procesos Padre-Hijo (5 min)

# Ver árbol de procesos desde init (PID 1)
pstree -p | head -20

# Ver procesos de tu usuario con jerarquía
pstree -p [tu_usuario]

# Crear proceso hijo desde tu shell
bash
# Ahora estás en un sub-shell (hijo)
echo $$
# Muestra el PID del shell actual

# Ver relación padre-hijo
ps -eo pid,ppid,cmd | grep $$
# El PPID debería ser el PID de tu shell anterior

Ejercicio 5: Simulación de Algoritmos (5 min)

Vamos a simular cómo el scheduler asigna CPU:

# Crear 3 procesos que consuman CPU
yes > /dev/null &  # Proceso A
yes > /dev/null &  # Proceso B  
yes > /dev/null &  # Proceso C

# Ver distribución de CPU
top

# Observa:
# - Los 3 procesos compiten por CPU (~33% cada uno en Round Robin)
# - Si cambias la prioridad de uno, cambia la distribución

# Cambiar prioridad (nice) de uno
sudo renice -10 [PID_proceso_A]

# En top, observa cómo ese proceso recibe más CPU
# Esto simula el algoritmo de Prioridad

Ejercicio 6: Limpieza y Conclusión

# Matar todos los procesos yes
killall yes

# Verificar que no queden procesos zombies
ps aux | grep -w Z
# No debería mostrar nada (o solo el grep)
Conclusión práctica: Has visto en vivo:
  • ✅ PCB: Información de PID, PPID, estado, prioridad
  • ✅ Estados: R (running), S (sleeping), T (stopped)
  • ✅ Cambio de contexto: Procesos alternando CPU en top
  • ✅ Jerarquía: Procesos padre-hijo con pstree
  • ✅ Scheduling: Distribución de CPU entre procesos

Resumen de la Clase

Cambio de Contexto

Proceso de transferir el control de CPU entre procesos. Incluye salvado/carga de estado y actualización de estructuras del kernel.

PCB

Estructura de datos que contiene toda la información de un proceso: identificación, estado de CPU, memoria y E/S.

Estados del Proceso

Nuevo → Listo → Ejecutando → Bloqueado → Terminado. Las transiciones ocurren por eventos del sistema.

Algoritmos de Planificación

FCFS, SJF, SRTF, Round Robin, Prioridades. Cada uno tiene trade-offs entre throughput, latencia y fairness.

Comandos Aprendidos Hoy

  • ps -eo pid,ppid,stat,pri,cmd - Ver PCB de procesos
  • pstree -p - Jerarquía de procesos
  • top - Monitor en tiempo real
  • kill -STOP/-CONT - Controlar estados
  • renice - Cambiar prioridad
