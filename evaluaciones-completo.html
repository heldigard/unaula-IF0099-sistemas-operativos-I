🚀 EVALUACIÓN 1: Fundamentos y Arquitectura
15% 25 Feb 2026 RA1

🎯 Objetivo Laboral Real

Eres contratado como ingeniero de infraestructura. Tu primera tarea es montar el ambiente de desarrollo/testing donde trabajarás todo el proyecto. Debes configurar dos servidores virtuales (Linux y Windows) que se vean entre sí, como ocurre en cualquier datacenter real.

🛠️ PASO 1: Preparar el Ambiente de Trabajo

1 Descargar Software Necesario

Debes conseguir:

  • VirtualBox 7.x desde virtualbox.org (hipervisor gratuito)
  • Ubuntu Server 22.04 LTS ISO (la versión SERVER, sin interfaz gráfica)
  • Windows 10/11 Pro ISO o Windows Server 2022
💡 Tip laboral: En empresas usan VMware o Hyper-V, pero VirtualBox es gratuito y sirve perfectamente para aprender. Los conceptos son los mismos.
2 Crear la Máquina Virtual Linux (UCS-Linux)

Configura una VM con estas especificaciones:

Nombre: UCS-Linux Sistema Operativo: Linux → Ubuntu (64-bit) RAM: 4096 MB (4GB) - mínimo 2048 MB Procesadores: 2 CPUs Disco Duro: 20 GB (dinámico) Red: Adaptador Puente (Bridge)
🔧 Acción: Instala Ubuntu Server. Durante la instalación:
  • Crea un usuario (ej: tu nombre)
  • Selecciona instalar OpenSSH server
  • No instales nada más (sin Docker, sin snaps adicionales)
3 Crear la Máquina Virtual Windows (UCS-Windows)
Nombre: UCS-Windows Sistema Operativo: Microsoft Windows → Windows 10/11 (64-bit) RAM: 6144 MB (6GB) - mínimo 4096 MB Procesadores: 2 CPUs Disco Duro: 40 GB (dinámico) Red: Adaptador Puente (Bridge)
🔧 Acción: Instala Windows. Si no tienes licencia, usa la versión de evaluación de 90 días. Activa el usuario Administrador y crea tu usuario de trabajo.

🛠️ PASO 2: Configurar Red (Adaptador Puente)

4 ¿Por qué modo Bridge?

En modo Bridge, tus VMs obtienen IPs de tu router real, como si fueran computadores físicos independientes. Esto permite:

  • Que las VMs se vean entre sí
  • Que tú (desde tu PC) accedas a las VMs
  • Simular un ambiente de red empresarial real
5 Configurar en VirtualBox
🔧 Acción para AMBAS VMs:
  1. Selecciona la VM → Configuración → Red
  2. Adaptador 1: Habilitar
  3. Conectado a: Adaptador Puente
  4. Nombre: Selecciona tu tarjeta de red (WiFi o Ethernet)
  5. Aceptar

🛠️ PASO 3: Verificar Conectividad

6 Obtener IPs de las VMs

En Linux (UCS-Linux):

ip addr show

Busca la interfaz que tenga una IP tipo 192.168.X.X o 10.X.X.X. Anota esa IP.

En Windows (UCS-Windows):

ipconfig

Busca "Dirección IPv4" y anota la IP.

7 Probar Conectividad

Desde Linux, hacer ping a Windows:

ping 192.168.1.XXX

(Reemplaza con la IP real de tu VM Windows)

Desde Windows, hacer ping a Linux:

ping 192.168.1.XXX

(Reemplaza con la IP real de tu VM Linux)

⚠️ Importante: Si el ping no funciona, revisa:
  • Que ambas VMs estén en modo Bridge
  • Que el firewall de Windows permita ICMP (ping)
  • Que estén en la misma red (mismos primeros 3 números de IP)

⚙️ EVALUACIÓN 2: Procesos y Monitoreo
15% 11 Mar 2026 RA2

🎯 Objetivo Laboral Real

Como ingeniero de infraestructura, no puedes estar entrando manualmente a cada servidor para verificar si todo funciona bien. Debes implementar monitoreo automatizado que te alerte cuando algo falla. En esta evaluación crearás scripts que supervisan el sistema 24/7.

🛠️ PARTE 1: Script de Monitoreo en Linux (Bash)

1 Crear el Script monitor.sh

Crea un archivo llamado monitor.sh en tu VM Linux con este contenido:

#!/bin/bash # monitor.sh - Sistema de monitoreo UCS # Este script monitorea CPU, RAM y envía alertas si hay problemas # Configuración UMBRAL_CPU=80 UMBRAL_RAM=80 INTERVALO=5 LOG_FILE="/var/log/ucs-monitor.log" # Función para obtener uso de CPU get_cpu_usage() { # Lee el uso de CPU del primer core CPU=$(top -bn1 | grep "Cpu(s)" | awk '{print $2}' | cut -d'%' -f1) echo "${CPU%.*}" } # Función para obtener uso de RAM get_ram_usage() { RAM=$(free | grep Mem | awk '{printf "%.0f", $3/$2 * 100.0}') echo "$RAM" } # Función para loguear mensajes log_message() { echo "$(date '+%Y-%m-%d %H:%M:%S') - $1" | tee -a "$LOG_FILE" } # Bucle principal de monitoreo echo "=== UCS Monitor iniciado ===" echo "Presiona Ctrl+C para detener" echo "" while true; do CPU_USAGE=$(get_cpu_usage) RAM_USAGE=$(get_ram_usage) log_message "CPU: ${CPU_USAGE}% | RAM: ${RAM_USAGE}%" # Alerta si CPU supera umbral if [ "$CPU_USAGE" -gt "$UMBRAL_CPU" ]; then log_message "⚠️ ALERTA: Uso de CPU alto: ${CPU_USAGE}%" log_message "Top 5 procesos por CPU:" ps aux --sort=-%cpu | head -n 6 | tail -n 5 | while read line; do log_message " $line" done fi # Alerta si RAM supera umbral if [ "$RAM_USAGE" -gt "$UMBRAL_RAM" ]; then log_message "⚠️ ALERTA: Uso de RAM alto: ${RAM_USAGE}%" log_message "Top 5 procesos por RAM:" ps aux --sort=-%mem | head -n 6 | tail -n 5 | while read line; do log_message " $line" done fi sleep $INTERVALO done
🔧 Acción: Guarda el archivo y dale permisos de ejecución:
chmod +x monitor.sh
2 Probar el Script Manualmente
🔧 Acción: Ejecuta el script y déjalo corriendo:
./monitor.sh

Deja el script corriendo mientras haces otras cosas. Debería mostrar el uso de CPU y RAM cada 5 segundos.

💡 Para generar carga de CPU y probar las alertas: Abre otra terminal y ejecuta:
stress --cpu 4 --timeout 60

(Si no tienes stress, instálalo: sudo apt install stress)

3 Configurar Ejecución Automática (systemd)

Para que el script se ejecute automáticamente al iniciar el sistema:

🔧 Paso A - Crear el archivo de servicio:
sudo nano /etc/systemd/system/ucs-monitor.service
🔧 Paso B - Contenido del archivo:
[Unit] Description=UCS System Monitor After=network.target [Service] Type=simple ExecStart=/home/tu-usuario/monitor.sh Restart=always RestartSec=10 User=tu-usuario [Install] WantedBy=multi-user.target

(Reemplaza /home/tu-usuario/ con la ruta real donde guardaste el script)

🔧 Paso C - Activar el servicio:
sudo systemctl daemon-reload sudo systemctl enable ucs-monitor sudo systemctl start ucs-monitor sudo systemctl status ucs-monitor
🔧 Paso D - Verificar que funciona:
sudo systemctl status ucs-monitor sudo tail -f /var/log/ucs-monitor.log

🛠️ PARTE 2: Script de Monitoreo en Windows (PowerShell)

4 Crear el Script services.ps1

Este script vigila servicios críticos y los reinicia si se detienen:

# services.ps1 - Monitoreo de Servicios Windows # Vigila el servicio Spooler (Cola de Impresión) y otros críticos # Configuración $SERVICIOS_A_MONITOREAR = @("Spooler", "w3svc", "MpsSvc") $INTERVALO_SEGUNDOS = 10 $LOG_FILE = "C:\ucs-monitor.log" # Función para escribir en log function Write-Log { param([string]$Message) $timestamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss" $logEntry = "$timestamp - $Message" Write-Host $logEntry Add-Content -Path $LOG_FILE -Value $logEntry } # Función para verificar y reiniciar servicio function Check-Service { param([string]$ServiceName) try { $service = Get-Service -Name $ServiceName -ErrorAction Stop if ($service.Status -eq "Stopped") { Write-Log "⚠️ ALERTA: Servicio $ServiceName está DETENIDO" Write-Log "Intentando reiniciar..." try { Start-Service -Name $ServiceName Start-Sleep -Seconds 2 $service.Refresh() if ($service.Status -eq "Running") { Write-Log "✅ Servicio $ServiceName reiniciado exitosamente" } else { Write-Log "❌ No se pudo reiniciar el servicio $ServiceName" } } catch { Write-Log "❌ Error al reiniciar ${ServiceName}: $_" } } else { Write-Log "✓ Servicio $ServiceName está $($service.Status)" } } catch { Write-Log "❌ Error al verificar ${ServiceName}: $_" } } # Bucle principal Write-Log "=== UCS Windows Monitor iniciado ===" Write-Log "Monitoreando servicios: $($SERVICIOS_A_MONITOREAR -join ', ')" Write-Log "Presiona Ctrl+C para detener" Write-Log "" while ($true) { foreach ($servicio in $SERVICIOS_A_MONITOREAR) { Check-Service -ServiceName $servicio } Write-Log "---" Start-Sleep -Seconds $INTERVALO_SEGUNDOS }
5 Probar el Script en Windows
🔧 Paso A - Abrir PowerShell como Administrador
🔧 Paso B - Ejecutar el script:
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process -Force .\services.ps1

(El primer comando permite ejecutar scripts temporalmente)

🔧 Paso C - Probar el monitoreo:

Mientras el script corre, abre otra ventana de PowerShell como Administrador y detén el servicio:

Stop-Service Spooler

El script debería detectarlo y reiniciarlo automáticamente.

6 Configurar Tarea Programada en Windows
🔧 Paso A - Abrir el Programador de Tareas:
taskschd.msc
🔧 Paso B - Crear nueva tarea:
  1. Clic derecho en "Biblioteca del Programador de Tareas" → "Crear tarea..."
  2. General: Nombre: "UCS-Monitor", Marcar "Ejecutar con privilegios más altos"
  3. Desencadenadores: Nuevo → Al iniciar la sesión / Al inicio
  4. Acciones: Nuevo → Iniciar un programa
    • Programa: powershell.exe
    • Argumentos: -ExecutionPolicy Bypass -File "C:\ruta\services.ps1"
  5. Condiciones: Desmarcar "Iniciar solo si hay conexión de red"
  6. Configuración: Marcar "Ejecutar la tarea lo antes posible..."
  7. Aceptar

🔬 EVALUACIÓN 3: Laboratorio de Optimización
20% 25 Mar 2026 RA3

🎯 Objetivo Laboral Real

Un administrador de sistemas pasa gran parte de su tiempo resolviendo problemas de rendimiento. En esta evaluación enfrentarás 5 escenarios reales donde el sistema tiene problemas y debes diagnosticarlos y solucionarlos usando comandos profesionales.

⚠️ Importante: Este es un checkpoint práctico individual. El docente te proporcionará los 5 escenarios específicos el día de la evaluación. Debes resolverlos en tu VM y documentar todo.

📋 Estructura de Cada Escenario

Cada escenario que resuelvas debe incluir en tu documento:

  1. Diagnóstico: ¿Qué problema identificaste?
  2. Evidencia: ¿Qué comandos ejecutaste para confirmarlo? (capturas)
  3. Solución: ¿Qué hiciste para resolverlo?
  4. Verificación: ¿Cómo confirmaste que quedó solucionado?

🔍 Ejemplos de Escenarios que Podrías Enfrentar

📊 Escenario 1: "El servidor está muy lento" (Memory Pressure)

Situación: Los usuarios reportan que el servidor responde muy lento.

Tu tarea:

# 1. Verificar uso de memoria free -h # 2. Identificar qué procesos consumen más RAM ps aux --sort=-%mem | head -n 10 # 3. Ver si está usando swap (memoria virtual en disco) vmstat 1 5 # Columnas 'si' (swap in) y 'so' (swap out) deben ser 0 o bajas # 4. Ver detalles de un proceso específico pmap -x [PID] # 5. Si hay un proceso consumiendo demasiado: # - Documentar el PID # - Decidir si matarlo (kill) o ajustar prioridad (nice) # Solución posible: sudo kill -9 [PID-del-problema]

💾 Escenario 2: "El disco está al 100%" (I/O Bottleneck)

Situación: El uso de disco está al máximo y todo es lento.

Tu tarea:

# 1. Verificar uso de disco iostat -x 1 10 # %util cerca de 100% indica problema # 2. Ver qué procesos usan más disco iotop # 3. Verificar espacio libre df -h # 4. Buscar archivos grandes sudo du -h / | grep -E "^\d+G" | sort -hr | head -n 10 # 5. Ver logs que consumen espacio sudo du -h /var/log | sort -hr | head -n 10

🔗 Escenario 3: "Hay un proceso zombie"

Situación: Existen procesos en estado zombie (terminados pero no liberados).

Tu tarea:

# 1. Ver procesos zombie ps aux | grep "Z" # 2. Ver el árbol de procesos pstree -p # 3. Identificar el proceso padre del zombie ps -o pid,ppid,state,cmd -p [PID-del-zombie] # 4. Decisión: matar el proceso padre o esperar sudo kill -9 [PPID]

📝 Escenario 4: "Disco lleno pero no hay archivos grandes" (Inodes)

Situación: El sistema dice "disco lleno" pero al revisar no encuentras archivos grandes.

Tu tarea:

# 1. Ver uso de inodes (no solo espacio) df -i # 2. Buscar directorios con muchos archivos pequeños sudo find / -xdev -printf '%h\n' | sort | uniq -c | sort -rn | head -n 20 # 3. Limpiar caché de paquetes sudo apt clean # 4. Buscar archivos temporales viejos sudo find /tmp -type f -atime +7 -delete

⚡ Escenario 5: "Deadlock entre procesos"

Situación: Dos procesos se bloquean mutuamente esperando recursos.

Tu tarea:

# 1. Ver procesos en estado D (uninterruptible sleep) ps aux | grep "^D" # 2. Ver procesos bloqueados esperando I/O cat /proc/[PID]/stack # 3. Ver archivos abiertos por un proceso lsof -p [PID] # 4. Decisión: matar uno de los procesos bloqueados sudo kill -9 [PID]

🔒 EVALUACIÓN 4: Seguridad y Hardening
15% 22 Abr 2026 RA4

🎯 Objetivo Laboral Real

Los sistemas que construiste hasta ahora funcionan, pero ¿están seguros? En esta evaluación aplicarás hardening (fortalecimiento de seguridad) como lo harías en cualquier empresa: cerrar puertos innecesarios, configurar firewalls, establecer políticas de contraseñas y documentar riesgos.

🛠️ PARTE 1: Hardening en Linux

1 Configurar Firewall (UFW - Uncomplicated Firewall)
🔧 Paso A - Verificar estado actual:
sudo ufw status verbose
🔧 Paso B - Configurar políticas por defecto:
# Bloquear todo entrada por defecto sudo ufw default deny incoming # Permitir todo salida (para que el servidor pueda actualizarse) sudo ufw default allow outgoing
🔧 Paso C - Abrir solo los puertos necesarios:
# Permitir SSH (para que puedas acceder remotamente) sudo ufw allow 22/tcp # Si ya tienes Apache instalado, permitir HTTP y HTTPS sudo ufw allow 80/tcp sudo ufw allow 443/tcp # Si tienes Samba (para compartir archivos) sudo ufw allow 139/tcp sudo ufw allow 445/tcp
🔧 Paso D - Activar y verificar:
sudo ufw enable sudo ufw status numbered

Captura pantalla del estado final.

2 Configurar ACLs (Listas de Control de Acceso)
🔧 Paso A - Crear estructura de directorios:
sudo mkdir -p /var/www/ucs/datos sudo mkdir -p /var/www/ucs/publico
🔧 Paso B - Configurar permisos base:
# Cambiar propietario a www-data (usuario de Apache) sudo chown -R www-data:www-data /var/www/ucs # Permisos: dueño puede todo, grupo puede leer/ejecutar, otros nada sudo chmod -R 750 /var/www/ucs
🔧 Paso C - Configurar ACLs granulares:
# Instalar ACL si no está instalado sudo apt install acl -y # Dar permiso de lectura a un usuario específico en /datos sudo setfacl -m u:tu-usuario:r /var/www/ucs/datos # Dar permiso de escritura al grupo 'developers' si existe sudo setfacl -m g:developers:rw /var/www/ucs/datos # Verificar ACLs configurados getfacl /var/www/ucs/datos

Captura pantalla del resultado de getfacl.

3 Desactivar Servicios Innecesarios
🔧 Paso A - Listar servicios activos:
sudo systemctl list-units --type=service --state=running
🔧 Paso B - Identificar y desactivar servicios innecesarios:
# Ejemplos de servicios que generalmente no necesitas en servidor: # 1. Impresión (CUPS) sudo systemctl stop cups sudo systemctl disable cups # 2. Bluetooth sudo systemctl stop bluetooth sudo systemctl disable bluetooth # 3. Detección de redes (Avahi) sudo systemctl stop avahi-daemon sudo systemctl disable avahi-daemon # Verificar que quedaron desactivados sudo systemctl list-unit-files --state=enabled --type=service

Documenta cuáles servicios desactivaste y por qué.

🛠️ PARTE 2: Hardening en Windows

4 Configurar Políticas de Seguridad Local
🔧 Paso A - Abrir editor de políticas:
secpol.msc
🔧 Paso B - Configurar políticas de contraseñas:

Navega a: Configuración de seguridad → Directivas de cuenta → Directiva de contraseñas

  • La contraseña debe cumplir requisitos de complejidad: Habilitada
  • Longitud mínima de la contraseña: 8 caracteres
  • Vigencia máxima de la contraseña: 90 días
  • Historial de contraseñas: Recordar las 5 últimas
🔧 Paso C - Configurar bloqueo de cuentas:

Navega a: Configuración de seguridad → Directivas de cuenta → Directiva de bloqueo de cuentas

  • Umbral de bloqueo de cuenta: 5 intentos fallidos
  • Duración del bloqueo de cuenta: 30 minutos

Captura pantalla de cada configuración aplicada.

5 Configurar Windows Defender Firewall
🔧 Paso A - Abrir firewall avanzado:
wf.msc
🔧 Paso B - Crear reglas de entrada restrictivas:
  1. Clic en Reglas de entrada → Nueva regla...
  2. Tipo: Personalizada
  3. Programa: Todos los programas
  4. Protocolo: Cualquiera
  5. Ámbito: IP locales: Cualquier dirección IP → IP remotas: Estas direcciones IP (agrega tu red: 192.168.1.0/24)
  6. Acción: Permitir la conexión
  7. Perfil: Dominio, Privado, Público
  8. Nombre: Permitir red local
🔧 Paso C - Bloquear todo lo demás:

Crea una regla final que bloquee todo el tráfico entrante no permitido explícitamente.

6 Habilitar Auditoría de Eventos
🔧 Paso A - Abrir visor de eventos:
eventvwr.msc
🔧 Paso B - Ver eventos de seguridad:

Navega a: Registros de Windows → Seguridad

Busca estos eventos importantes:

  • ID 4624: Inicio de sesión exitoso
  • ID 4625: Intento de inicio de sesión fallido
  • ID 4634: Cierre de sesión

🌐 EVALUACIÓN 5: Integración de Servicios

🎯 Objetivo Laboral Real

🛠️ PARTE 1: Servidor Web Apache (Linux)

1 Instalar y Configurar Apache
🔧 Paso A - Instalar Apache:
sudo apt update sudo apt install apache2 -y
🔧 Paso B - Crear Virtual Host:
sudo nano /etc/apache2/sites-available/ucs.conf

Contenido:

<VirtualHost *:80> ServerName ucs.local ServerAdmin webmaster@ucs.local DocumentRoot /var/www/ucs <Directory /var/www/ucs> Options Indexes FollowSymLinks AllowOverride All Require all granted </Directory> ErrorLog ${APACHE_LOG_DIR}/ucs_error.log CustomLog ${APACHE_LOG_DIR}/ucs_access.log combined </VirtualHost>
🔧 Paso C - Crear contenido del sitio:
sudo mkdir -p /var/www/ucs sudo chown -R www-data:www-data /var/www/ucs # Crear página de prueba echo "

UNAULA Cloud Services

Servidor Apache funcionando

" | sudo tee /var/www/ucs/index.html
🔧 Paso D - Activar sitio y reiniciar:
sudo a2ensite ucs.conf sudo a2dissite 000-default.conf sudo systemctl reload apache2 sudo systemctl status apache2
🔧 Paso E - Probar:

Desde tu navegador: http://IP-de-tu-VM-Linux

Deberías ver: "UNAULA Cloud Services - Servidor Apache funcionando"

2 Configurar HTTPS con SSL (Certificado Auto-firmado)
🔧 Paso A - Generar certificado SSL:
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \ -keyout /etc/ssl/private/ucs.key \ -out /etc/ssl/certs/ucs.crt \ -subj "/C=CO/ST=Antioquia/L=Medellin/O=UNAULA/OU=UCS/CN=ucs.local"
🔧 Paso B - Crear Virtual Host SSL:
sudo nano /etc/apache2/sites-available/ucs-ssl.conf

Contenido:

<VirtualHost *:443> ServerName ucs.local DocumentRoot /var/www/ucs SSLEngine on SSLCertificateFile /etc/ssl/certs/ucs.crt SSLCertificateKeyFile /etc/ssl/private/ucs.key <Directory /var/www/ucs> AllowOverride All Require all granted </Directory> ErrorLog ${APACHE_LOG_DIR}/ucs_ssl_error.log CustomLog ${APACHE_LOG_DIR}/ucs_ssl_access.log combined </VirtualHost>
🔧 Paso C - Activar SSL y sitio:
sudo a2enmod ssl sudo a2ensite ucs-ssl.conf sudo systemctl reload apache2
🔧 Paso D - Probar HTTPS:

Desde tu navegador: https://IP-de-tu-VM-Linux

(Aceptará el warning del certificado auto-firmado)

🛠️ PARTE 2: Servidor Web IIS (Windows)

3 Instalar IIS
🔧 Paso A - Instalar desde PowerShell (Admin):
Install-WindowsFeature -name Web-Server -IncludeManagementTools
🔧 Paso B - Verificar instalación:
Get-WindowsFeature Web-Server

Debe mostrar "Install State: Installed"

4 Configurar Application Pool y Sitio
🔧 Paso A - Crear Application Pool:
Import-Module WebAdministration New-Item -Path IIS:\AppPools\UCS-Pool Set-ItemProperty -Path IIS:\AppPools\UCS-Pool -Name "managedRuntimeVersion" -Value "" Set-ItemProperty -Path IIS:\AppPools\UCS-Pool -Name "startMode" -Value "AlwaysRunning"
🔧 Paso B - Crear directorio y sitio:
# Crear directorio New-Item -ItemType Directory -Path "C:\inetpub\ucs" -Force # Crear archivo de prueba '

UNAULA Cloud Services

Servidor IIS funcionando

' | Out-File -FilePath "C:\inetpub\ucs\index.html" # Crear sitio web en puerto 8080 New-Website -Name "UCS-Windows" -Port 8080 -PhysicalPath "C:\inetpub\ucs" -ApplicationPool "UCS-Pool"
🔧 Paso C - Probar:

Desde tu navegador: http://IP-de-tu-VM-Windows:8080

🛠️ PARTE 3: Almacenamiento Redundante

5 Configurar RAID 1 en Linux
⚠️ Importante: Para RAID necesitas 2 discos virtuales adicionales. En VirtualBox:
  1. Apaga la VM Linux
  2. Configuración → Almacenamiento → Agregar disco duro
  3. Crea 2 discos de 10GB cada uno
  4. Inicia la VM
🔧 Paso A - Verificar discos:
lsblk

Debes ver sdb y sdc (los nuevos discos)

🔧 Paso B - Instalar mdadm y crear RAID 1:
sudo apt install mdadm -y # Crear RAID 1 (mirroring) sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc # Verificar creación cat /proc/mdstat
🔧 Paso C - Formatear y montar:
# Formatear como ext4 sudo mkfs.ext4 /dev/md0 # Crear punto de montaje sudo mkdir -p /mnt/raid1 # Montar sudo mount /dev/md0 /mnt/raid1 # Verificar espacio sudo df -h /mnt/raid1
🔧 Paso D - Configurar fstab (persistencia):
# Obtener UUID del RAID sudo blkid /dev/md0 # Agregar a fstab echo '/dev/md0 /mnt/raid1 ext4 defaults 0 0' | sudo tee -a /etc/fstab # Probar fstab sudo mount -a sudo df -h

🛠️ PARTE 4: Interoperabilidad (Samba)

6 Compartir Carpetas entre Linux y Windows
🔧 Paso A - Instalar Samba:
sudo apt install samba -y
🔧 Paso B - Crear carpeta compartida:
sudo mkdir -p /srv/samba/ucs-data sudo chmod 777 /srv/samba/ucs-data echo "Archivo compartido desde Linux" | sudo tee /srv/samba/ucs-data/leeme.txt
🔧 Paso C - Configurar Samba:
sudo nano /etc/samba/smb.conf

Agregar al final:

[ucs-data] comment = UCS Shared Data path = /srv/samba/ucs-data browsable = yes guest ok = yes read only = no create mask = 0755
🔧 Paso D - Reiniciar Samba:
sudo systemctl restart smbd sudo systemctl restart nmbd sudo systemctl status smbd
🔧 Paso E - Acceder desde Windows:
  1. En Windows, abre Explorador de archivos
  2. En la barra de direcciones escribe: \\IP-de-Linux\ucs-data
  3. Deberías ver el archivo "leeme.txt"
  4. Crea un archivo nuevo desde Windows y verifica que aparezca en Linux

📦 ENTREGABLES OBLIGATORIOS

📁 Debes entregar:

  • URLs/IPs funcionando: Capturas mostrando:
    • Apache HTTP: http://IP-Linux
    • Apache HTTPS: https://IP-Linux
    • IIS: http://IP-Windows:8080
  • Archivos de configuración: Copia de:
    • /etc/apache2/sites-available/ucs.conf
    • /etc/apache2/sites-available/ucs-ssl.conf
    • /etc/samba/smb.conf
    • /etc/fstab
  • Evidencia de RAID: Captura de cat /proc/mdstat mostrando el RAID activo
  • Evidencia de interoperabilidad: Captura de Windows accediendo a carpeta compartida de Linux

⚠️ Errores Comunes que Debes Evitar

  • ❌ Configurar Apache e IIS en el mismo puerto (80) - IIS usa 8080
  • ❌ Olvidar abrir puertos en firewall para Samba (139, 445)
  • ❌ No configurar fstab y el RAID no monta al reiniciar
  • ❌ Certificado SSL en ubicación incorrecta
  • ❌ No probar que todo sigue funcionando tras reiniciar VMs
